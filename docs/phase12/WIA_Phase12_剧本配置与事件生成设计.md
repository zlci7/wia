# Phase12 剧本配置与事件生成设计

状态：已确认设计，待开发与验证。当前实现事实见[开发状态](WIA_Phase12_开发状态.md)；M2 基线证据见[验收记录](acceptance/M2.md)。

## 1. 目标与范围

作者用本地剧本包定义故事起点与边界，玩家从公开介绍选择故事，每次新开局创建独立世界。人物、记忆和事件在该世界中发展，原始剧本包保持不变。

实施顺序为：剧本配置化 → 旧渡口流程型收束 → 开放型与 AI 事件生成 → 综合验证。复用现有 NPC 独立决策、ContextComposer、个人记忆、纠正、世界事务和恢复机制，不新增常驻导演 Agent。

专项包含本地 JSON 配置、格式与引用校验、资源目录及两个可玩示例。不包含可视化编辑器、角色共享平台、内容商城、在线资源管理、图片生成、任意脚本、向量数据库或无限地图与重要 NPC 扩张。M3 的编辑、导入导出及行动建议和 M4 的部署交付单独推进。

第一项独立开发交付为“剧本配置化与多剧本运行”：完成内容加载、公开展示、多剧本全链路、定义与资源快照，迁入旧渡口并增加一个不同题材的最小互动样例。该单元沿用已有条件剧情、时间、记忆与纠正能力，不承担第二步的完整路线收束或第三步的动态事件生成。四步顺序保持不变，第一步验收不等于专项全部完成。

## 2. 剧本包

每个剧本一个目录，包含 `story.json`、`npcs/*.json` 和 `assets/`。地点与剧情资料先作为 story.json 的内容分区，不建设独立地图编辑器或复杂模板继承。JSON Schema 及跨文件引用检查共同约束格式；自然语言用于背景、动机、语义条件与发展说明。

文件组织与运行逻辑分离，加载后统一生成内部定义及公开投影。首版只支持这一种文件布局，不同时实现多套目录格式。

### 2.1 剧本 definition

| 分区 | 内容语义 |
| --- | --- |
| 身份与版本 | game_id、schema_version、revision；同一内容版本不可歧义地对应不同内容 |
| 类型 | 作者指定唯一 mode：guided 或 open；普通玩家开局不选择或覆盖类型 |
| 公开介绍 | 标题、简介、玩法与自由度说明、可选封面及替代文本 |
| 主角规则 | 默认姓名与简介、可自定义范围、开局身份要求；不授予程序数据权限 |
| 公开背景 | 玩家开局应知的时代、环境与世界规则 |
| 作者资料 | 固定事实、隐藏真相、世界约束；不是所有人物的初始知识 |
| 开局 | 正文、地点、游戏时间、初始人物与背景人群 |
| 地点 | 稳定标识、特点、连接或可达关系、初始人物及可生成事件的范围；秘密与公开描述分开 |
| 人物引用 | 包内 NPC definition 与初始实体绑定；引用限定在当前剧本 |
| 剧情 | 事件线、节点、必要依赖、可选时间边界、语义条件、干预后果和结束条件 |
| 生成策略 | 是否允许生成事件、可用地点与人物、规模与题材、触发机会、节奏和活跃数量限制 |
| 表达默认值 | 人称、回复长度、描写密度等现有故事设置默认值；玩家可按现有规则调整 |

规则分三层：程序固定的信息权限、玩家重要选择权、版本与事务合同；作者定义的世界和玩法规则；可调整的表达偏好。剧本规则不能覆盖程序合同，表达偏好不能改变世界真相或剧情类型。身份、引用和版本结构化，具体剧情语义不转换为任意动作 DSL。

身份、版本、唯一类型、公开标题与简介、有效开场、初始地点和时间，以及初始化所需的人物绑定必须提供。封面、额外地点说明、补充策略和表达偏好可省略并使用明确默认值。上表描述完整内容职责，不表示第一步支持全部执行字段：首版 Schema 仅接纳运行时实际消费的配置，包含现有剧情机制可执行的节点结构；尚未支持的执行字段或能力返回明确错误，不静默忽略。作者说明文本单独标识，不冒充有效结束条件或已启用的事件生成策略。

设置初始化按“应用默认值 → 剧本声明的默认值 → 新开局时允许的玩家覆盖”合成，形成一份世界设置并保存来源与有效值，后续编辑只作用于当前世界。场景、正文和 NPC 共用策略每个目的采用一份有效策略，不叠加多套全文；明确选项和程序固定合同优先。世界中已保存的剧本策略不随原包更新，自定义、恢复默认沿用现有设置入口及版本合同。NPC 共用策略只写行为规则，秘密仍由个人知识入口提供。

### 2.2 NPC definition

每份 NPC 文件包含 definition_id、内容修订、姓名、身份、公开外观、性格与行为倾向，以及本剧本中的初始知识、初始关切、关系和位置。首版模板归属当前剧本，不提供跨剧本继承。

definition_id 标识初始模板；entity_id 标识具体世界中的人物实例，结合 user_id/game_id/world_id 确定作用域。模板不存放游玩中产生的感知、对白、主观记忆、承诺完成情况或当前动作结果。

初始关切描述起点动机，不是永久待办。人物根据本人获准经历形成新的关切、关系判断与约定；完成和受阻状态进入世界记忆。作者真相仅按初始知识授权给相关人物，具体人物动机不写入通用提示词。

关系事实与人物对关系的认知分别表达。作者知道两人是亲属，不代表玩家或当事人已知；相关资料仅进入明确获准的初始知识和公开投影。首版可由一个模板绑定一个固定实例，名字不是身份键。

地点采用稳定 location_id，初始地点、人物位置和剧情引用按 ID 校验。连接与场景描述可以是自然语言材料；加载器不据此承诺确定性的通行、距离、路径规划或逐物件模拟。位置变化仍由现有协调与场景合同处理。

## 3. 玩家展示与资源边界

首页展示封面、标题、简介和类型；剧本详情展示公开背景、玩法、自由度及主角要求。开局表单仅包含该剧本允许的主角配置和存档名称，类型作为只读说明。

后端使用显式公开字段投影。普通目录、详情、人物和资源接口不返回完整 definition、秘密、节点答案、私人关切或未获知的背景。创作视图沿用明确授权与剧透提示，打开视图本身不改变角色知识。

本地完整剧本包可以由文件所有者自行读取。信息边界保护普通界面、API 与模型上下文，不承诺防止用户检查自己电脑上的配置，不修改文件读取权限或 ACL 来隐藏内容。

封面使用剧本包内的相对资源引用，无封面时使用统一占位。资源只通过受控静态资源入口提供，限制图片类型和大小，规范化后校验路径及链接解析结果处于许可资源目录，拒绝路径穿越和任意文件读取；不把剧本目录整体作为静态目录。首版不自动抓取远程图片或执行资源中的脚本。

## 4. 加载、版本与存档

程序从配置目录加载剧本注册表，以 game_id 查找内容。加载校验覆盖格式版本、字段类型、枚举、长度与数量限制、重复 ID、缺失引用、非法资源路径、剧情依赖环及结束条件的结构与引用。加载器不证明自然语言条件合理或剧本必然可通关，实际收束由剧情测试和游玩验证。错误指明文件与字段；无效剧本不能新开局，也不以空内容或旧渡口默认内容冒充加载成功。

校验后的版本作为完整不可变快照发布。新建时固定该快照及实际资源引用，不从多个正在编辑的文件拼出混合版本；首版重新加载可以通过重启服务完成，不要求文件监听或在线发布界面。

每个包先完整校验再发布；坏包不半加载、不替换已发布有效修订、不阻止无关剧本和已存在存档继续运行。若仍保有较早有效修订，仅以其真实版本提供，不把失败候选标成可用新版本。目录无可新建剧本时允许继续已有完整存档，并明确显示加载问题。

对规范化有效定义及引用资源计算内容摘要，持久保存 game_id + revision 与摘要的绑定。相同版本和相同内容可重复加载；同一版本对应不同内容或资源时拒绝发布，提示更新修订号。纯格式排版不改变规范化定义含义，摘要不包含用户经历或凭据。

详情返回实际内容修订，新建请求携带 game_id 与 expected_revision。服务端仅从匹配的已校验快照创建；若当前可用修订已变化，返回版本冲突，保留主角表单并让玩家刷新详情确认，不静默换用新版。相同创建请求的幂等重放仍返回原结果，不因目录更新重复建档。

| 操作 | 采用内容 |
| --- | --- |
| 新故事／重新开局 | 与玩家确认的 expected_revision 匹配的有效剧本版本，创建新的 world_id，不继承其他世界经历 |
| 继续存档 | 存档内的定义快照、有效修订及已提交运行状态 |
| 另存 | 复制当前完整快照、资源依赖、记忆和事件进度，之后独立发展 |
| 作者更新剧本包 | 影响之后的新开局，不自动修改已有世界 |
| 当前世界纠正 | 沿用现有版本与重建合同，仅作用于该世界，不修改原始剧本包 |

schema_version 表示配置格式，revision 表示故事内容版本。创建世界时保存完整逻辑定义快照并复制必要资源到世界所有的资源目录，覆盖或移除原包不使已有世界依赖最新模板。快照与运行状态可以保存在同一 world.db，职责分开即可，不引入第二套世界数据库或资源去重服务。另存复制所需资源，删除源世界不破坏副本。旧存档保留已有类型和冻结内容；缺失字段按明确兼容规则处理，不自动植入新版未来事件或人物动机。必要迁移必须幂等，不以最新剧本包覆盖旧资料。

多剧本接入覆盖目录、详情、创建、激活、列表、继续、另存、删除、回顾、纠正及后台任务。所有世界查找从已授权世界记录解析 game_id，不依赖固定示例常量或前端声称的归属。不同剧本可以使用同名人物和局部 ID，仍须隔离。未确认操作、草稿和迟到响应继续绑定原世界与版本。

## 5. 流程型示例：暮灯镇的失踪信使

旧渡口剧本固定为 guided。作者定义主要矛盾、关键事实、调查机会、替代路径与结束条件；玩家可以参与、拒绝、失败、离开或错过机会，实际行动决定结局范围内的结果，不强制按固定动作顺序接取任务。

夜渡离岸保留为有现实意义的游戏内时间边界。条件事件依据已成立的交谈、行动或关系发展，后果事件依据已提交结果；不要求所有节点绑定固定时刻。信使已被转移时按新处境发展，不能为了预设结局恢复开场状态。

完整路线验证至少覆盖实际参与并到达相应结果，以及不参与而错失机会的结束。旁白出现结束语不构成 story_ended，必须有已成立条件与证据；玩家或 NPC 的关键决定仍来自各自授权主体。

## 6. 开放型与生成事件

独立 open 示例包含少量可往返地点、少量重要人物及至少两条可独立发展的事件。无因果关系的事件不建立前置依赖，一条事件条件不足不阻塞无关事件；单事件结束不结束世界。

### 6.1 生成机会与边界

成功到达地点或情境显著变化可以产生生成机会。程序依据当前世界、活跃事件和节奏限制准入，模型可以决定本次没有新事件。优先接续已有事件，每次触发最多引入一个新事件，同时活跃事件数量有界；具体默认值在实现中通过体验验证固定。刷新、读取、模型等待和离线不触发事件。

AI 可以在作者授权范围内生成小插曲或持续的较大事件，复用已有地点、重要人物与背景人群。新事件不得改写固定事实或已提交经历，不为制造冲突强制玩家接受任务。背景人物由场景处理，自动创建大量独立 NPC Agent 或扩张地图不属于本次范围。

### 6.2 事件生命周期

生成候选包含世界内稳定身份、发生契机与来源、相关地点和人物、实际成立的起始事实、后续可能发展、可见范围、状态与结束条件。区分作者约束、当轮确认的新事实和未来计划；模型生成的计划不是已经发生的历史。

候选在当前回合工作区内由现有协调链路校验和处理。重要 NPC 的新承诺、隐瞒或立场交给本人决策；最终正文只表达已经确认的玩家可见结果。持续事件定义、进度、结果、感知、记忆、场景和正文随回合原子提交。即时小插曲也保留实际结果，但不必形成长期待办。

通过触发来源与事件身份保证幂等；失败、取消、重试和迟到响应不创建重复或半份事件。生成步骤受现有阶段期限、输入预算与调用量诊断约束，不运行无限后台模拟。新事件的实际内容归属当前存档，另存复制、重启接续，不写回共享剧本包。

## 7. 长期记忆验证

M1 已有个人感知、主观记忆和多轮上下文；M2 提供连续回顾、完整近期尾部、相关历史检索及有效纠正。存储记录存在不等于本轮模型看到该记录。

以跨出近期窗口的旧约定作为专项样本：只有沈岚获知约定；后续经历触发回顾整理；再次追问时检查原始来源、回顾和实际模型请求；铁杉不能获知私密内容。另存、重启、限定范围纠正后重复检查。生成事件也须在离开重返后继续，而不是重新生成同一事件。

分别报告资料是否正确提供，以及模型如何使用资料。已完成关切不持续作为未完成任务；无检索命中不制造经历。沿用现有检索方案，有实际证据的缺口再修复，不以短期复述成功代替长期验证。

## 8. 实施与验收

| 顺序 | 交付 | 必需验证 |
| --- | --- | --- |
| ① 剧本配置化与多剧本运行 | 本地剧本包、NPC 配置、封面与公开详情、多剧本加载、固定类型、快照与校验 | 新包无需改业务代码即可加载；不同题材连续互动；玩家接口及资源不泄露作者内容；非法包不影响其他存档；跨剧本同名 ID 隔离；版本冲突与同修订不同内容拒绝；更新或移除包后旧存档可继续；另存后删除源世界不破坏副本 |
| ② 旧渡口流程型收束 | 配置化旧渡口、明确主线和多个合理结束结果 | 参与、拒绝与错失机会；时间/条件/后果正确接续；不替玩家或 NPC 决定；完整真实模型路线 |
| ③ 开放型与事件生成 | 独立示例、多事件进度、AI 生成与持续接续 | 无关事件不互相阻塞；可不生成；规模与频率有界；重要 NPC 决策和可见范围；失败回滚与重复触发；离开重返 |
| ④ 综合验证 | 长期记忆、存读档与恢复、可运行构建及体验路径 | 跨窗口召回、纠正隔离、另存重启、跨剧本切换与迟到结果、全仓及相关并发检查、前端构建、浏览器和真实模型验证 |

每个独立单元检查与回归后本地提交，不推送远端。工程验证、真实模型结果、浏览器验证和用户体验验收分别记录；用户数据与凭据不进入测试内容包。现有 M2 验收记录保留其原范围，新专项未执行的项目保持待验证。

第一步的第二样例使用不同于旧渡口的题材与人物，不以改名复制代替通用性验证；只要求同一系统完成开局、连续互动和存档往返，不提前声明完整结局或动态事件能力。具体样例内容在实现时确定，第三步可以在该独立样例上补充开放型多事件体验。既有条件剧情、回顾、检索和纠正必须回归，不能标记为尚未实现或为配置化而移除。
