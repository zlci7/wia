# World Is Agent 产品说明

一体化叙事角色扮演 · 产品设计基线 v1.0

日期：2026-09-27。状态：待实现与验收的产品设计，不代表已发布能力。

配套文档：[总体技术方案](总体技术方案.md)。

开发与验收安排：[开发指南](开发指南.md)。实际进度：[开发状态](开发状态.md)。

## 1. 产品定位

**World Is Agent 是面向普通玩家的 AI 叙事角色扮演应用。玩家选择故事、进入角色，就能自然地与人物互动；角色记忆、多人场景、剧情回顾和行动建议由产品默认组织好。**

玩家通过自然语言说话、行动、观察和选择，推动自己的故事。产品负责让人物带着经历回应，让不同人物知道不同的事情，让故事能够保存、接续和纠正。

核心承诺是：**功能完善，默认可用，少做配置，多投入剧情。**

“功能完善”指从开始故事到长期游玩的一套完整体验：故事与人物、主角身份、场景与多人互动、人物记忆、回顾与纠正、行动建议、自由输入、保存恢复、内容编辑及导入导出。每一项能力都应在实际游玩中发挥作用。

“门槛低”指玩家无需研究 Agent、提示词编排、记忆策略、检索参数或插件组合。必要的模型连接有清楚的引导，日常游玩不依赖持续调参。

## 2. 服务的人与解决的问题

主要用户是希望直接进入故事的普通玩家。创作者可以进一步编写世界、人物和开场，并检查与纠正故事记录。

需要解决的问题是：应用具备某项能力，但玩家要先知道它存在、理解配置、组合正确，才能真正获得体验。功能存在与普通玩家实际用到之间的距离，由产品承担。

| 玩家想做的事 | 默认体验 |
| --- | --- |
| 尽快开始一个故事 | 选择可直接游玩的故事、确认主角后开始；需要连接模型时就地引导 |
| 和眼前的人说话 | 在同一个输入框表达；系统识别对象和在场人物的相关反应 |
| 让人物记住经历 | 自动记录其获知的事情，并在后续回应时使用 |
| 接着上次的剧情游玩 | 当前进度自动持久化，重新打开后接续，回顾帮助回忆 |
| 保留当前进度，之后再回来尝试 | 手动另存为新存档；读取已有存档后持续更新该存档 |
| 不知道下一步做什么 | 默认提供三个可修改、可忽略的行动建议 |
| 修正记错的事情 | 从回顾或人物记录进入统一纠正入口，后续按有效版本继续 |
| 自己创作或导入人物 | 提供可读的编辑、映射预览与确认，不要求编写技术配置 |

高级设置按需展开。角色连续性、信息分发和存档正确性属于基础能力；行动建议等辅助能力可以关闭，关闭后自由输入仍然完整可用。

## 3. 第一次游玩

玩家打开应用后，选择一个现成故事，或者创建、导入自己的故事；确认主角身份后进入开场。

模型接入与故事准备分开处理：本地使用自有模型服务时，首次填写必要连接信息并验证；访问已由管理员开放模型的服务器时，玩家选择有权使用的服务即可。普通玩家不需要给每个 NPC 分配模型，也不需要配置记忆数据库。

产品提供可直接游玩的示例故事和默认参数。创作入口保留自由度，首次体验不以完成整套人物设定表为前提。低门槛不等于承诺免费模型服务或无需网络。

游玩界面以正文、输入框和轻量人物栏为主。回顾、人物记录和内容编辑按需展开，技术参数不占据主要阅读空间。

### 3.1 开放型与流程型剧本

剧本规定世界背景、人物、初始矛盾和固定事实，也可以设定多条世界剧情。世界规模与剧情模式分别决定：小场景可以自由发展，大世界也可以包含有明确流程的剧情。

| 模式 | 世界剧情 | 玩家选择与结束方式 |
| --- | --- | --- |
| 开放型 | 事件根据人物目标、游戏内时间和触发条件发展，可以有多条并行剧情 | 玩家自由选择参加哪些事件、怎样参加，也可以全部不参加；一条剧情结束不代表整个世界结束 |
| 流程型 | 围绕明确主线组织关键节点、目标、替代路径及结束条件 | 玩家在主线内选择行动路径，产生成功、失败或作者规定的结局 |

剧本类型由作者在 definition 中指定，玩家在详情页了解类型与自由度，开局不切换类型。同一背景的不同玩法作为独立剧本内容设计。创作者可以给出剧情文本，由系统整理固定事实、关键节点、触发条件和结局约束的草稿，确认后采用。普通玩家使用预设内容即可开始。

流程型默认固定关键事实与目标，允许不同路径和成功、失败结局。严格指定结局是作者可选的更强约束，开始前说明其自由度，并明确拒绝关键行动时的失败或结束处理。两种模式都由玩家决定主角行动，系统不替玩家接受任务、承诺或关系。

### 3.2 世界剧情与玩家参与

世界剧情描述世界正在发生什么，玩家经历记录玩家选择参与什么。玩家不参加某条剧情时，相关人物和事件仍可按既定条件发展，产生合理后果；系统不因玩家拒绝就反复强推同一任务。

例如，剧本规定商队明早出发，如果埋伏未被发现且无人干预，商队将在山路遇袭。玩家可以随行、预警、改变路线，也可以留在镇上处理别的事情。干预可能改变事件结果，不参与则按实际条件继续发展。

内容分别表达：已经成立的事实、人物未来计划、事件触发条件及可能后果。计划可以被干预、延迟或阻止，不能因为作者写下就自动成为已发生事实。固定背景和关键真相保持一致，主 Agent 可以创造符合这些约束的线索与事件来形成节奏。

世界发生了事件，不等于玩家或所有 NPC 都知道。商队遇袭后，玩家可能先发现店里缺货，再通过传闻得知原因。消息需要通过目击、通信、转述等途径进入各人的认知。

开放型允许 AI 在作者配置的地点、人物、题材和规模范围内补充小插曲及持续事件。到达地点或情境显著变化时可以产生事件，也允许平静无事；优先接续已有事件，单次生成及同时活跃数量有界。持续事件保存到当前世界，离开重返、另存和重启后能够接续，不写回原始剧本。重要人物自行决定，玩家决定是否接受任务；新事件不改写已成立事实。一条事件未满足条件不阻塞无关事件。

当前开放示例《远星维修站》提供检修交接和补给调度两条独立事件线。设备检修间与值班室之间的已确认到达可提供一次小事件机会，允许没有新事件；同一轮最多生成一个，同时最多保留两个活跃生成事件，两次生成机会至少相隔三个成功回合。作者事件到期时优先处理；临时事件有后续条件，不能只在正文中出现后消失。读取、另存、重启不触发生成。

### 3.3 游戏内时间

世界剧情随游戏内时间与事件条件推进。有时间成本的行动、等待和场景转换可以使时间流逝；普通对话按情境判断耗时，不机械地把每条消息视为一天或一个剧情阶段。

关闭应用、停留在设置页、阅读历史或等待模型响应，不推进世界时间。重新打开存档时从已保存的时间与事件状态继续，不补算离线期间的剧情。

主 Agent 根据条件协调场外事件，相关重要人物需要作出新选择时按需参与决策，不要求所有离场 NPC 持续运行。长时间等待遇到需要玩家决定的变化时，先呈现事件并交还控制权。

## 4. 一轮故事怎样发生

### 4.1 场景与人物共同形成一段叙事

玩家输入：

> 我推门走进酒馆，看看里面是什么情况。

系统呈现一个完整画面：雨水、酒架、压低声音的客人、老板的招呼、佣兵的反应。这些内容组成一段自然的故事，玩家不需要分别启动旁白、老板和佣兵的对话。

场景主 Agent 负责场景、环境、背景人群、情节推进和最终叙述。当前场景内的重要 NPC 通过各自的 Agent 理解自己获知的信息，决定回应或保持沉默。系统协调这些回应，形成玩家读到的正文。

玩家无需切换“场景模式”与“角色模式”。可以直接写“我转向佣兵”，也可以使用人物栏指定交谈对象；指定对象不意味着其他实际听到谈话的人自动失去反应机会。

### 4.2 人物有自己的立场

老板可以拒绝、隐瞒、讨价还价，佣兵可以插话或旁观。他们的回应依据各自的设定、经历、关系判断和当前关切。

主 Agent 协调人物的尝试与结果，并组织文字；人物是否答应、是否透露秘密、是否改变立场，由对应 NPC 作出选择。一个人物尝试抢走东西，也不等于已经抢到。

重要 NPC 可以使用相同模型服务，但各自保有身份与记忆。“独立 Agent”指独立的角色决策与信息范围，不要求每人常驻一个程序。

重要 NPC 获得符合其可见范围的感知，不等于每轮都必须发言或动作。默认采用“按情境主动”：人物不必等待玩家点名，根据职责、兴趣、安全、承诺、当前关切和合适机会可以主动招呼、追问、试探、打趣或行动；普通进入和环顾不要求每个人都回应。玩家可以按存档改成“回应为主”或“积极互动”。继续观察、保持警惕和维持原位属于人物状态，不作为需要场景裁定的新行动。

人物的初始关切来自 definition，描述开场动机而非固定动作顺序。新世界复制这份资料，旧存档缺失时保持为空。NPC 可以根据自己的处境处理事务、延续计划或保持沉默；是否发言和是否行动分别判断。初始关切结合已提交经历理解，完成或受阻的结果属于当前存档，不由模板更新覆盖。长期关切整理属于 M2。

### 4.3 玩家控制自己的主角

玩家可见不等于全场公开。玩家自己的私聊原话可以出现在面向自己的正文中，旁观人物仅获知实际感知到的内容。指定交谈对象、使用引号或试探语气不自动表示耳语；当前明确表达优先。NPC 回复目前为愿意让在场者听见的公开对白。

正文可以自然复述或直接承接玩家的话，不要求逐字重复，但应保留其原意、态度和信息，不把一句陈述改写为多次询问。

玩家表达的是说话、观察或行动尝试，系统结合情境呈现后果。输入“老板同意给我钥匙”不能直接覆盖老板的选择。

系统不擅自替主角作出重大感情、立场和承诺。人物之间可以产生必要的后续反应，在需要玩家决定时交还控制权；后台不会无限自行演完故事。

面向玩家的故事正文默认采用第二人称有限视角：玩家输入中的“我”在正文中对应“你”。玩家可以按存档改为第一人称或使用主角姓名的第三人称，也可以选择正文篇幅与描写密度。NPC 在对白中对主角的自然称呼不受正文人称影响。

无论采用哪种人称，正文只呈现主角能够感知、已经知道或有明确来源获知的信息，不断言其他人物未表露的心理，也不使用“来人”“来客”等泛称把主角写成另一个旁观人物。写作偏好只能改变表达，不能覆盖玩家控制权、人物知识边界或已经确定的事件来源。

默认互动风格为“自然共创”。正文可以把玩家已经明确表达的意图补成与其等价的简短台词、日常动作、必要衔接和即时反应，例如“跟老板打招呼”可以自然写成点头并说“晚上好”，不要求玩家逐字输入每个动作。补写保留玩家原意，不能把疑问改成承诺、把拒绝改成接受，也不能新增会成为后续依据的身份、秘密、目标、关系、关键资源处置、危险行动或移动目的地。

互动风格提供“克制扮演”“自然共创”“小说共创”三个预设，分别组合主角补写幅度和 NPC 主动性。高级设置可以单独调整这两个维度；正文篇幅和描写密度与互动风格分开。小说共创可以更充分地表现主角已经选择的方向，但不授权正文自行补出多轮 NPC 对话或替主角作出重要选择。

低影响的表达补全只改善本轮呈现，不作为后续剧情依据。会改变下一轮地点、物品、资源、关系、知识、任务、剧情条件、NPC 立场或可选行动的内容，必须进入事件、感知和协调流程。NPC 的新对白与可见行动必须来自对应人物已经作出的决定。

描写密度决定表现细节的丰富程度。可以补充符合当前情境的感官、氛围和低影响表现细节；影响后续进程的关键事实、人物决定与持续状态，以已有设定和本轮确认结果为依据。临时细节既不能与已有内容矛盾，也不能被直接提升为线索、承诺或其他持续状态。

正文围绕本轮新增的对白、动作和观察展开，在有意义的内容表达完整时自然结束，可以停在一句对白、一个动作或一处观察上。玩家选择权通过保留尚未选择的重要行动来体现；仅在等待本身具有剧情意义时描写等待，不把“等你回答”“或不答”等轮到玩家操作的说明作为固定收尾。

回复长度是展开偏好，不是每轮需要达到的最低字数。三档均可简短结束简单互动，不用重复环境、已完成动作或等待状态填充篇幅；界面说明采用相同含义。

| 回复长度 | 展开偏好 |
| --- | --- |
| 简短 | 直接呈现关键回应和变化，简单互动可用几句话结束 |
| 标准 | 根据本轮新增内容适度展开，观察或重要变化时增加细节 |
| 细致 | 对有内容可展开的部分充分描写，简单回应仍可简短结束 |

历史正文提供人物位置、物件状态和已发生事件的连续性参考，不作为本轮需要重演的动作或必须沿用的句式。已经进门、递茶等动作保持完成状态，后续从该状态继续；输入与既有状态有重叠时，结合上下文承接本轮意图。

人物仍在场不要求正文每轮逐个点名。正文只提本轮相关人物；没有写到某人不表示其已经离场，也不逐项汇报人物未变化的姿势和状态。

### 4.4 高级行为策略

故事设置的详细设置提供三个可选文本入口：场景协调策略、正文表达策略、NPC 共用决策策略。默认即可游玩；自定义文本替换对应的默认策略，而非与默认文本叠加。人称、回复长度、描写密度、主角表现和人物主动程度是明确选项，优先于策略文本；人物知识范围、事件来源、输出合同和玩家重要选择权保持有效。

每项最多 4,000 字，可查看并恢复当前软件的默认策略。空文本采用当前版本默认值，默认值随软件版本更新；自定义文本保存在当前存档，升级不覆盖，另存时继承。修改仅对下一轮生效，生成或另存期间不可修改。策略不改写已有正文、事件或记忆。

NPC 共用策略发送给所有参与决策的人物，不填写人物秘密或专属背景。具体动机来自人物资料；策略不提供宏、脚本或任意资料读取能力。正文表达策略是唯一写作策略入口，旧存档已有写作偏好保留在其中。

### 4.5 路人与重要人物有不同处理方式

普通客人、行人和临时侍者由场景叙述自然表现，不逐个建立完整 Agent。已被确立为重要人物的 NPC 则持续保有自己的身份与经历。

玩家可以选中一名路人的相关描写，使用“保留为角色”整理已知资料、补充背景，确认后继续深入互动。既有姓名和经历有来源；补充背景与历史事实分开。曾在酒馆出现不等于知道酒馆发生过的全部秘密。

## 5. 每个人记得什么、知道什么

**记忆按人物分别维护，信息按人物实际获知的内容进入记忆。两者共同决定人物如何回应。**

例如，玩家低声告诉老板“今晚有人要来搜查”：

- 老板听到完整内容，可以记住并作出自己的判断。
- 佣兵如果只看见两人低声交谈，只能根据这一迹象猜测。
- 随后进入酒馆的人，不会自动知道之前的谈话。
- 老板后来转告佣兵时，佣兵获得的是“老板这样告诉我”的信息，可以相信，也可以怀疑。

角色亲眼看见的事情、听说的消息、自己的推测和未来打算分别保留。一个人说谎，不会使谎言自动成为世界事实；人物可以形成错误认知，后续再被新经历改变。

当前场景内的重要 NPC 即使选择沉默，也会保留自己已经获知的经历。离场人物保留记忆，参与场外事件时按实际获知内容更新，再次出现时继续使用；本阶段不要求所有离场人物持续自主行动。

长期游玩会自动整理回顾、检索相关经历，并保留尚未整理的近期内容。普通动作可以逐渐淡出回顾，当前仍影响情境的事实和未完成约定应当延续，原始记录仍可追溯。

相关旧经历按当前容量成组选入，不挤掉本轮输入和完整近期经历。未被提供给模型的旧记录仍可追溯；缺少一段检索材料不等于那件事没有发生。

M1 已有个人记忆和多轮上下文，M2 的增量是跨近期窗口的回顾、检索和纠正。长期效果以旧约定退出近期窗口后仍能接续、人物知识隔离及另存重启一致性验证，不以复述上一轮代替长期记忆验收。

信息范围由程序管理，具体“是否听到、怎样理解”的自然语言判断仍可能出错。产品提供检查和纠正能力，并以实际情境测试评估质量，不承诺绝对无误。

产品接受少量不影响持续游玩的模型幻觉，包括叙述细节偏差、偶发误解或表达不一致。叙事质量以整体连贯、人物可辨认、选择有回应和错误可纠正为目标，轻微偏差不默认中断游戏。程序仍须正确隔离人物与存档数据、保存已提交内容，并在存储或运行失败时准确显示状态。

## 6. 记忆可查看，错误可纠正

正文、剧情回顾、人物经历和人物判断有清楚区别。记录可追溯到来源，玩家需要时能理解某个约定或结论从何而来。

例如，系统把“老板拒绝赴约”整理成“老板答应赴约”。用户可以在统一入口中纠正记录。之后的回顾、人物上下文、检索和行动建议使用有效版本，不各自保留冲突的旧摘要。

纠正应说明改的是故事事实、人物设定，还是某个人的认知。修正世界事实不等于让所有人物立刻知道；修正某个人的误解，也不等于改变世界中实际发生的事。

事件纠正同时使其相关旧投影、场景解释及回顾采用有效版本。只获知局部信息的人物不会因纠正而获得作者秘密。连续提交多处纠正时，已接受的回顾修改保持有效；后续相关来源发生纠正时，受影响回顾重新整理。

原文保留，当前采用的纠正有明确标识。纠正约束后续延续，不自动重演或撤销所有已经发生的后续情节。用户可以另存当前进度，分别继续不同存档；任意历史正文重写、从未保存的旧进度创建分支及分支合并不属于本阶段交付。

游玩顶栏提供“回顾与纠正”。默认只展示主角回顾和已提交经历；人物私密设定、感知、主观状态及世界事件，需要确认剧透提示后进入创作视图。修改绑定打开编辑时的存档和版本，网络结果不确定时确认原操作。必需重建期间保留正文阅读，暂停新回合与另存；失败时可原地重试。

未公开人物背景、私人关切和作者答案不显示在普通游玩界面。创作者可以在有剧透提示的编辑入口查看与修改；打开编辑页面本身不使主角或 NPC 获得这些信息。

## 7. 默认行动建议与自由输入

每次正文完成后，默认给出三个行动建议。建议只基于玩家已知内容，提供可尝试的方向，不提前决定结果，也不使用隐藏答案提示玩家。

点击建议会填入输入框，玩家可以修改后提交，也可以直接自由输入。只有最终提交的内容进入本轮处理，未选择的建议不属于历史。

建议异步生成。正文保存后即可继续阅读和输入，建议失败不会回滚故事，也不会覆盖正在输入的文字。

## 8. 保存、等待与恢复

### 8.1 剧本与存档

一个剧本可以拥有多份独立游玩进度。每份进度是一个可持续推进的世界，具有自己的 `world_id` 和数据库；NPC 的经历、记忆与当前场景属于该世界。

正常对话将数据持久化到当前存档。刷新页面、关闭后重新打开，能够接续最新进度，并看到未完成输入的状态。自动持久化不会为每轮对话建立可回退的历史存档。

| 操作 | 结果 |
| --- | --- |
| 新开一局 | 从剧本创建新世界与数据库 |
| 正常游玩 | 持续更新当前世界 |
| 另存为新存档 | 将当前完整进度复制到新世界；继续游玩时仍留在原世界 |
| 读取存档 B | 切换到 B 的最新进度，后续对话持续更新 B |
| 返回首页 | 只离开游玩页面；不切换存档、不取消生成、不推进时间 |
| 删除存档 | 明确确认后删除完整世界；正在生成或另存时暂不允许删除 |
| 退出后继续 | 接续所选存档的最新持久化状态 |

例如，A 在第 10 轮另存为 B，随后 A 推进到第 20 轮。此时读取 B，从第 10 轮继续并玩到第 15 轮，B 的最新进度就是第 15 轮；再次读取 B 将从第 15 轮继续。如果希望保留第 10 轮，需要在推进 B 之前再手动另存。

**只能另存当前进度，只能读取实际存在的存档。**没有保存过的第 10 轮，不能在第 20 轮通过聊天记录还原。另存和读取均有明确的当前存档名称，界面说明“游玩进度自动保存到当前存档”。

同一后端上的一个账户共享一个当前游玩存档。电脑正在 A 中生成时，手机显式读取 B，会结束或取消 A 的生成，再切换到 B；电脑显示存档已切换，旧页面不能继续提交到 A。重复打开当前 B 不打断 B 正在进行的生成。查看列表、阅读其他存档的历史或刷新页面不改变当前存档，不同账户互不影响。

应用每次打开默认显示首页。首页只提供继续当前存档和选择剧本两个主入口，不直接展示或删除存档。选择剧本后进入剧本详情，在该剧本范围内新开一局、继续最近进度、选择或删除已有存档；游玩页的“存档与故事”也只管理当前剧本。服务端记录的“当前存档”只决定下一次游玩写入哪个世界，不决定浏览器必须停留在哪个页面。删除当前存档会清空当前选择并停留在所属剧本详情，不自动激活其他存档；删除另存世界不会影响源世界或其他副本。

首次进入允许浏览首页、剧本介绍和已有正文；开始新故事或发送输入前检查模型连接。连接表单默认提供服务商、推荐模型和密钥，模型名称与自定义地址在高级连接设置中展开。连接完成回到原操作位置，保留主角表单或输入草稿，由玩家继续提交。

新故事名称预填“剧本名称 · 本地日期时间”；另存名称预填“原存档名称 · 分支日期时间”。名称均可修改，空名称采用服务端默认值。主角与简介使用剧本默认值，允许范围由作者声明；模式由作者固定并以只读方式展示。存档列表突出名称、地点、现实更新时间与当前标记，时间标注为“更新于”；游戏内时间与模式作为次要信息。另存成功明确显示新存档名称，继续留在源存档。

另存结果暂时无法确认时，页面保留原操作，显示“继续确认另存”；恢复过程使用原名称和源存档，不因再次点击创建第二份副本。确认完成或明确失败后，才开始新的另存操作。

### 8.2 完整保存与切换

存档包含当前采用的剧本模式和人物设定、世界时间、世界剧情及触发进度、场景、正文与事件、各 NPC 的感知、记忆、关系判断、关切及有效纠正。读取时恢复整份世界，各存档的后续经历独立演进。

另存发生在完整回合结束的稳定状态。生成中请求另存时，等待本轮结束；本轮失败或取消时说明另存尚未完成，不将半轮结果写成存档。切换存档前结束或取消当前生成，防止旧任务影响切换后的世界。另存失败不影响原存档。

### 8.3 等待与失败恢复

多人物思考期间，界面显示简洁的进度与取消入口，不展示人物的秘密、内部提示词或推理过程。首次交付在正文完整保存后展示该段内容；等待期间的内部草稿不作为正式剧情出现。

生成失败时保留输入并标明未完成，允许用户重试。这些输入只保留作展示与重试，不作为已经发生的剧情进入人物记忆、回顾或建议。重试不能重复写入同一句输入或多份成功回复。已成功的回复不通过失败重试入口重新生成。

模型调用量与等待时间需要可观察；本阶段优先完整体验与角色质量，不以削减人物参与换取固定低调用次数。

顶栏“模型用量”展示本账户或当前存档的调用记录、输入、输出、其中推理、缓存命中与未命中 token，以及调用耗时。缓存命中率按有缓存数据的请求加权，并显示数据覆盖次数。未返回用量时标为未知；输出已经包含推理，不重复相加。调用返回不等于故事保存成功，失败与重试同样保留记录。账本从功能启用后累计，重启保留，另存不复制费用；金额以供应商账单为准。

支持推理的模型可以在模型窗口内单独预留内部推理额度，正文长度档位保持不变。额外推理可能增加调用成本与等待时间；推理内容不展示给玩家，也不写入默认日志。达到模型容量或期限仍按生成失败处理，保留输入及已提交故事。

### 8.4 游玩布局与长篇阅读

顶部导航持续可见，提供返回首页、模型设置，以及游玩时的存档与故事、故事设置。顶栏仅显示简洁连接状态，完整模型名称在模型设置中查看。首页和剧本详情使用普通页面滚动；游玩页固定顶栏与底部输入区，正文独立滚动，采用暖纸色、17px 正文字号、约 1.85 行高和有限阅读宽度。玩家输入用轻量气泡区分，正文标签和现实时间保持低干扰。

桌面右栏集中展示当前地点、明确标注的游戏内时间和眼前人物。小于 860px 时通过“场景与人物”打开侧面面板；窄屏保留首页与存档入口，设置收入更多菜单。人物仅展示现有公开字段，点击人物即可指定交谈对象，输入区支持清除并回到“自动判断”；人物离场或切换世界后校验对象有效性。

第一次进入存档显示最新 100 条正文，顶部按需加载更早的 100 条，加载前后保持可见消息位置，失败可原地重试。距底部不超过 80px 时跟随新内容；上翻阅读时保持位置，并提示“回到最新”及新内容。主动提交后显示本轮输入与生成状态，随后上翻不会被回复强行拉回。当前页面会话按存档保留草稿、交谈对象和阅读锚点；刷新或换浏览器不保留这些临时状态。

输入框随内容增高，最多占可用视口高度的四分之一，超出后内部滚动。Ctrl+Enter 提交；空格、普通 Enter 和中文输入法组合期间均不触发提交。布局使用动态视口高度与安全区域留白。

### 8.5 故事设置与就地反馈

故事设置默认展示互动风格和回复长度；详细设置提供叙事视角、描写密度、主角表现、人物主动程度和写作偏好。三档预设只调整主角表现与人物主动程度两个字段，独立调整后不匹配预设的组合显示“自定义”。关键选择仍由玩家决定。设置按存档保存，下一轮生效，运行中的回合拒绝修改。

设置草稿绑定打开时的存档和版本。同一存档在其他页面发生修改时，旧草稿保存应提示版本冲突，保留草稿供玩家处理；切换活动存档后原编辑会话失效，草稿不转移到新存档。迟到的保存响应不能覆盖较新的页面状态或其他编辑会话，成功反馈明确归属原存档。

发送错误留在输入区；模型、故事设置、新建、另存和删除的错误分别留在对应弹窗。网络异常在持续可见的状态区域提示，已有正文与草稿保留。提交中禁止重复发送；异步结果归属原存档。生成、失败和取消根据实际运行状态显示，只有回合完成且已读到提交后的世界状态与对应正文时，才显示“本轮已保存”。

等待模型时显示真实经过时间，不展示模拟阶段。连接等待超时后恢复页面操作并保留输入；提交结果尚未确认时，页面查询原请求，玩家可以确认或重发同一请求，确认前不能发出新的行动。暂时断连不等同于回合失败，只有读取到实际完成结果与已保存正文后才显示已保存。

人物已经说出的对白与准备执行的行动分别处理。对新刺激追加反应时，尚待协调的计划仍是计划；重复且没有新需要的行动不另行执行。正文呈现已确定的对白与结果，公开交谈的温和语气不改变其可听范围，也不替未回应的 NPC 补出表示接受的动作。

同时只显示一个主弹窗，支持焦点圈定、关闭后恢复焦点、Esc 和背景滚动锁定。写入请求进行时显示处理中并禁止关闭，结束后恢复；普通弹窗可点击遮罩关闭，删除确认只通过显式按钮或 Esc 关闭。

## 9. 内容创作与迁移

### 9.1 本地剧本包

剧本配置由本地 JSON、NPC definitions 和图片资源组成。剧本 definition 提供名称、唯一类型、格式与内容版本、封面、玩家介绍、玩法说明、主角要求、世界规则、开局、地点、作者事实、剧情及 AI 生成边界。NPC 定义包含身份、性格、初始知识、关切、关系与位置；游玩经历和成长保存在各自世界。

普通玩家只接收公开介绍、玩法和已获知的人物信息。作者秘密、节点答案和人物私人资料不随普通接口发送；作者视图沿用授权与剧透提示。封面来自包内受控图片资源，缺失时使用统一占位。

每次新开局读取当前有效版本并建立完整快照；继续与另存使用该存档的快照、资源和状态。作者更新或移除包不改写已有世界，旧存档保留原有模式和剧情。程序固定的信息范围、选择权和事务规则不能由剧本文本覆盖；作者决定世界与玩法，玩家可调整已有表达偏好。

文件配置、校验、公开展示及两个示例已经由 M2 交付；可视化创作与导入导出按 M3 推进。详细合同见 [M2 技术方案](stages/M2-世界剧情与长期记忆.md)和 [M3 技术方案](stages/M3-完整玩家工作台.md)。

### 9.2 编辑与导入

首版支持手动编辑、TXT/Markdown 背景、自有版本化故事内容包，以及 Character Card V2 JSON 的基础文本字段导入。

导入先展示人物、情境、开场和说话示例的映射结果，列出未支持的内容，确认后保存。剧情文本可整理成模式与约束草稿；用户确认前，草稿不进入世界事实或人物记忆。模板更新不自动改写已开始的故事；对当前故事应用修改时，发布明确修订。

高级提示、宏、脚本和扩展行为不作为可执行程序导入。完整插件兼容、所有角色卡容器格式及自动转换任意扩展行为不在首版范围内。

## 10. 使用方式与完整交付范围

完整 Phase12 覆盖 Windows 桌面本地游玩、本机浏览器，以及自托管服务器上的电脑和手机浏览器访问。桌面应用自动管理本地服务，玩家只启动一个应用。

同一后端上的故事可以跨设备接续。独立本地数据与服务器数据通过导出、导入迁移；本阶段不提供离线双向同步。服务器支持不同用户各自游玩，不包含多人同时操控同一个故事。

使用远程模型需要网络。服务器运营者与所选模型服务可能接触其处理的内容，不宣传端到端加密或完全离线。macOS/Linux 桌面包与原生手机应用后置。

本阶段完整交付包括：

- 可直接开始的故事、主角与人物管理，内容编辑及受限导入导出。
- 开放型与流程型剧本、按游戏内时间与条件推进的世界剧情，以及玩家参与或不参与的自由。
- 自动协调的场景主 Agent 与重要 NPC Agent，自然的多人叙事与玩家控制权。
- 分人物的信息范围、持续记忆、关系判断、关切与约定，长期回顾及统一纠正。
- 默认行动建议、自由输入、响应式界面和基础外观设置。
- 当前进度自动持久化、手动另存、读取后持续游玩，以及取消、失败恢复、模型连接引导与部署使用路径。

语音、生成图片、动态立绘、任意插件运行、完整物理模拟、无限自主世界和逐个路人的独立计算不属于本阶段交付。实施可以分工作单元推进，早期演示不等于完整产品验收。

流程型示例采用旧渡口小型调查冒险，包含有限地点、少量重要人物、明确矛盾及结束条件。开放型使用独立的小型多事件示例，验证自由参与、AI 补充事件及持续接续。大型开放世界内容与大范围长期演进后续扩展。

## 11. 与 SillyTavern 的差异怎样成立

SillyTavern 已提供群聊、摘要、World Info 和工具扩展等能力；群聊还提供多种角色发言组织方式。[群聊文档](https://docs.sillytavern.app/usage/core-concepts/groupchats/)、[摘要文档](https://docs.sillytavern.app/extensions/summarize/)、[World Info 文档](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)、[函数调用文档](https://docs.sillytavern.app/for-contributors/function-calling/)。

WIA 的产品价值建立在普通玩家实际获得的体验上：默认进入连贯的多人故事，人物自动记住各自经历，回顾和建议自动配合，遇到错误有统一纠正路径。这是一项需要验证的产品目标，功能数量或 Agent 数量本身不能证明优势。

比较分为两个问题：普通玩家从首次使用到持续游玩，需要完成多少准备、遇到多少求助点；在相同模型与相近内容下，持续人物、信息差和叙事质量能达到什么程度。后者应使用合理配置的 SillyTavern 对照，不能把对方未启用功能当作缺乏能力。

## 12. 产品验收

以下都是待执行的验收要求。

叙事与人物表现按连续游玩体验评估，允许少量可纠正的语义偏差；频繁破坏人物立场、关键剧情或导致无法继续的问题需要修复。数据所有权、存档完整性、重复提交和失败恢复按程序正确性验收，不以模型容错代替。

| 目标 | 可观察的结果 |
| --- | --- |
| 默认可用 | 新玩家从现成故事开始，无需接触 Agent、提示词或记忆配置，即可完成首轮与连续游玩 |
| 能力真正被使用 | 正常游玩自然出现多人回应、旧事影响和行动建议，玩家无需逐项开启功能 |
| 人物连续性 | 隔多轮、离场重返、重新打开故事后，经历与未完成约定仍影响相关人物 |
| 人物知情不同 | 私聊、旁观、晚到、转述情境中，人物依据各自获知的信息回应 |
| 叙事自然 | 多人反应形成完整段落，沉默有合理空间，玩家的重大选择仍由玩家作出 |
| 纠正有效 | 一处纠正后，受影响的回顾、人物记录和建议采用同一有效版本 |
| 持续可玩 | 保存恢复可靠，等待状态清晰，可选功能故障不阻塞自由输入 |
| 存档行为清楚 | 另存仅复制当前进度，读取后更新所选存档；各存档记忆独立，未保存的历史进度不可回退 |
| 跨设备接续清楚 | 同账户共享当前存档，显式切换后其他设备收到提示；查看历史或刷新不切换，旧页面不能误写 |
| 世界有持续变化 | 开放型也有世界剧情，玩家不参与时事件按条件发展，干预可改变未来计划 |
| 自由度与剧本一致 | 开放型允许拒绝全部预设事件；流程型尊重主线和结局条件，两者都保留主角选择权 |
| 时间与信息一致 | 离线和界面操作不推进剧情；存读档保留时间与事件状态，场外消息通过合理途径获知 |
| 创作自由 | 用户可编辑设定、导入内容、保留路人；来源与补充背景有区分 |

至少使用三个题材、每个包含两名重要 NPC 和若干路人的故事开展连续游玩测试。质量评估与新手可用性测试分别记录，不以接口成功代替玩家体验。性能报告列出主流程和辅助任务的实际耗时及调用量；缓存优化以保持信息范围和内容版本正确为前提。
