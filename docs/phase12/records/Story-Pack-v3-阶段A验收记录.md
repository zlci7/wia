## 实现结果

### 作者接入

- `schema_version: 3` 通过 `requires: {"spatial": 1}` 明确启用空间合同；程序只接受编译期支持的能力和版本。
- region/place、父级区域、公开地点、有向连接以及玩家、固定 NPC、稳定背景实体的初始位置在创建世界前完成跨文件校验。
- 无效包保持隔离。目录问题包含文件、字段、稳定错误码和预期约束；其他合法包及已有世界不受影响。
- 运行定义冻结 schema 版本、能力清单、地图、人物和初始位置；另存继续使用同一冻结定义。

### 空间运行

- `entity_locations` 是 v3 世界的位置权威来源。场景文字和模型返回的 `scene_characters` 不改变位置。
- 移动必须引用本轮玩家或 NPC 本人提交的行动及成功或部分成功结果，并提供从当前地点到实际到达点的完整有向路线。
- 玩家输入不能代替 NPC 同意跟随。人物同场、稳定背景实体、玩家当前位置和可见相邻地点全部从提交后位置派生。
- 每个移动者必须获得以本次行动为来源的移动后场景视图。协调后的剧情与叙述阶段读取更新后的回合工作态。
- 位置变化与事件、感知、场景视图、时钟和消息在最终事务中共同提交；失败候选不写入世界。

### 存档与界面

- 世界创建时写入完整初始位置和能力清单；另存复制位置、来源与冻结定义；重启后重新校验并投影。
- 玩家界面显示当前地点的名称与描述，以及公开的有向相邻地点；人物列表只显示与玩家同场的重要 NPC。
- 当前权威位置依赖链上的行动与结果事件暂不允许直接纠正；连续移动会保留前后位置来源依赖，拒绝发生在任何写入前。该边界防止后续移动继续依赖已经失效的起点。

## 已知限制

- 《雾都余烬》本阶段只验证接入、交流和空间。作者材料中的银镜、人物状态、关系、物品归属、风险及事件效果尚未成为可执行机制。
- 空间世界的剧情阶段不能用 `actor_in_scene` 绕过权威位置；阶段 C 接入世界推进时需要复用结构化移动与最终事务。
- 当前权威位置依赖链上任一行动或结果事件的内容纠正会被拒绝。自动回溯位置、重放后续移动和重建场景属于后续独立设计，不在本阶段伪造。
- 实际模型证据为三轮短路径，证明正式界面和真实 Provider 能执行本阶段合同，不证明长程叙事质量或完整调查玩法。

## 内部审查结论

阶段 A 的数据、运行、持久化、API 与界面使用同一份位置事实，没有第二套空间状态或根据正文解析位置的路径。CR-A 发现的连续移动纠正、跨地点结果投影、位置来源完整性、事件机会地点绑定与空间路人提升问题均已修复并通过回归。v1/v2 兼容分支明确，默认数据根未被开发和验收操作修改。阶段 B、C 能力没有以空字段、名称分支或提示词效果提前混入样本。阶段 A 已通过，可以按计划进入阶段 B。
