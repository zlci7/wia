## 5. R1 的两个已知约束

### 5.1 `runtime/config` 交叉依赖

`storyapp/app.go` 只用了 `runtimeconfig.WriteFile`，而 `runtime/config` 又引用旧 `agent` 与 `definition`。切断方式：把 WIA 需要的配置读写并入新结构（`model` 或薄 `config`），此后 `runtime/config` 随旧包一起删除。

`runtime/config` 的 14 个测试中大部分覆盖旧 Game Profile 与 legacy 发布迁移，属删除类；文件凭据与密钥写入相关行为要确认在 `secret` 侧仍有等价覆盖。

### 5.2 前端嵌入不能跨目录

`console/embed.go` 使用 `//go:embed all:dist`，指向 `console/web/dist`。Go 的嵌入文件必须位于该 Go 文件所在目录之下，**不能向上引用 `../frontend/dist`**。

因此前端搬迁必须同时决定嵌入包的位置：或把它移到 `frontend/` 同层，或由构建脚本把产物复制到嵌入包目录。**这是 R1 的第二个前置条件**，需在 R1 开工时先定，不能留到执行中途。

## 7. 并发与事务现状核对

架构方案 §6.2 要求"同一世界同时只有一个修改权威状态的 Turn"，并说明现有实现已具备该语义。本次核对确认：

- 存在统一的活跃运行检查与明确的忙碌错误，被多个改变权威状态的入口调用：回合、纠正、设置更新、建议、另存、世界创建、路人提升。
- 提交阶段在短事务内校验 `context_epoch` 与场景版本，并推进 `turn_seq`。
- 存在进程级数据根独占锁，防止多进程写同一数据根。

**未在本次核对中逐行验证的部分**（留待 R2 确认，不阻塞 R1）：

- 上述入口是否全部在**开始模型工作之前**取得预约，而非仅在提交时校验。
- 预约在取消与失败路径上是否都被释放。
- 派生任务（建议、摘要）的发布是否严格走 basis/version 校验。
