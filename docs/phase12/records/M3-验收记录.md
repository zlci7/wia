状态：M3 机制开发完成，两轮复审确认成立的问题均已修复。本页只记录已经执行并观察到结果的证据，未完成项明确标注。确定性测试、浏览器验证、真实模型验证与用户体验验收分开记录，不用一种证据替代另一种。真实模型质量与最终用户体验验收仍待用户本人完成。

## 范围变更（记录，不改写历史）

产品定位收窄为**开发者准备世界和人物，玩家直接进入、自由行动**。因此以下已交付能力不再作为玩家侧交付与验收项，代码保留：

- 面向普通玩家的剧本创作与发布流程；
- 跨剧本主角模板库；
- 游玩中将路人提升为重要人物。

本页下文对上述能力的验证记录**保持原样**：它们记录了当时按旧合同实际执行并观察到的结果，是这些代码仍然存在的原因。范围变更不意味着这些记录作废，也不意味着相关缺陷自动消失——开发者仍会使用的发布与加载路径继续按写入正确性要求验证。

**本轮新增但尚未实现**：地点层级、人物当前位置、由位置推导同场，以及旧存档的位置兼容。合同见[总体技术方案 4.2.1](../总体技术方案.md#421-位置与同场)，当前状态见[开发状态](../开发状态.md)。

- 多组未整理历史：请求提供的窗口有界，原始记录与摘要水位不变，模型材料明确说明未提供部分不代表没有发生。

- 召回去重：移出窗口的较早约定可由默认召回与回合内追加召回取回，且不跨接收者。
- 纠正仍生效：旧组上的纠正不因离开窗口失效。

## U1 行动建议

### 交付

- 三条异步建议、basis 绑定 `message_head / event_head / context_epoch / revision`、同 basis 幂等、开关按世界保存、迟到结果不发布、未选建议不进入历史。

### 确定性证据

- 幂等与作用域：同一 basis 重复请求复用结果；材料不含作者事实、其他人物私有资料或个人记忆；未选建议不改变 heads。
- 迟到与状态：世界切换、删除、epoch 变化、关闭建议时丢弃旧结果；`empty`、`waiting`、`ended`、`disabled` 各状态与"未配置模型时明确报错"分别覆盖。
- 失败输入排除：未提交输入不作为生成依据，失败不计入后续材料。
- 用量：建议调用以 `purpose=suggestions` 计入账本，读取不产生调用。
- 另存与重启：关闭偏好随另存与重启保留，且不触发模型调用。

### 浏览器证据

- 真实 HTTP + 正式前端：面板呈现三条建议；点选填入输入框且不自动发送；已有草稿时建议按钮不可点；编辑后仍可提交（标记为自由输入）；关闭建议后输入框仍可用；重新打开后恢复。
- 视口：1280×720、768×1024、375×812 三档无横向溢出。截图位于本地忽略目录 `.gstack/u1-reports/screenshots/`。

## U2 主角与内容草稿

### 交付

- 包 schema v2：路人稳定身份与公开资料，重要人物可选头像与说话示例；加载器只有一个归一化入口，v1 字符串与 v2 对象都可读，导出与新编辑只写对象形式。
- 主角模板：owner 作用域的创建、读取、按版本修改、删除与列出；选入新世界即复制，之后修改或删除模板都不改变已开始的世界；固定主角的剧本拒绝模板。
- 内容项目与草稿：稳定 `game_id` 的项目身份，草稿可从空白或已发布修订起稿，按 `expected_version` 保存，草稿字段校验与 2 MiB 载荷上限，草稿编辑不影响任何世界。
- 人物在草稿内联可编辑（身份、外观、资料、知情、关切、头像、说话示例、初始地点），发布侧有确定的人物文件映射。
- 双视图预览：玩家视图只携带公开投影，作者事实、人物私有资料与剧情条件只存在于显式请求的作者视图。
- 当前世界主角资料：按 `expected_context_epoch` 版本化修改，接受后递增 epoch 并使旧建议失效，正文、事件与 heads 不变。
- HTTP：`/api/v1/personas`、`/api/v1/worlds/{world}/player-profile`、`/api/v1/content/...` 路由与显式错误码。
- 前端：顶部"创作"入口与独立创作页（我的剧本、草稿列表、分区表单、玩家/作者预览、750ms 防抖自动保存、冲突时保留本地编辑并提供重新载入或复制为新草稿）。

### 确定性证据

- schema：v1 与 v2 路人归一化、legacy ID 由 revision、序号与规范化文本确定生成、重复与未知地点与外链头像被拒绝、对象形式往返编码、v2 包可加载并保留身份。
- 模板：CRUD 与版本冲突、跨 owner 隔离、模板复制进世界后模板变更与删除不影响世界、未知模板与固定主角被拒绝。
- 草稿：项目身份唯一、空白与复制起稿、版本冲突保留原草稿、非法枚举与重复地点与重复人物被拒绝、owner 隔离、草稿编辑不改变世界 definition 与进度。
- 人物往返：从已发布修订复制出的完整人物字段、编辑后写回人物文件、未知地点与外链头像被拒绝。
- 预览：玩家视图不含作者事实、人物私有资料与剧情条件（按响应体断言），作者视图包含且带剧透提示，预览不改变草稿版本。
- 主角资料：epoch 校验、活动写入与重建期间 busy、同值提交为 no-op、历史与 heads 不变、旧建议失效、固定主角拒绝。
- HTTP：路由方法与错误码（400/404/405/409）、版本冲突、玩家预览响应体不含作者字段。

### 浏览器证据

## U3 发布与资源

### 交付

- 发布状态机：校验并冻结草稿 → 写入专属 staging 目录 → 由真实包加载器加载 staging（校验与摘要都由加载器给出）→ 同内容根目录原子 rename → 应用库单事务登记不可变修订并推进项目版本。SQLite 与文件系统不宣称跨介质原子性。
- 幂等与恢复：同一 `request_key` 重发返回原操作，不同载荷冲突；未终结操作在启动恢复时按阶段处理（已登记修订则补交，未完成则清理专属 staging 并明确失败），不扫描或删除未知目录。
- 草稿图片：按内容解码决定媒体类型与尺寸，路径必须是包内 `assets/` 相对引用，同名重复上传替换该资源；发布按字节原样复制。
- 世界资源：建档时把封面与人物头像复制进世界目录并记录世界相对名，读取时拒绝越界名并重新解码验证；模板后续修改、重发或删除修订都不改变已有世界。
- 前端：资源分区（上传、尺寸、设为封面、移除）与"发布修订"动作，发布前先保存、冲突时拒绝发布并报告操作阶段。

### 确定性证据

- 发布：同键幂等、不同载荷冲突、不可变修订只能发布一次、过期项目版本冲突、staging 校验失败不留修订、状态推进到 ready、重启后目录仍可用、新世界冻结新修订。
- 恢复：中断操作对应的 staging 被清理、操作标记为失败且不登记修订，随后同一草稿可正常发布。
- 资源：缺资源拒绝发布、上传按内容校验（非图片、超限、越界路径、空文件被拒绝）、同名上传替换而不堆叠、发布携带字节、删除资源同时清理暂存。
- 世界资源：世界目录保留自己的副本，删除已发布修订目录后世界封面与头像仍可读；读取拒绝 `../` 名称与缺失文件。
- 包形态：`story.json` 为 schema v2 对象形式，修订号稳定且内容变化会产生不同身份。

### 浏览器证据

- 真实 HTTP + 正式前端：新建项目 → 新建空白草稿 → 填写基本信息、地点、人物、路人与作者事实 → 上传封面并设为封面 → 发布修订 → 项目头显示 `已发布 r-<UTC>-<摘要>`；脚本触发的"发布修订"由界面按钮进入同一服务端流程。
- 发布内容用于新开局：`/api/v1/games` 列出新 `game_id` 与新修订，封面返回 200 `image/png`；从该修订建档后场景、人物与封面均来自新内容。
- 主角可编辑：新内容默认允许玩家修改主角资料，实测在建档后的世界里成功修改主角并递增 epoch；作者可在编辑器中把主角固定。
- 刷新与重启：页面刷新后项目、草稿与已发布修订完整恢复。

## U4 导入与导出

### 交付

- 导入先预览：识别格式后映射为草稿并给出报告（理解了什么、哪些不支持、哪些需要确认），原始字节作为不执行附件保存；确认是带版本的，把同一草稿变为可编辑草稿，不产生第二个草稿身份。
- 文本与 Markdown：作为公开背景候选，不执行 HTML、脚本或远程资源，只按文本读取。
- Character Card V2：只接受 `spec=chara_card_v2`、`spec_version=2.0` 的文本卡；姓名、`description`+`personality`、`scenario`、`first_mes`、`mes_example`、`creator_notes`、元数据按方案映射；`{{char}}`/`{{user}}` 只在可预览处替换，其余宏保持原文并列为未支持；`system_prompt`、`post_history_instructions`、`character_book`、`extensions` 一律不执行，并报告为不支持。卡片缺少世界结构，因此导入草稿带一个可用地点、起始时间、作为开场候选的问候语和中性目标行，确认后可直接发布。
- WIA 包：使用与运行时相同的加载器与 schema，绝不沿用来源 `game_id`；路径穿越、绝对路径、重复规范化路径、过深嵌套、非普通文件、超出解压上限的归档整包拒绝。
- 导出：只从已发布修订重建规范归档（story、npcs、被引用资源），不打包任意目录；归档不含世界存档、凭据、会话、日志或用量。

### 确定性证据

- 文本：空文件与超限文件被拒绝；Markdown 报告格式、来源大小、映射与不支持项；预览可编辑但不能用过旧版本确认；重复确认被拒绝；原始字节作为附件落盘。
- 卡片：字段映射（姓名、资料、知情、示例）与宏替换；行为指令、book、extensions 不出现在草稿里；`chara_card_v1`、损坏 JSON、缺少姓名被拒绝；导入草稿确认后**能真正发布**（端到端）。
- 包：导出可被重新导入得到等价的公开内容、作者内容、人物、地点与路人；内部引用按新项目身份重映射；四种恶意归档与解压上限、重复条目整包拒绝；未知修订导出返回未找到。
- HTTP：导入预览/确认与导出的方法与错误码。

### 浏览器证据

- 真实 HTTP + 正式前端：`POST /api/v1/content/imports/preview` 上传 CCV2 卡片 → 报告 `format=ccv2` 且列出未执行指令 → 确认 → 发布 `ready/succeeded` → 新 `game_id` 出现在 `/api/v1/games` → 从该修订建档后场景为卡片映射出的地点、人物为导入人物 → `GET /api/v1/content/revisions/{game}/{revision}/export` 返回 200 `application/zip`。

## U5 路人提升

### 交付

- 归属经历：协调结果新增 `bystanders` 字段，只列出本轮真正参与、且已在定义中的路人；只有被明确归属的路人才把这个结果记为本人经历。同处一室、出现在正文或被玩家知道都不算。未定义的人员归属使本轮失败而不是静默丢弃。协调合同同时把路人的稳定 id 交给模型，避免从正文猜人。
- 预览：公开名称、描述、头像、当前位置与在场状态；普通预览只给玩家已知的经历与总数，作者视图才给私有经历明细；草稿字段默认取自公开信息。
- 确认：单事务内生成稳定身份、写入人物与其来源记录（`character_origins`），仅把选中且确属本人的经历跟随到新身份（不复制给无关记录），从活动路人列表移除同一人且**不改变其物理位置**，递增 context epoch，使旧建议失效。进行中回合、另存、记忆重建期间返回 busy；同一 `request_key` 重复提交返回同一人物，换键提升同一人返回冲突；删除世界后迟到的提升不能复活数据。
- 提升后从下一轮起作为重要人物参与；路人不拥有独立决策调用。
- 前端：场景抽屉列出已定义路人并提供提升入口，预览面板支持编辑与确认。

### 确定性证据

- 归属：只有被归属的路人获得经历，其他路人的经历不移动；未归属的在场路人经历数为 0；外人的来源被拒绝；旧 epoch 被拒绝。
- 事务：epoch 递增、路人从活动列表移除、其他人保留、人物进入世界名册、来源记录写入、重复同键幂等、换键冲突、缺请求键或空资料被拒绝。
- 世界边界：`definition_snapshot` 仍是冻结模板（纠正不污染模板），实时名册来自角色表；提升后下一轮正常提交（新人物获得本轮视图）；删除世界后提升失败。

### 浏览器证据

- 真实 HTTP + 正式前端：在既有存档中打开"场景与人物" → 列出 10 名有稳定身份的路人 → 打开"卖花的老人"预览（位置=旧渡口客栈、已归属经历 0 条、玩家可见经历为空并说明只继承明确归属的结果）→ 填写身份/资料/知情/关切 → 确认 → 提示"已成为重要人物"、路人列表减少一项、名册出现该人物 → 存档内后续回合正常提交（第 252/253 条消息），新人物出现在对话对象列表中。
- 视口：1280×720、768×1024、375×812，移动端面板无横向溢出。截图位于本地忽略目录 `.gstack/u6-reports/screenshots/`。
