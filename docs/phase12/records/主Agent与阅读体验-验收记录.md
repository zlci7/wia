## NPC 衔接与世界主持

`interaction_continuity_test.go` 使用受控模型输出，执行真实 Turn 阶段和协调校验；城市事务所、轨道维修站是通用合成场景，区别于真实剧本游玩样本。

| 场景 | 已验证结果 |
| --- | --- |
| 拒绝 | 实际听众收到本人原话与来源，在已有第二阶段独立回应；说话者不重复回应自己 |
| NPC 私聊 | 指定听众收到原话，第三人与玩家正文不获得私聊；本人回复保持私人听众范围 |
| 争夺物品 | 两份尝试裁定为一次转移，唯一物品只有一个持有人，决定阶段保持有界 |
| 行动失败 | 本人后续获准请求包含失败观察及实际事件来源 |
| 无效双重归属 | 同一物品的冲突结果用一次纠正仍失败后停止，原快照不变，无转移输出 |

两个题材各四项，加双重归属反例，共九个子场景通过。完整 `turn` 包测试与 `go test -race ./backend/internal/turn -count=1` 通过；race 使用现有 w64devkit GCC 的进程级环境变量。

世界主持沿用既有调用和两名刺激接收者上限，提示版本 `story.open-world.v3`；《雾都余烬》新导入修订为 `mist-embers.pack.v9`。城市调查与维修站的发展材料使用固定事实、当前压力、合理发展、信息传播四部分，重要人物继续决定本人反应。

发展材料评估、四片段完整回合容量、剧本加载、初始目录和世界信息回归通过。最终四片段受控用例共 26 次请求，单次最大输入估计 11,818，累计 198,073，输入上限仍为 12,000；该用例没有补充读取或技术纠正，不代表任意长对白、真实费用或语义质量。实际维修站测试包的跨年、现金与物品变化、另存重启和旧冻结定义回归通过。

## 正文合同与表达

正文提示版本 `story.narration.v13`，表达任务明确为段落、节奏、关键对白和实际后果；事件归属、公开或私密听众、拒绝与沉默、未执行结果和有限视角继续作为依据。表现细节不形成新的后续世界事实。

正文解析、人称与可听范围、最终能力投影、保存设置与输出预算、因果衔接及完整四片段容量回归通过。三档篇幅预算仍为 768 / 1,536 / 3,072。

## 行动建议

提示版本 `story.suggestions.v2`。每项包含对象、具体做法与目的，中文通常 35—70 字；三项按当前情境形成不同参与方式，长度是软目标。输出保持三个字符串和单项 120 字上限。

既有建议测试全部通过：许可材料、单次生成与幂等、迟到世界或版本丢弃、失败输入排除、失败有界、偏好另存与重启。建议仍只填入可编辑草稿，实际行动通过原提交机制执行。受控输出不证明新提示的真实生成质量。

## A「暖纸浮层」正式界面

正式 Vue 界面使用暖纸实底正文、平台无衬线、圆润玻璃操作层。角色、背包、地图和人物共用资料窗口，桌面采用非模态侧浮层，720px 以下采用模态底部面板。正文、三个建议和自由输入共用阅读滚动区域。建议完整换行，每项独占一行，点选只填入空草稿。

视觉规范见 [DESIGN.md](../../../DESIGN.md) 与 [组件侧表](../../../.impeccable/design.json)，均依据当前正式样式与组件提取；YAML、JSON、引用和文字一致性检查通过。

世界日期、现金和物品读取真实服务端投影；《雾都余烬》图中余额为 8 金镑 14 苏勒，背包为玩家实际持有的三件道具。维修站使用独立测试包的 2189 年日期、地点与物品，前端和通用提示保持题材无关。

首次进入定位到最新正文开头，建议异步加载后仍保留该位置；历史分页与消息追加保留阅读锚点。查看资料保留草稿、交谈对象、游戏时间和世界版本；桌面正文与输入仍可聚焦，手机资料层约束焦点，Escape 关闭后恢复入口焦点与原阅读位置。

| --- | --- |
| 三项建议 | 桌面、手机、矮屏纵向排列；120 字边界完整换行，点选不提交，已有草稿保留 |

浏览器运行真实 API 与正式构建，模型为隔离的受控替身。截图中的建议是明确的布局测试文本，不代表新提示词的生成质量。测试数据根独立创建和清理，用户存档及本机模型配置不参与验证。

### 复验入口

先在 `frontend` 执行正式构建，然后在仓库根通过进程环境变量 `WIA_BROWSER_FIXTURE=1` 运行 `go test ./backend/internal/storyapi -run '^TestBrowserFixture$' -count=1 -v -timeout=25m`。仅使用其输出的本地隔离地址，将 `WIA_FIXTURE_URL` 与现有 gstack `browse.exe` 路径 `WIA_BROWSE_BIN` 传入三个浏览器脚本，顺序执行。结束时 POST `/fixture/finish`。服务使用受控模型并自动限时关闭；验证失败时停止后续脚本，修复后重新构建与创建隔离 fixture。
