#### 本阶段的验证工具（`tools/refactor`）

工具是**独立 module**（有自己的 `go.mod`），因此不在根构建与根测试里。**在仓库根目录执行 `go run ./tools/refactor ...` 会直接报错**，正确用法是：

```powershell
cd tools/refactor
go run . <命令> [flags]
```

- 命令表是唯一的子命令列表（dispatch 与帮助都由它派生，`go run . -h` 即可查全部），`dropfunc` 自带回归测试。
- **两个会咬人的行为**（A1 实测）：`qualify -tests` 是**只改测试文件**，不是"也改测试"——生产调用点要另跑一次不带 `-tests`；`move`/`unqualify` 会**把源文件的文档注释留成孤儿**并用 `go/printer` 重排格式（`unqualify` 还会连带剥掉注释里的 `turn.`，把句子截断）。**每次搬完必须 `gofmt` + 清孤儿注释 + 读一遍改动**。
- **不再新增迁移工具。** 现有工具够用；小缺陷用 `gofmt` + 人工清理 + 测试解决即可，不必把它打造成通用重构框架。
- **字节级核对（`cmpfunc`/`strcmp`）只用于三类东西**：Prompt 文本、Schema、关键 SQL / 数据迁移合同。**普通 helper 不做**——`go build` + `go test` + review 足够。注意这类工具**不得过度替换**：把函数名全局换成 `NAME` 会改写包含该名字的标识符，制造假差异。

**「能编译」不等于「没改行为」**：已发生三次静默偏差——`visibleEvents` 无处传递（玩家投影会变空）、`intent.Input` 未填（私密消息为空）、`SceneFor` 手写重建时 fallback 用了世界场景（会把不在场的地点告诉角色）。所以**涉及字段填充、roster/顺序、投影的搬移必须有行为测试兜底**——这是测试的责任，不是逐字节比对每个 helper 的理由。

#### 仍然有效的硬约束

- **⚠️ 新代码不得落进 R5 待删的旧包目录。** `backend/internal/memory` 是旧 Game Runtime 包（R5 删除），WIA 的 memory 类型当前在 `backend/internal/memorymodel`。**两者都是 `package memory`，编译与 `go doc` 都不报冲突**——`go doc ./backend/internal/memory` 会把新旧类型混在一起列出。同类：`agent`/`context`/`task`/`tool`/`gateway`/`httpapi`/`definition`/`session`/`idgen`/`trace`/`bootstrap` 也全是旧的。
- **`pure ≠ domain`**：`settings.go`/`behavior.go` 的 Prompt 指令构造器虽是纯函数，但回答"怎么把设置翻译给模型看"，属 `turn`（已在 3.4 搬入）；`migrateWritingPreference()` 是旧字段兼容迁移，属 storage migration 或 application 兼容层（仍在 `storyapp`）。
- **四层归属**：`content` 拥有外部包格式（可删除）、`story` 拥有归一化后的不可变运行定义、`world` 拥有可变/已提交的世界词汇、`plot` 拥有世界推进规则。依赖：`content → story`、`turn → story`、`content → plot`、`story → plot`、`plot → world`。
- **`plot` 与 `content` 的分工**：`content` 负责"内容包是否合法"，`plot` 负责"剧情定义本身是否合法"；**`plot` 永不 import `content`**。运行时入口调 `plot.Validate(def, progress)`，发布入口只调 `plot.ValidateDefinition(def)`。
- **storage 边界（选项 C）**：**领域名词可以进 storage（表示"存了什么"），领域决策不能进**。检验：*"删掉 SQL、换成 PostgreSQL 后，名字和参数是否仍然合理？"*。`WorldTx` 只提供具名持久化操作，**不暴露 `Exec`/`Query`/`QueryRow`**。
- **`CoverURL` 不属于运行定义**：目录条目放 `loadedPack.Catalog`，`WorldGame()` 优先取 pack 的 `Catalog`，pack 不在时从 `story.Summary` 兜底。**新增目录字段时放 `Catalog`，不要加回 `story.Summary`。**
- **`MetaGetTx`/`MetaSetTx` 只剩 8 处，全在 `promotion.go` 的 `PromoteCharacter`**（约 140 行事务，体内有游标循环）。提升路人不在当前交付范围（实现保留）。另有 6 个自开事务但不用 `MetaTx` 的函数（`createWorldFromPack`/`completePublish`/`ReadUsage` 操作表结构，`DeleteWorld`/`SaveAs`/`performCopyLocked` 只动 `app.db`）待处理。
- **R0 保留表要求的旧包过筛已完成**，见 [R3 旧包过筛](records/R3-旧包过筛.md) 第 10 节的逐项裁定：保留/淘汰**明确后置**（理由与到期条件已写明）、摘要覆盖可验证 / 检索代码级上限 / 同源冲突**现在实现**、旧 Runtime 的 future-memory filter**不迁移**。这三项目标落在 C 块，**旧 Runtime 的删除不再被它们阻塞**。旧 `context`/`memory` 的测试在 D1 之前保持原样。
- **改写 Go 源码的十条硬规矩**（每条都由一次实际事故换来）：① 不要用 `Get-Content -Raw` / `Set-Content`——它们按系统代码页解码再编码，会把所有非 ASCII 字面量写成乱码，而行数、diff 规模、字节数都看不出异常；用 Go 程序或 `edit` 工具。② 不要靠"列 0 的 `}`"判断函数体边界，按 `ast.Decl` 删除。③ 判断标识符是不是目标符号，用它绑定的 `ast.Object` 是否指向**包级**声明（函数、类型、常量都算，不只是类型）；局部同名变量必须放过。④ 判断结构体字面量的字段名要按**包**（而非按文件）收集类型名；嵌入字段名（无冒号）也要保护。⑤ 不要手工枚举"能放表达式的位置"——漏一个就静默失效（第一版漏了 `switch` 的 `case`）。⑥ **先限定引用、再删除定义**：顺序反了会产出 `wiaworld.X` 这种包里不存在的成员。⑦ 重写 import 块的工具**必须保留它不认识的导入**，否则会删掉 `embed`/`zip`/`slices`/`jsonschema`。⑧ **不要为搬运而手抄**：schema 这类长字面量要从 Git 原文按字节提取，再用字符串包含关系验证；函数用 `tools/move` 逐字搬。⑨ 正则替换要限定接收者：`\.path\b` 会误伤 `DiagnosticLog.path`，`"app.db"` 会被改成字符串里带方法调用的怪东西。⑩ **比对工具不得过度替换**：把函数名全局换成 `NAME` 会改写 `BehaviorPolicyVersion` 这类"包含函数名"的标识符，制造假差异——只在声明行替换。
- **一次一个工作单元**：一个依赖簇、一个明确 owner、一个提交。**500–1500 行可以接受**——不必死守 200–800，也不要一次 `+5000/-5000`。
- **不再新增 package**，除非确实无处可放。`turn`/`content`/`memory`/`app` 里放 500–1500 行不是问题；**不要为了清空 `storyapp` 发明 `WorldService`/`SuggestionService`/`CorrectionService` 这类新服务层**——那是重新制造 `storyapp`。
- **不追求 `Database()` 归零，不追求所有旧 Runtime 行为都被迁移，不追求架构纯度。** A/B/C/D 四块做完即停，转产品功能（空间系统、人物状态）。
