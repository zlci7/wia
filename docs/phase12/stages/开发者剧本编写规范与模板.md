# 开发者剧本编写规范与模板

Story Pack v4 编写与加载合同。[v4 完整文件模板](../templates/story-pack-v4/README.md)与本合同配套；[v3 基础包](../templates/story-pack/story.json)保留旧格式示例。实际交付与验证状态见[开发状态](../开发状态.md)。

阶段接口和验收见[渐进材料与持续世界技术方案](渐进材料与持续世界-技术方案.md)。已有能力字段见[Story Pack v3 技术方案](../Story-Pack-v3-技术方案.md)和[模型主导的可选能力模块](模型主导的可选能力模块.md)。

## 1. 剧本包组成

一个剧本包包含入口配置、分类世界材料、固定人物资料和按需启用的能力配置。`story.json` 保存目录与初始条件；长篇背景、规则、真相和人物知识分别保存为 UTF-8 Markdown。JSON 保存需要准确引用的标识、地图、类型、数值与初始归属。

```text
your-story/
  story.json
  materials.json
  world/
    locations.json
    background/
      core.md
      history.md
      society.md
    rules/
      anomalies.md
    facts/
      current-situation.md
    locations/
      reception.md
    items/
      special-object.md
  narrative/
    progression.json
    conflicts.md
    developments.md
  npcs/
    contact/
      npc.json
      profile.md
      knowledge.md
      plans.md
  capabilities/
    state.json
    relations.json
    items.json
    rules.json
  assets/
```

目录按材料规模使用；小剧本可只有一份背景、两个地点和一个人物。加载器读取入口明确引用的文件。材料职责由索引声明，文件名与 Markdown 标题不承担运行协议。

每个固定重要 NPC 有一个 `npc.json`，详细资料可继续拆分。人物名单由作者确定。地图限定可行动的具体地点；背景人物保持背景身份。

## 2. 入口配置

| 部分 | 字段 | 内容 |
| --- | --- | --- |
| 身份与版本 | `schema_version`、`game_id`、`revision` | 格式版本与稳定剧本身份；内容变更发布新 revision |
| 展示信息 | `title`、`description`、`gameplay`、`mode` | 名称、简介、自由活动范围、开放型 `open`；题材写入介绍 |
| 主角 | `player` | 默认身份、资料、允许编辑的范围及可选初始状态 |
| 开始条件 | `initial_location`、`clock`、`opening` | 开始地点、游戏时间及玩家实际能感知的开场 |
| 数据引用 | `data_files` | 地图以及已启用能力的结构化 JSON 文件 |
| 材料目录 | `materials_file` | 材料索引文件 |
| 固定人物 | `npcs` | 各人物 JSON 的包内相对路径 |
| 能力声明 | `requires` | 已有可选能力以及拟新增的持续推进能力 |

v4 入口示例：

```json
{
  "schema_version": 4,
  "game_id": "story-template",
  "revision": "story-template.v2",
  "mode": "open",
  "title": "填写剧本名称",
  "description": "填写题材、玩家身份与当前局势。",
  "gameplay": "填写可探索的地方、可接触的人物与自由活动。",
  "requires": { "spatial": 1, "progression": 1 },
  "player": {
    "name": "来访者",
    "profile": "填写主角开始时的身份和已知经历。",
    "requirements": "填写允许玩家修改的资料范围。",
    "editable": true
  },
  "initial_location": "reception",
  "clock": "第 1 日 09:00",
  "opening": "你走进接待室，联系人正在桌旁整理资料。",
  "materials_file": "materials.json",
  "data_files": {
    "locations": "world/locations.json",
    "progression": "narrative/progression.json"
  },
  "npcs": ["npcs/contact/npc.json"]
}
```

`data_files.locations` 的内容为 `{ "locations": [...] }`，地点字段沿用 v3。具体 place 有稳定 ID、名称、公开说明、可选所属 region 和有向连接；往返分别声明。长篇地点背景进入材料索引，地图说明保持简短且可公开。

能力文件仅引用已启用的能力：

| 引用键 | 文件顶层字段 | 启用声明 |
| --- | --- | --- |
| `state` | `state_definitions` | `requires.state = 1` |
| `relations` | `relation_definitions`、`initial_relations` | `requires.relations = 1` |
| `items` | `item_definitions`、`item_instances` | `requires.items = 1` |
| `rules` | `action_rules` | `requires.rules = 1` |
| `bystanders` | `bystanders` | 背景人物，沿用空间能力 |
| `progression` | `developments`、`initial_plans`、`external_schedules` | `requires.progression = 1`，拟新增 |

主角和 NPC 的 `initial_state` 留在各自配置中。物品实例初始归属填写持有人或地点之一。能力语义沿用现有合同，拆文件不改变状态类型、关系归属、物品唯一归属或固定判定。

v4 的长文字统一由材料索引引用；入口不重复保存 `background`、`rules`、`author_facts`，NPC 的详细知识和计划也由材料目录提供。短材料在索引内写 `text`，长材料使用 `file`，二者择一。v1/v2/v3 的内联字段继续按原格式读取。

## 3. 材料索引

`materials.json` 顶层为 `{ "materials": [...] }`。每份材料表达一个可独立读取的主题，保持接收权限与正文内容一致。

```json
{
  "materials": [
    {
      "id": "world-core",
      "purpose": "background",
      "visibility": "public",
      "delivery": "core",
      "summary": "世界的时代、公开常识和当前生活环境。",
      "file": "world/background/core.md"
    },
    {
      "id": "case-truth",
      "purpose": "author_facts",
      "visibility": "author",
      "delivery": "on_demand",
      "summary": "当前事件中已经成立的隐藏事实。",
      "location_ids": ["reception"],
      "entity_ids": ["npc:contact"],
      "file": "world/facts/current-situation.md"
    },
    {
      "id": "case-development",
      "purpose": "development",
      "visibility": "author",
      "delivery": "on_demand",
      "summary": "当前冲突中的压力与可能发展。",
      "location_ids": ["reception"],
      "entity_ids": ["npc:contact"],
      "file": "narrative/conflicts.md"
    },
    {
      "id": "contact-knowledge",
      "purpose": "npc_knowledge",
      "visibility": "owner",
      "owner_id": "npc:contact",
      "delivery": "on_demand",
      "summary": "联系人本人掌握的初始线索与误解。",
      "file": "npcs/contact/knowledge.md"
    },
    {
      "id": "contact-plan",
      "purpose": "npc_plan",
      "visibility": "owner",
      "owner_id": "npc:contact",
      "delivery": "on_demand",
      "summary": "联系人准备做什么及重新考虑的情境。",
      "file": "npcs/contact/plans.md"
    }
  ]
}
```

| 字段 | 合同 |
| --- | --- |
| `id` | 包内唯一、稳定的材料标识；作为来源引用 |
| `purpose` | `background`、`world_rules`、`author_facts`、`development`、`npc_profile`、`npc_knowledge`、`npc_plan`、`location_lore` 或 `item_lore` |
| `visibility` | `public`：可公开内容；`author`：作者层真相；`owner`：指定人物本人的资料 |
| `owner_id` | `owner` 材料的所有者；与已定义人物一致 |
| `delivery` | `core`：对应用途的精简基础材料；`on_demand`：按相关性提供 |
| `summary` | 简短且与正文同权限的主题索引；摘要同样受知情限制 |
| `location_ids`、`entity_ids`、`item_ids` | 可选关联；`item_ids` 引用物品实例 ID，精确标识辅助选择 |
| `known_to` | 可选人物 ID 数组；仅 public 材料可用，声明哪些人物开场已知这份详细资料。公开精简常识无需逐人声明；当前地点的公开 `location_lore` 可以作为可观察情境提供 |
| `file` / `text` | 包内 UTF-8 文件或内联正文，单一来源 |

世界规则可以包含普通人不知道的部分，应分别声明为公开材料和作者材料。主持按调用职责读取作者材料；NPC 读取本人材料和本人有来源的经历；正文只读取玩家获准材料。具体可用调用由系统的用途映射决定，作者字段不授予系统权限。

同一主题可以分别写真实情况、某人的知识和某人的误解，各份正文独立、来源明确。人物交流使接收者获得实际说出的内容，不自动授予整份原始档案。

初始计划正文最多 1200 个 Unicode 字符；计划的运行记录保存当前内容与状态，人物调整或取消后以存档中的记录为准。单次调用的可读目录最多 16 份，自动选入最多 4 份相关详细材料；补充请求与全部输入共享现有预算。结构化模块文件与启用能力一一对应。v4 文件包支持导入、发布与导出，结构化编辑与作者预览需在源文件中进行；发布后可用独立存档检查实际场景。

## 4. 渐进式披露

包加载时校验并冻结所有引用材料；每次模型调用只选取需要的部分。冻结内容与提供模型输入分别处理。

| 层级 | 输入内容 | 选择依据 |
| --- | --- | --- |
| 基础 | 精简公开世界概况、当前身份、当前地点、阶段刺激和必要执行合同 | 当前调用用途与接收者 |
| 相关 | 涉及的地点、物品、人物知识、计划和相关经历 | 当前表达、已知对象、地点变化、到期计划和已确认结果 |
| 详细 | 异常物品限制、组织资料、地点历史等正文 | 当前判断需要，或模型提出获准材料请求 |

选择顺序为：按用途与知情权限过滤 → 根据当前对象和情境选择 → 装配必需事实与可选材料 → 使用现有上下文预算。材料索引也只提供获准且相关的部分。普通模型调用不接收整包目录。

材料相关性可由模型理解，读取权限与容量由程序执行。首批装配使用稳定 ID、当前地点和对象关联；需要细化时，同一用途可进行有上限的材料请求。模型请求材料 ID，运行系统从冻结内容提供正文。材料请求不产生人物决定、事件或状态变化，最终候选才参与结算。

当前判断必需的结构化事实随能力接入提供。例如物品转移需要该实例当前归属，移动需要当前地点与相关路线，关系提案需要本人已有经历来源。可选背景可以整份省略；已选行动的必要规则和事实必须完整。必需内容超出容量时明确失败，输入保留。

例如玩家进入诊所时，提供公开描述和实际同场信息；检查银镜时，加入可观察现象、当前归属和已获知经历；世界主持裁定银镜影响时，再读取相关作者规则。NPC 未获知银镜性质时，其决策保持本人的有限认识。

## 5. 作者材料模板

### 基础背景

```markdown
# 基础背景

## 时代与环境
[当前时代、社会环境和普遍可知的常识]

## 当前局势
[开始时公开可知的情况]

## 玩家起点
[玩家身份及允许自由活动的有限范围]
```

历史、社会、组织和地理等详细主题各自拆分，基础背景保持精简。

引用现有作品的剧本明确原作截止时间、开场时已经成立的事实，以及后续同人分支。较晚的原作事件、教会变化和技术发展按时间标注，不自动成为较早开场的既有事实。作者参考资料与运行材料分别保存，运行材料仍按用途和知情范围引用。

### 世界规则与作者真相

```markdown
# 主题名称

## 已成立的事实
[已经存在的能力、经历、隐藏身份或真实归属；标明确定与未知部分]

## 表现与限制
[情境中的合理表现和边界；普通行为由模型理解]

## 信息分布
[哪些人物知道什么、误解什么，以及各自的来源]
```

世界规则描述世界设定。应用的 Prompt、知情校验、SQL、模型连接、输入预算和系统命令由应用负责。原作参考、剧本原创、尚未核实的参考资料分别标明。

引用作品的作者资料示例见[诡秘世界参考目录](../reference/诡秘世界/README.md)。资料库可保存完整主题与出处；剧本从中编写相关材料，并在 `materials.json` 声明用途、权限与关联对象。资料库目录不参与自动装配。

### 世界发展

```markdown
# 世界发展

## 当前冲突
[尚未解决的问题、涉及人物与地方]

## 压力与机会
[外部环境可能产生的变化]

## 玩家影响
[参与、拒绝、离开或改变局势可能影响哪些方面]
```

发展材料描述可能性；实际行动和后果结合最新事实决定。作者确定的外部安排可以配置时间，例如当晚暴雨；人物计划的检查时间只触发重新考虑。

### 人物资料

`npc.json` 保存 `definition_id`、`revision`、`entity_id`、姓名、角色、外观、简短本人性格资料、`initial_location`、可选 `initial_state` 和表达示例。外观与角色为公开呈现，本人性格资料供本人决策；隐秘身份进入本人材料与作者真相。

```markdown
# 本人知识

## 亲历与确认
[亲历或已经核实的事实及来源]

## 听说与推测
[尚未核实的线索与误解]

## 尚未核实的问题
[人物依据本人线索提出的疑问；作者掌握但人物尚无概念的秘密写入作者材料]
```

```markdown
# 本人计划

## 当前关切
[为何在意这件事]

## 行动意向
[准备做什么、依据本人哪条线索]

## 时间意向与重新考虑
[何时考虑行动、什么变化可能使其改计划]
```

## 6. 持续推进配置

`narrative/progression.json` 示例：

```json
{
  "developments": [
    { "id": "local-conflict", "material_ids": ["case-development"], "location_ids": ["reception"], "entity_ids": ["npc:contact"] }
  ],
  "initial_plans": [
    { "id": "contact-follow-up", "owner_id": "npc:contact", "material_id": "contact-plan", "review_after_minutes": 60 }
  ],
  "external_schedules": []
}
```

`review_after_minutes` 相对开场游戏时间，只表示首次检查。之后的计划内容、依据、下次检查时间与变更由本人决定并保存。外部安排可使用 `{ "id": "evening-rain", "at_minute": 1080, "material_id": "evening-weather" }`，`at_minute` 沿用游戏时钟的绝对分钟合同。

人物行动依据本人知识、当前计划与新刺激决定。世界主持提供外部变化并协调后果；人物对白、跟随、调查、交付和撤离由本人提出。到期计划可以继续、改变、暂缓或放弃，不要求作者填写行动成功标记。

关键发展以材料、计划或外部安排表达。新开放包使用持续推进合同；已有 v1/v2/v3 世界继续读取冻结的节点和生成事件记录。

## 7. 发布与初始条件

所有 JSON、NPC 文件、材料正文和资源参与 revision 内容校验。引用路径限定包内，校验 UTF-8、文件类型、大小、材料 ID、用途、人物和关联对象。导入、导出与发布保留实际引用内容。

| 作者配置 | 存档中的运行记录 |
| --- | --- |
| 初始位置、地图和物品归属 | 当前权威位置、唯一物品归属及变化来源 |
| 状态、关系定义与初值 | 当前值与有序变化 |
| 人物初始知识和计划 | 获准经历、计划变更及检查依据 |
| 世界真相、发展材料与外部安排 | 已发生事件、各人的感知及待检查安排 |
| 固定判定规则 | 已准备的参数、骰点与结算结果 |

作者提交前核对标识引用、地点连接、初始归属、开场一致性与材料知情范围。新存档冻结整个运行定义和材料；已有存档读取自己的冻结内容。单个剧本接入由配置和材料完成。
