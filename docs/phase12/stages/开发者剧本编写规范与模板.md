# 开发者剧本编写规范与模板

状态：编写合同提案，待 review。附带的基础 JSON 包使用当前 Story Pack v3；Markdown 材料引用与持续计划配置属于待实现合同，当前加载器不接受这些新增字段。

现有格式见 [Story Pack v3 技术方案](../Story-Pack-v3-技术方案.md)，可选能力见 [模型主导的可选能力模块](模型主导的可选能力模块.md)。运行状态和验证证据以 [开发状态](../开发状态.md) 为准。

## 1. 必填内容

一个剧本包描述世界的起点。作者填写静态配置和文字材料，游玩后的当前状态由存档保存。

| 部分 | 作者填写内容 | 编写要求 |
| --- | --- | --- |
| 身份与版本 | `game_id`、`revision`、格式版本 | 剧本身份稳定；改变内容使用新 revision |
| 展示信息 | `title`、`description`、`gameplay`、`mode` | 名称、一句话介绍、玩家可以做什么；本模板使用开放型 `open`。悬疑、科幻等题材可写在介绍中，当前没有独立题材字段 |
| 公开世界背景 | `background` | 时代、环境、社会常识、当前局势；只写玩家和人物可共享的背景 |
| 世界设定 | `rules` | 世界中的能力和限制，例如异常物品的一般表现；描述语义，不要求列举行动条件树 |
| 作者真相 | `author_facts` | 世界主持需要知道的真实情况、隐藏身份、矛盾和秘密；人物知道哪些内容另写 |
| 主角起点 | `player`、`initial_location`、`clock` | 默认姓名、身份、可编辑范围、开始地点和游戏内时间；玩家尚未作出的承诺留给玩家 |
| 开场 | `opening` | 玩家此刻实际能看到、听到或已经知道的情境；与初始位置、人物名单和物品一致 |
| 有限地图 | `locations` | 稳定 ID、名称、说明、place/region、连接和公开属性；人物位于具体 place。连接有方向，往返需要分别声明 |
| 固定重要人物 | `npcs` 引用的 JSON 文件 | 身份、性格、初始位置、本人知识和关切；初始知识允许不完整或错误 |

作者真相、人物认知、未来计划分别编写。开场及地点的公开描述只包含对应接收者可获得的内容。稳定标识用于配置引用，名称用于展示；正文措辞不承担标识职责。

## 2. 按需配置的能力

| 能力 | 当前配置入口 | 作者决定什么 |
| --- | --- | --- |
| 空间 | `requires.spatial`、`locations`、各实体 `initial_location` | 有限地图和初始位置；v3 必须启用 |
| 状态栏 | `requires.state`、`state_definitions`、`initial_state` | 状态名称、说明、类型、范围、初值和更新策略；普通状态使用 `model` |
| 关系 | `requires.relations`、`relation_definitions`、`initial_relations` | 关系维度、范围、初值及可选数值预算 |
| 物品 | `requires.items`、`item_definitions`、`item_instances` | 物品含义、公开属性和每个实例的初始归属 |
| 固定判定 | `requires.rules`、`action_rules` | 当前支持的特定玩家行动规则、骰型、阈值与修正；通用玩家/NPC 风险判定待另行设计 |
| 背景人群 | `bystanders` | 固定身份、名称、说明和初始位置；保持背景人物身份 |
| 呈现偏好 | `defaults`、封面和头像引用 | 已有叙事设置的初始偏好及包内图片资源；省略时采用应用默认值 |

声明能力时同时填写它需要的数据；没有对应数据时省略能力及其配置。状态、关系、物品和判定各自可选，不要求所有剧本启用同一组合。

物品实例初始归属填写持有人或地点之一。接受委托、拒绝邀请、拾取和交付通常由模型理解并保存实际结果；只有明确需要数值规则的玩法才配置固定判定。

模型连接、密钥、上下文预算和系统调用职责属于应用配置。作者不需要编写系统 Prompt、SQL、脚本或工具命令。

## 3. 作者文字材料模板

以下各段可直接填写。当前基础包将文字填写到相应 JSON 字符串；包内 Markdown 引用接入后可以分别保存为材料文件。

### 公开背景

```markdown
# 公开背景

## 世界与题材
[时代、地点、社会环境和公开可知的世界设定]

## 当前局势
[故事开始前已经发生、当地人普遍知道的事情]

## 玩家身份
[主角在这个小世界中的身份与已知背景]

## 自由行动范围
[玩家可以接触的地方、人物和活动]
```

### 作者真相

```markdown
# 作者真相

## 已成立的事实
[谁做过什么、隐藏资源在哪里、尚未公开的真实情况]

## 核心矛盾
[各方想要什么、冲突为什么存在]

## 特殊事物
[异常物品或能力的表现、限制和可能后果]

## 信息分布
[哪些人知道哪部分；其余人物为何尚不知道]
```

### 世界发展材料

```markdown
# 世界发展材料

## 尚未解决的矛盾
[当前有哪些持续存在的问题，涉及哪些固定人物和地方]

## 确定的外部安排（可选）
[作者确定的外部事实及时间，例如当晚有暴雨。人物如何应对仍由其决定]

## 可能的发展（可选）
[合理的发展方向、压力或机会；这些内容尚未发生]

## 玩家介入
[玩家参与、拒绝、离开或改变局势可能影响什么；具体结果由当前事实与人物决定]
```

### 单个人物资料

```markdown
# 人物资料

## 身份与性格
[稳定身份、公开表现、动机和行为倾向]

## 本人初始知识
[亲历、听说、猜测分别写明；可以与作者真相不一致]

## 本人初始关切
[在意什么、担心什么、希望达成什么]

## 本人初始计划（可选）
[准备做什么、依据哪条本人掌握的线索、时间意向及可能重新考虑的情境]

## 表达风格（可选）
[简短对白示例，只作风格参考]
```

计划可改、可放弃、可继续追查。写“准备今晚调查旧诊所”即可；人物去不去、见到谁、物品是否仍在那里，根据游玩中的实际局势决定。未来设想保持为材料，已经发生的结果才进入事件历史。

## 4. 当前可加载的基础包

复制 [基础包目录](../templates/story-pack/story.json) 中的 `story.json` 和 `npcs/contact.json`，修改身份、地点、人物及文字内容。目录结构为：

```text
your-story/
  story.json
  npcs/
    contact.json
```

该模板声明空间能力，提供两个地点和一个固定 NPC。它不配置剧情节点、状态、物品或骰子；人物关切由当前 NPC 决策读取。时间与人物自身计划驱动的场外调度属于下一轮实现，省略节点本身不会启用这一能力。

状态栏可按需加入下列配置，并在 `requires` 中增加 `"state": 1`：

```json
{
  "state_definitions": [
    {
      "id": "fatigue",
      "name": "疲劳",
      "description": "行动强度、休息与遭遇造成的身体负担。",
      "type": "integer",
      "minimum": 0,
      "maximum": 100,
      "default": 0,
      "scope": "player",
      "projection": "self",
      "knowledge": "owner",
      "update_policy": { "kind": "model" }
    }
  ]
}
```

这个片段合并到 `story.json`；`player.initial_state` 可覆盖默认初值。人物共用的状态定义可采用当前合同支持的 `scope`，不要求为每个 NPC 复制定义。更多能力字段以现有可选能力合同为准。

## 5. Markdown 引用与持续计划配置提案

目标目录在基础包上按需增加 `materials/`。短材料仍可内联；长材料可以引用 UTF-8 Markdown 文件。

以下是拟新增的 `materials` 字段示意，当前加载器尚不支持，不合并到上面的 v3 基础模板。目标格式版本在实现方案中确定。

```json
{
  "materials": [
    { "id": "world-background", "purpose": "background", "file": "materials/world.md" },
    { "id": "world-truth", "purpose": "author_facts", "file": "materials/truth.md" },
    { "id": "world-development", "purpose": "development", "file": "materials/development.md" },
    { "id": "contact-knowledge", "purpose": "npc_knowledge", "entity_id": "npc:contact", "file": "materials/contact-knowledge.md" },
    { "id": "contact-plan", "purpose": "npc_plan", "entity_id": "npc:contact", "file": "materials/contact-plan.md" }
  ]
}
```

| 用途 | 内容与接收范围 |
| --- | --- |
| `background` | 公开背景，根据调用用途选入 |
| `author_facts` | 作者真相，供世界主持推演；人物知识通过个人来源提供 |
| `development` | 尚未发生的发展材料，供世界主持评估 |
| `npc_knowledge` | 指定人物的初始知识；主持装配该人物材料时识别其来源与归属 |
| `npc_plan` | 指定人物本人拥有的初始计划；其他人物依据实际交流获得信息 |

材料用途由配置明确指定，不从 Markdown 标题推断。文件采用包内相对路径、明确大小限制和边界检查。相同人物的同一种初始材料选择内联或文件之一，世界背景和作者真相同样保持单一来源；多份独立发展材料可使用不同 ID。

材料内容参与 revision 校验并冻结进新存档。游玩后的计划调整写入存档，包文件仍描述初始条件。作者可填写计划与时间意向，计划标识、有效来源、下次检查时间和推进记录由运行系统维护。

## 6. 作者配置与运行时记录的边界

| 作者配置 | 运行时保存 |
| --- | --- |
| 初始位置与地图 | 当前位置与实际移动 |
| 初始状态及定义 | 当前值与变化来源 |
| 初始物品及归属 | 当前唯一归属与转移记录 |
| 初始人物知识和计划 | 获准经历、当前认知和计划调整 |
| 世界矛盾和未来材料 | 已发生事件、各接收者投影及尚未解决的发展 |
| 判定规则 | 已准备的判定参数、骰点和结算结果 |

作者提交前核对 ID 引用、地点连接、初始位置、物品归属、开场一致性及个人知情范围。修改发布内容使用新 revision；旧存档保留其冻结材料。一次新剧本接入由配置与内容完成，通用模块读取同一份合同。
