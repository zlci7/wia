## 1. 交付范围

WIA 接受不同题材的开发者剧本。玩家通过故事正文和自然语言行动进入世界，按需查看身份、现金、实际持有物品、状态、已知地点和同场人物。

本阶段复用 Story Pack v4 分类材料、ContextComposer、Turn、状态、物品、位置和现有独立世界数据库。内容编辑与导入导出保持开发者工具身份。地图采用分区地点列表；技能采用既有状态中的只读能力；资料窗口只读。

| 工作单元 | 产出 | 验收 |
| --- | --- | --- |
| U0 | HEAD、工作区、权限与真实模型授权基线 | 保留并行变更、用户存档与暂停授权 |
| U1 | 日期、币制、街区与社会生活资料 | 稳定事实 ID、出处、年代、等级及未知项 |
| U2 | 世界日期、资金表达、实例归属和玩家投影 | 数据校验、原子提交、内容修订、旧档冻结 |
| U3 | 正文优先布局与四栏目资料窗口 | 可读空间、草稿、对象、焦点、阅读位置保持 |
| U4 | 非诡秘最小文件包 | 使用相同引擎和界面完成连续性验证 |
| U5 | 全量回归、浏览器证据、CR 与本地提交 | 实际结果、未验证范围和可恢复边界 |

研究、实现与验证预算约300分钟，其中最后55分钟留给回归与收口。可选视觉范围以有用的地点列表收敛，交付以通过验证的完整工作单元为边界。

## 2. 内容与能力合同

Story Pack 保持 `schema_version: 4`；采用世界信息字段的包声明 `requires.world_info: 1`。历法、初始已知地点、状态分类或币制与能力声明对应。未知能力版本、非法数据和缺失引用在加载边界拒绝。

```json
{
  "schema_version": 4,
  "requires": {"spatial": 1, "world_info": 1},
  "calendar": {"kind": "gregorian", "era": "联合历"},
  "clock": "2189-12-31 23:55",
  "player": {"known_locations": ["service-bay", "cargo-locker"]}
}
```

以上为字段摘录；可加载完整示例见[v4 作者模板](../templates/story-pack-v4/README.md)和[维修站测试包](../../../backend/internal/content/testdata/repair-station/story.json)。正文与人物知识继续保存为受权限裁剪的材料。

v4 文件包导入、冻结、发布和导出保留原始文件。结构化工作台沿用对完整 v4 文件包的明确拒绝合同，开发者通过源文件和完整包维护这些字段。

## 3. 世界日期的数据与执行设计

### 3.1 时间事实

世界运行时间的唯一可变值为现有 `clock`，新日期内容采用严格格式 `YYYY-MM-DD HH:mm`。冻结定义保存历法与开场时间，当前时间随回合最终事务提交。列表、详情、模型材料、时间事件、另存和重启读取同一份值。

`gregorian` 采用公历式月长和闰年规则，支持0001–9999年，精度为分钟。计算环境固定为UTC，不从设备时区、现实日期或模型响应耗时推导世界时间。这个历法是WIA作者计算约定；原作完整历法仍由参考资料标注证据范围。

`plot.ClockMinute` 将绝对日期转换为从0001年1月1日00:00起的整数分钟，供计划、调度、排序和条件使用；`plot.AdvanceClock` 完成校验和推进。非法日期、负耗时、溢出或超出年份范围使候选失败。

### 3.2 计划和调度

作者文件中的 `at_minute` 仍按开场所在日00:00起算。加载新日期包时，编译器将该日午夜的绝对分钟加到冻结调度上。编译复制列表，原始文件中的偏移保持不变；导出再导入只从作者偏移重新编译一次。

初始个人计划的 `review_after_minutes` 加到开场时刻，之后的 `NextCheck`、`LastCheck` 与世界当前分钟使用同一基准。新时间事件携带实际世界日期的文字；现实 `CreatedAt` 保留审计含义。

自然语言约定依据当前世界时间解释。计划检查表示重新考虑行动的时间，事实成立仍经人物决策、协调及来源校验。长等待、场外行动与失败的时序合同保持现有Turn职责。

### 3.3 旧档与冻结

旧相对格式的冻结世界继续使用其原有纪元和修订，读取接口保持只读；玩家时间控件显示“日期未配置 · HH:mm”。当前目录的新日期、币制与初始资产只进入新建世界。

冻结定义与当前时间格式必须一致。历法缺失、未知历法、能力声明不匹配或损坏币制返回明确存储错误，保留原数据。旧存档补充年月日需要具体世界与日期映射授权，属于独立迁移工作。

## 4. 角色资料与背包

### 4.1 状态与能力

身份来自已有 `player_name`、`player_profile`。状态复用整数、布尔和枚举，并可声明 `category: condition | skill | resource`。技能说明来自作者定义，首轮职业能力采用只读布尔状态，训练和成长保持后续范围。

服务端 `PublicState` 在既有权限过滤之后提供分类、说明、币制与显示值。NPC的秘密身份、个人计划、精确关系和隐藏状态保持各自授权边界。《雾都余烬》的镜像失谐为隐藏作者状态，身体感受通过实际可见叙事体现。

真实整数0与布尔false按照类型显示。数组中没有对应状态表示缺配置，不从缺配置生成余额或能力。

### 4.2 资金

现金沿用整数状态，最低余额非负；币制采用数据配置：

```json
{
  "category": "resource",
  "currency": {
    "name": "维修积分",
    "denominations": [{"name": "积分", "units": 100}, {"name": "分", "units": 1}]
  }
}
```

面额从大到小排列，名称唯一、单位为正整数、逐级整除，末级为1。服务端从余额生成 `display_value`；引擎和前端按照数据处理，不按故事ID、状态名或币名选择逻辑。

获准模型材料包含实际值与面额换算。玩家私人钱包只进入本人和主Agent获准材料。报价与报酬承诺保持文字事实，实际收付由状态变化提交。

模型变化和规则现金变化都检查整数算术及余额范围。余额不足、超限或溢出拒绝候选；普通身体状态规则保留其已有范围行为。资金与物品变化随同一回合原子提交，技术重试使用原请求幂等边界。

完整商品目录、通用交易配对、跨国兑换、动态物价与债务账本属于后续范围。

### 4.3 物品

物品复用唯一实例、持有人或所在地点、转移来源与可见投影。背包仅收录 `holder_id == player` 的获准物品；同场NPC的可见持有物品在人物栏目展示，当前位置的场景物品在地图栏目展示。

查看物品保持只读，使用、交付或取走由自然语言进入正常回合。场景出现、报价或桌上放置本身不改变持有人。空背包、没有现金配置和读取失败保持各自实际含义。

## 5. 地点与人物资料

`player.known_locations` 声明作者授予的初始公开地点知识。服务端 `known_locations` 合并这些地点、玩家实际位置、当前位置的公共出口和必要的公共父区域；连接只指向本次投影允许查看的地点。

每条地点资料包含 `id`、`name`、公开介绍、`kind`、可用 `parent` 和过滤后的 `connections`。地区组织地点，具体地点承担移动；地图展示已知与可达事实，不触发移动。

同场人物和路人使用位置推导出的既有投影。人物栏提供公开身份、已允许的状态、可见持有物品和选择交谈对象的入口。远处人物实时位置、隐藏地点和秘密内容按来源控制。到访历史与动态知情地点账本属于后续范围。

## 6. 阅读界面

常驻区域为紧凑世界日期与地点、故事正文、行动输入和角色／背包／地图／人物四个轻量入口。辅助资料共用一个窗口切换栏目；桌面从右侧打开，窄屏接近全宽。

阅读页的时间标记为当前世界日期。消息的现实创建时间保留审计用途，存档列表的更新时间保留管理用途。

正文采用有限行宽，主要增量来自纵向阅读空间。输入区持续显示明确交谈对象，支持清除到自动判断。选择对象与表达范围分别处理，私密表达沿用自然语言意图。

窗口打开、切换、关闭及只读查看保持当前世界时钟和提交水位。草稿、对象与阅读锚点保留；Esc关闭后焦点回到资料入口。共享弹窗继续使用焦点圈定、背景滚动锁定和按世界归属处理的请求边界。

移动端适配动态视口和安全区域；短屏保持正文、输入和提交按钮可达。资料面板、错误与建议均不得造成页面横向溢出。软键盘与真实设备结论由实机验证单独记录。

## 8. 验收范围

- 日期覆盖跨日、跨月、跨年、闰年、非法值、溢出与宿主时区独立性。
- 调度覆盖开场午夜偏移、个人计划检查、源文件保留及导出再加载。
- 资金覆盖两种币制、实际零余额、缺配置、不足、溢出和幂等。
- 资产覆盖本人持有、NPC持有、场景放置、交付、非法转移与整轮失败。
- 存档覆盖发生变化后的另存、重启、副本后续独立推进与旧冻结定义。
- 知情覆盖本人钱包、隐秘状态、未知地点连接与同场人物。
- 前端覆盖类型、既有机制、正式构建、四栏目只读、草稿、对象、锚点和焦点。
- 浏览器记录1440×900、390×844、1440×600；正文尺寸与截图标注确定性fixture。

非诡秘测试包采用联合历2189年12月31日23:55、两个地点、一个工程师、100积分、两件随身物品和疲劳状态；它作为测试资料使用。真实模型游玩沿用有效授权、暂停与费用边界，未执行时明确保留待验证项。
