# 世界模拟剧本借鉴评估

日期：2026-10-06。定位：作者材料、提示设计、状态组织和内容导入的参考评估。本文的建议尚未纳入实施范围；当前交付状态以[开发状态](../开发状态.md)为准。NPC 决策的调用组织方式单独评估，本文不预设每个人物必须对应一次独立模型调用。

## 1. 评估对象与证据范围

评估对象为用户提供的《蚍蜉撼大树，可敬不自量.png》和《中世纪领主的地图填色模拟器.png》。分析依据是原文件内嵌的 JSON、世界书条目、变量规则、正则配置和扩展脚本声明。未运行扩展脚本、外部界面或真实模型；以下结论不代表已经验证其完整游玩效果。

两份文件均在 PNG 的 `tEXt` 块中存放 `chara` 和 `ccv3` 数据，Base64 解码后的 JSON 一致，声明 `spec: chara_card_v3`、`spec_version: 3.0`。CCv3 的封装方式见[格式规范](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md)。版本声明与可解析性不等同于全部字段已经通过规范校验。

| 项目 | 《蚍蜉撼大树，可敬不自量》 | 《中世纪领主的地图填色模拟器》 |
| --- | --- | --- |
| 卡片内部名称 | 星火 | ck3模拟器 |
| 世界书条目 | 18 条，16 条启用 | 83 条，76 条启用 |
| 启用条目的调用配置 | 16 条均标为常驻 | 6 条常驻，70 条带关键词 |
| 启用世界书原始内容 | 30,872 个字符 | 23,395 个字符 |
| 开场原始内容 | 1,510 个字符 | 1,497 个字符 |
| 正则配置 | 6 条，均启用 | 2 条，均启用 |
| 助手脚本 | 变量更新器与内嵌变量结构声明 | 变量更新器与外部变量结构声明 |
| 界面实现线索 | 内嵌 HTML 状态栏与美化配置 | 通过外部地址加载界面 |

字符数包含标记和规则文本，是静态统计，不代表实际发送 token、费用或上下文长度。常驻与关键词配置的实际效果还受客户端、预算和其他设置影响。

两份卡片的主要剧本内容都位于 `character_book.entries[].content`，常规人物描述很少。卡片名称代表世界模拟入口，不能据此创建一名同名 NPC。背景和规则以 JSON 字符串保存，内部混合自然语言、缩进式结构和标签，并未独立保存为 Markdown 文件。

## 2. 借鉴判断

| 判断 | 含义 |
| --- | --- |
| 优先借鉴 | 能直接改善作者材料或当前体验，适合优先选择 |
| 改造借鉴 | 保留设计意图，调整数据、权限或执行方式 |
| 保持并完善 | WIA 已有对应机制，重点是内容质量与验证 |
| 后续评估 | 需要新增产品能力或超出当前范围 |

题材里的教会、封建阶层、领地等级、死亡规则与传承制度属于具体剧本。可复用的是描述方法和信息结构，通用引擎的规则由当前[架构方案](../../summary/ARCHITECTURE.md)与[总体技术方案](../../summary/总体技术方案.md)定义。

## 3. 文件与作者材料组织

### 01. 封面与内容作为同一份可分发作品

**来源设计。** PNG 同时承担封面和剧本载体，作者分享一个文件即可传递作品。

**判断：改造借鉴。** WIA 的正式格式继续使用 Story Pack v4；作品封面、名称、简介和剧本文件随同一份包分发。PNG 角色卡可作为未来的外部导入格式候选，提取内容后转换为 v4 草稿。当前尚未实现这类 PNG 内嵌卡解析。

**采用方式。** 保留封面作为资源，展示解析出的作品摘要、内容数量和转换限制。封装形式不决定运行权限；图片中的脚本、宏和外部页面需要分别识别。

### 02. 明确格式版本与作品版本

**来源设计。** 卡片区分格式版本、作品名称和作品版本；第二份卡片声明了自己的作品版本。

**判断：保持并完善。** 对应 v4 的 `schema_version`、`game_id` 与 `revision`。格式升级和内容修订分别处理，已建立的存档继续使用冻结定义。

**采用方式。** 作者模板解释三者用途；导入报告记录识别出的格式与版本。字段缺失、拼写变体和扩展依赖应形成具体报告，不能仅凭版本标签宣称完整兼容。

### 03. 用专题材料替代一整块世界描述

**来源设计。** 第一份按制度、社会、人物、知识和事件拆分；第二份进一步按地区拆分。

**判断：优先借鉴。** 对应 `materials.json` 与分类 Markdown。每份材料处理一个明确主题，提供摘要、用途与关联对象。

**采用方式。** 世界背景、运行常识、作者事实、发展压力、人物资料和地域风俗分别编写。章节之间用明确引用保持联系，减少重复定义同一条规则。

### 04. 核心材料与局部细节分层

**来源设计。** 第二份用少量常驻规则搭配大量关键词地域条目，避免将所有地点说明都作为常驻候选。

**判断：改造借鉴。** 常驻内容保留时代、当前身份和必要约束；细节使用现有按需材料读取。相关性由当前地点、参与人物、行动对象和调用用途共同判断。

**采用方式。** 关键词可以作为内容检索的辅助线索，人物许可仍按材料可见范围判断。名字出现在对话中，并不自动授予该人物全部秘密。

### 05. 作者备注与运行材料分开

**来源设计。** 卡片具备作者备注、版本和扩展元数据，运行规则则集中在世界书。

**判断：保持并完善。** 作者说明用于创作、导入和维护；时代事实、人物知识与发展材料进入对应运行用途。

**采用方式。** 作者模板分别说明“作品使用说明”和“模型需要理解的世界内容”。依赖说明、来源信息与兼容性限制不混入 NPC 的知识。

## 4. 世界、空间与经济

### 06. 时代、技术、基调和当前局势共同定义世界

**来源设计。** 两份卡片同时描述技术边界、社会制度、日常生活与叙事基调，第一份还明确制度矛盾的形成条件。

**判断：优先借鉴。** 作者材料应回答：世界处于什么时代，普通人能做什么，当前哪些事情正在改变，作品偏向什么表达。

**采用方式。** 基调指导表达和关注点；具体成败由行动和世界结果决定。第一份关于反抗的主题可以保留为创作方向，其预设的个人成败不作为 WIA 通用结果规则。

### 07. 机构有职责、资源与内部差异

**来源设计。** 第一份将机构拆成层级、经济来源、执行方式、与其他权力的关系及内部派系。

**判断：优先借鉴。** 机构材料提供具体的运转逻辑，让人物行动有现实条件。

**采用方式。** 说明机构控制什么、依赖什么、谁负责执行、内部有哪些不同利益。同一机构的成员可以立场不同，人物行为由本人处境与事件支持。

### 08. 社会身份影响机会、能力和接触范围

**来源设计。** 身份关联教育、技能、资源、权利和日常能接触的人物，高层人物需要有具体出现原因。

**判断：改造借鉴。** 身份提供初始生活条件与社会阻力，人物仍可通过实际经历学习和改变。

**采用方式。** 作者资料解释常见机会、限制和可能的改变渠道。能力限制以经历和条件表达，避免用出身标签永久否定玩家的学习与探索。

### 09. 地方差异提供可行动的内容

**来源设计。** 第二份地域条目包含风俗、食物、作物、建筑、资源与交通线索，地点有具体生活质感。

**判断：优先借鉴。** 对应地域材料与现有地点定义。

**采用方式。** 为已声明地点补充“这里能做什么、谁常来、有什么资源、何时热闹”。地图结构与移动连接使用结构化定义，文化说明作为材料；文案提到某地不等于已建立可移动节点。

### 10. 地理层级与实际控制分别描述

**来源设计。** 第二份区分头衔、称呼、法理归属和实际领主行为，制度上的归属与居民的接受程度可以不同。

**判断：改造借鉴。** 当前先将这类差异写入制度、地域和发展材料。完整领地控制、封臣和头衔继承需要另行评估。

**采用方式。** 涉及统治权争议时，区分法定身份、实际控制、公众说法和人物判断。身份名称不能自动替代有来源的控制权变化。

### 11. 世界时间作为明确状态

**来源设计。** 第二份初始化了完整年月日时分；第一份使用纪年描述与季节，关注时间对环境的影响。

**判断：保持并完善。** WIA 的界面与运行时间使用剧本配置的年月日时分。纪年名称和季节可丰富背景，但不能替代明确时间。

**采用方式。** 开局、约定、行动耗时与事件记录对应同一份世界时间。季节关联天气、营业、劳作和资源情况；需要确定性结算的周期另有明确规则，不从氛围文字中猜测。

### 12. 经济资料先提供尺度和生活条件

**来源设计。** 第二份给出币制、职业收入、产业收益、物价和维护费，帮助生成有尺度的经济叙事。

**判断：改造借鉴。** 当前优先补齐剧本自己的币制、实际开局现金、常见服务与物品的价格参考。

**采用方式。** 参考价格用于理解交易条件，实际成交形成明确现金与物品结果。原卡的收入、税率和兵种费用属于该剧本，不写入通用引擎。报价、预算与已支付金额分别表达。

### 13. 势力关系有类型与实际事件

**来源设计。** 第二份描述领主、封臣、邻国、战争状态和态度，第一份强调不同地区制度压力的差异。

**判断：改造借鉴。** 可先作为作者事实、发展材料和人物已知信息使用。

**采用方式。** 正式身份关系、公开冲突状态与个人态度分别描述。玩家资料显示本人获知的内容，精确信任值和隐藏动机遵守现有投影边界。完整战争与势力经营属于后续能力候选。

## 5. 玩家与人物

### 14. 角色资料呈现一个完整的人

**来源设计。** 第一份将身份、身体、技能、资源、认知和关系共同描述，技能多用具体经验表达。

**判断：优先借鉴。** 对应角色资料、背包和人物信息的内容完整性。

**采用方式。** 身份与能力由剧本资料提供；身体、现金、物品和已确认变化使用真实状态。没有动态机制支持的技能成长先作为作者材料，不把预留栏目填成虚构进度条。

### 15. 初始示例与当前状态明确区分

**来源设计。** 第一份明确要求读取当前变量，人物生成规则和示例不代表正在游玩的角色。

**判断：保持并完善。** 模板、初始定义和当前存档分别承担不同职责。

**采用方式。** 当前事实优先于初始示例。开场的现金、位置、伤势和物品在实际变化后不能被初始描述覆盖。作者例子标明参考用途，避免误当作玩家已获得的能力或资源。

### 16. 能力成长需要条件与经历

**来源设计。** 第一份把技能与教育、实践时间、工具和可接触的人联系起来。

**判断：改造借鉴。** 可先改善人物资料和叙事尺度；正式学习、熟练度与长期成长系统另行评估。

**采用方式。** 区分尝试、学习机会和已获得能力。一次看见操作可以留下印象，不能自动认定掌握专业技能。能力变化应有具体经历支持。

### 17. NPC 有自己的生活与出现原因

**来源设计。** 第一份要求 NPC 在玩家到来前就有生活，出场与当前地点和事件相符，离开玩家后仍有自己的事务。

**判断：优先借鉴。** 对应已定义人物的身份材料、当前位置和当前计划。

**采用方式。** 作者说明人物为什么在这里、正在做什么、需要什么。场外延续按现有有界调度处理。动态创建重要人物、路人提升和无限后台模拟不包含在这项材料改进中。

### 18. 动机分层，允许与玩家无关

**来源设计。** 第一份区分眼前关切、长期愿望和隐藏动机，允许部分人物只有其中一层。

**判断：优先借鉴。** 对应人物资料、初始计划和当前计划。

**采用方式。** 先提供当下最迫切的事情，再按人物需要补充长期与私密内容。人物可以配合、拒绝、拖延、误判或忙于自己的事；不要为所有角色强行配置一个秘密。

### 19. NPC 之间的关系在玩家之外成立

**来源设计。** 第一份明确人物之间有地理、身份和历史交往形成的关系网，玩家行为可以间接改变它。

**判断：优先借鉴。** 作者提供既有关系和互动依据；关系变化沿用当前事件与关系机制。

**采用方式。** 为相关人物说明利益、旧经历和日常接触。多人对话可以包含对彼此的回应和分歧，人物收到相应发言或结果后才有新的判断依据。

### 20. 态度与性格变化有具体触发

**来源设计。** 第一份区分渐变、重大事件后的转变和长期经历带来的退缩，第二份要求相对稳定的性格材料少量更新。

**判断：优先借鉴。** 稳定性格用于形成行为倾向，具体态度随有来源的经历变化。

**采用方式。** 写明人物在什么条件下愿意合作、什么会让他重新判断。一次好话不自动形成深度信任；一次变化也不要求从此保持相同强度。反应差异来自身份、利益和经历。

### 21. 人物判断允许不确定与错误

**来源设计。** 第一份允许 NPC 根据言行推断玩家，判断可能错误；转述也可能与原事实不同。

**判断：优先借鉴。** 材料区分亲见、转述、推测和未知。

**采用方式。** 对话用人物真正掌握的证据表达确信程度。猜测可以影响行为，但猜测不自动成为权威世界事实。后续新证据可以改变判断。

### 22. 信息来源、传播渠道和接收者共同决定知情

**来源设计。** 第一份明确亲身经历、目击、转述、传闻及时间衰减，世界各地的人不会自动知道同一件事。

**判断：保持并完善。** 对应现有材料可见性、个人感知、记忆与来源引用。

**采用方式。** 人物资料写清初始已知、消息渠道和盲区；当前互动按实际听众授予来源。无论 NPC 决策采用什么调用组织方式，身份与个人知识记录仍可按人物分别保存。统一提示中的人物分区只能提供行为引导，不能等同于模型从未接触其他分区。

## 6. 持续世界、风险与节奏

### 23. 世界变化从已有矛盾产生

**来源设计。** 第一份把事件视为当前制度、资源、人物处境与环境共同作用的结果，避免从固定类型清单机械挑选。

**判断：优先借鉴。** 对应 v4 的发展材料与现有持续世界阶段。

**采用方式。** 材料分别写明当前事实、压力、可能变化和接触渠道。创作新局势时保持因果支持，生成压力、机会、障碍和环境变化，具体结果留给参与者行动与结算。

### 24. 世界变化有多种方向，日常可以成立

**来源设计。** 第一份允许压力减轻、机会出现或消失、中性变化与安静日常；玩家不行动不会自动受到惩罚。

**判断：优先借鉴。** 对应世界与正文提示的正向创作目标。

**采用方式。** 普通交谈和检查可以自然收束。改变源自实际条件与所有参与者的行为，等待可能有效、可能错过机会，也可能没有明显结果。世界自发行动不要求每次都针对玩家。

### 25. 事件密度与玩家行动相协调

**来源设计。** 第一份要求事件之间有日常，玩家主动行动时减少外部打断。

**判断：优先借鉴。** 可以先改善现有发展材料与主持提示的节奏判断。

**采用方式。** 玩家意图正在得到处理时优先完成这段互动；连续高压之后允许平静。外部变化的频率和规模与情境相符。不要为每轮增加固定的规划调用或强制事件配额。

### 26. 大事件有演变过程，阶段不是固定分支

**来源设计。** 第一份以迹象、积累、公开化、传播和收束描述历史转折，参与者可改变其发生时间和方向。

**判断：改造借鉴。** 可作为开放发展事项的作者写法。

**采用方式。** 描述当前演变条件、可观察迹象和可能影响。事件可以延期、被阻止、部分发生或改变方向；阶段用于理解世界过程，不自动建立必须逐项完成的剧情节点。

### 27. 世界改变会影响后续生活条件

**来源设计。** 第一份将技术、人口、制度和消息传播的变化关联到人物的机会、技能与生活。

**判断：改造借鉴。** 当前先让已确认变化影响后续作者材料理解与人物感知。

**采用方式。** 写具体发生了什么、影响哪些人、哪些地区仍不同。不要用一句全局概括替代有来源的局部变化。跨年代模拟、新身份池与全局科技系统属于后续评估。

### 28. 后果具有持续性与传播条件

**来源设计。** 第一份的遗产包含直接成果、间接影响和负面后果，信息可能变成传说，也可能丢失。

**判断：改造借鉴。** 借鉴后果持续性的表达，沿用事件、记忆、当前计划和未解决事项。

**采用方式。** 影响通过具体的人、物品、记录和消息渠道延续；保存事实与人物听到的版本分别处理。事实记录保持可追溯，人物记忆的模糊或转述变化不覆盖原事实。暂不新增平行的“遗产数据库”。

### 29. 风险依据处境，变化有过程

**来源设计。** 第一份关注伤病、资源不足、日常危险和长期积累，要求后果符合行为与环境。

**判断：改造借鉴。** 可改善身体状态材料与结果描述，具体风险规则由剧本声明。

**采用方式。** 区分风险迹象、实际受伤与长期影响，状态由真实结果更新。公平性是因果一致和可理解的反馈；原卡的永久死亡、不可撤销和特定寿命限制不作为 WIA 通用规则。

### 30. 跨代继续与人物生命周期

**来源设计。** 第一份允许新主角在未来继续同一世界，旧人物会衰老或离世，前代关系不会完整转移给新身份。

**判断：后续评估。** 当前可以吸收“世界影响留存”“新人物不自动继承他人知识”的原则。主角更替、跨度模拟、继承与死亡存档规则是独立产品能力。

**采用方式。** 若后续立项，需要明确新主角身份、世界时间、存档所有权、旧人物状态和可接触的遗留信息。人物不再活动时保留历史身份与事件引用，不能通过删除记录破坏既有来源。

## 7. 状态、校验与展示

### 31. 初始值与类型共同约束状态

**来源设计。** 两份卡片都有初始化条目、更新规则和结构声明，第一份部分结构在文件中，第二份依赖外部结构脚本。

**判断：保持并完善。** 使用当前状态与物品定义表达已支持的类型，作者材料说明复杂语义。

**采用方式。** 区分有配置的初始值、尚未填写的创作草稿和运行时未知信息。默认值只用于明确允许的初始化，不用“待初始化”或零值伪装实际现金、能力与人物关系。不能只凭字段类型合法认定变化有因果依据。

### 32. 每个字段有更新依据和负责方

**来源设计。** 第二份对时间、金币、位置、产业和亲信分别说明更新条件，还将部分收益字段标为只读。

**判断：优先借鉴。** 作者说明字段含义，程序依据现有机制限定变化来源。

**采用方式。** 区分模型可提议的状态、确定性规则负责的数值、由位置或物品推导的结果，以及仅用于显示的资料。新增重要状态需要同时明确依据、可更新方式和玩家可见范围。

### 33. 增量变化与派生结果分别处理

**来源设计。** 卡片要求以增量表达部分收支，同时保留总余额和派生收益；输出协议借用了类似补丁的形式，并包含自定义操作。

**判断：改造借鉴。** WIA 保留自己的变化合同与原子提交，借鉴明确增量、依据和执行顺序的表达。

**采用方式。** 同一交易分别记录成交、现金变化和物品变化，重复处理不能重复扣款。派生字段从权威来源计算，模型不能直接写入。自定义 `delta` 等操作不能直接按标准 JSON Patch 执行。月度收益、负债、产业和军队结算尚需独立定义与验证。

### 34. 模型读取状态，界面展示投影

**来源设计。** 两份卡片通过变量宏向模型提供当前状态，再用正则隐藏、美化部分输出；第一份还裁剪旧楼层变量更新。

**判断：改造借鉴。** 借鉴“当前状态单独提供、展示文本保持简洁”的目标。

**采用方式。** 当前模型请求使用结构化状态与获准材料，界面使用服务端投影。正文中的状态栏 HTML、被正则隐藏的文字和聊天楼层都不成为权威状态来源。缩减重复内容时保留必要来源与个人记忆。

### 35. 资料按需查看，展示完整但有边界

**来源设计。** 第一份聚合角色、世界与历史信息；第二份将领地与经营信息组织成独立界面。

**判断：改造借鉴。** 沿用已选定的阅读主界面与按需资料窗口，吸收信息组织和分类方式。

**采用方式。** 玩家可查身体、能力资料、实际资源、位置和已知人物；世界或地图资料按本人知识投影。资料窗口不公开所有 NPC 的隐藏动机与精确态度，也不因查看而推进时间。外部卡片的 HTML 和脚本不直接替换正式前端。

### 36. 导入报告声明依赖与缺失能力

**来源设计。** 两张 PNG 除文本外，还依赖变量更新器、结构脚本和界面资源。第二份的 PNG 中没有完整远端界面源码。

**判断：后续评估。** 外部卡片兼容需要内容提取、映射和具体兼容报告。

**采用方式。** 报告区分可解析文本、可映射结构、未支持机制和外部依赖。作者修订映射后，使用同一 v4 加载与校验入口。当前已有角色卡 JSON 导入限定 CCv2 的有限映射，世界书与扩展不会自动转换成运行能力；不能把本次读取两个文件记成产品已经支持 PNG 或 CCv3。

## 8. 作者材料与提示参考

以下示例为重新编写的通用草案，供作者材料和后续业务提示调整参考，尚未接入运行。具体调用的输入、输出与强制校验以现有业务合同为准。示例不要求输出模型内部推理过程。

### 8.1 人物作者资料

```text
身份与生活条件：说明职业、经历、能力、资源与日常接触范围。
当前处境：说明所在地、正在做的事与眼前压力。
当前关切：写最迫切的问题；需要时补充长期愿望与私密动机。
已有关系：说明与相关人物的交往事实、利益与冲突。
个人知识：分别写亲见、转述、推测和未知，注明来源。
表达习惯：使用具体用词、句式与称呼示例。
变化条件：说明什么经历可能改变判断，保留选择空间。
```

### 8.2 世界发展材料

```text
当前事实：哪些事情已经发生，哪些结果已经确定。
当前压力：哪些资源、制度、环境或关系正在积累变化。
合理发展：当前条件可能带来的压力、机会、中性变化和日常。
参与者：相关人物各自有什么利益与可行动条件。
可观察迹象：玩家和人物能通过什么实际渠道接触变化。
结果空间：允许缓解、延期、失败、部分解决或改变方向。
```

### 8.3 人物决策提示目标

```text
依据该人物提供的身份、当前状态、个人知识与本次获知信息作决定。
决定服务于人物自己的处境与关切，可以合作、拒绝、误判或保持沉默。
对事实、转述与推测保持相应的确信程度。
相关变化用本次实际提供的来源支持，表达具体的台词和行动意图。
多人决定按人物分别输出，保留个人听众、依据与状态变化的归属。
```

### 8.4 世界主持提示目标

```text
处理玩家当前意图，并依据当前事实和发展材料组织合理情境。
外部变化与已有压力、机会和参与者行动相符，日常和平静结束同样有效。
玩家正在处理自己的事情时，外部变化的密度与规模适度。
把可感知变化交给实际接触者，保留未获知者的信息边界。
物品、位置、时间与状态变化形成对应结果，沿用本次明确的结算合同。
```

### 8.5 正文提示目标

```text
围绕玩家可知的情境和已确认结果形成自然连续的一段互动。
突出关键对白、人物差异、具体后果与下一步可行动的空间。
表现性衔接保留已经确定的台词含义、决定和听众范围。
叙述关注玩家能够感知的内容，未公开的动机保留在对应个人材料中。
普通互动可以简洁，重要变化再展开，按场景自然收束。
```

## 9. 实现对应与选择范围

| 借鉴内容 | 现有对应入口 | 选择范围 |
| --- | --- | --- |
| 材料分层与权限 | Story Pack v4、`materials.json`、ContextComposer | 优先完善作者材料与读取质量 |
| 当前状态覆盖初始例子 | 冻结定义、世界快照、当前人物计划 | 检查来源与当前状态表达 |
| 人物生活、动机、关系、知识 | 人物定义、个人感知、记忆、计划与关系 | 优先完善人物材料与互动质量 |
| 因果发展与事件节奏 | 发展事项、持续世界与正文阶段 | 优先完善内容与提示 |
| 日期、现金、物品与资料 | 世界时间、状态、物品与玩家投影 | 完善真实信息与一致性 |
| 地域文化与探索机会 | 地点定义、地域材料与已知地图 | 补充已声明地点的可行动细节 |
| PNG/CCv3 输入 | 内容导入 | 新能力候选，尚未实现 |
| 动态重要人物、技能成长、产业战争 | 无完整对应交付 | 独立范围评估 |
| 主角更替与跨年代世界 | 无对应交付 | 独立产品评估 |

优先选择材料层的改进：当前事实与发展范围分开、人物动机和已有关系具体化、知识来源清晰、地域资料可行动、世界变化允许多种方向。它们不要求扩建一套运行引擎。

已有机制的改善需要实际体验验证。动态人物创建、完整经济经营、永久死亡与跨代继续不能因参考卡片存在而自动进入产品范围。

## 10. 评估与验收场景

| 场景 | 需要观察的结果 |
| --- | --- |
| 玩家更新了现金、位置或物品后继续游玩 | 当前状态保持，初始例子不回填覆盖 |
| 同一事件影响两名利益不同的人物 | 反应有区别，来源与个人处境相符 |
| 两人私聊，第三人同场 | 第三人没有获得私聊原话与秘密；公开后果按可观察范围处理 |
| 一人转述未证实消息 | 听众获得转述与不确定性，权威事实不被改写 |
| 玩家等待或进行日常交谈 | 世界可以变化，也可以平静结束，不机械增加负面事件 |
| 玩家离开后再返回 | 有来源的计划与后果延续，已完成事项保持完成 |
| 到达不同已知地点 | 场景呈现与当地文化、资源和人物有关的具体机会 |
| 同一交易被重复请求 | 现金、物品和记录保持一次有效结算 |
| 资料与地图按需打开 | 显示实际、获准的信息，正文位置、输入草稿与世界时间保持 |
| 评估外部卡片导入 | 报告文本映射、缺失机制和外部依赖，产品支持状态表述准确 |

确定性校验用于验证状态、权限、来源和提交机制；人物自然度、多人对话质量、世界节奏与长程连续性需要真实模型和实际游玩单独验证。
