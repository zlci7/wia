# 渐进材料与持续世界技术方案

状态：待 CR 的实施方案，运行时能力尚未实现。作者配置合同见[开发者剧本编写规范与模板](开发者剧本编写规范与模板.md)；模块职责与依赖规则见[架构方案](../../ARCHITECTURE.md)。

## 1. 交付范围

按两个完整模块实施，各完成工程验证、内部 CR、一次本地 Git 提交和一次用户 CR。模块内的实现步骤不设置人工审批。

| 顺序 | 模块 | 用户可见结果 |
| --- | --- | --- |
| 1 | 世界推进 | 分目录剧本材料按需提供；人物根据本人计划与游戏时间行动；世界推进读取最新事实；《雾都余烬》提供新修订 |
| 2 | 个人感知 | 一次输入支持不同交谈范围与行动顺序；NPC 能私密回复；同一事实按个人观察形成不同感知；纠正保护已消费的来源 |

范围包含 Story Pack v4 文件格式与引用加载，保留当前状态、关系、物品和固定判定能力。旧存档继续读取冻结内容。通用玩家/NPC 风险判定后续单独交付；本轮保留既有固定判定。

## 3. 世界推进模块

### 3.1 文件加载与冻结

采用编写规范中的 v4 格式。`content.Load` 读取入口、结构化数据、材料索引、各人物及被引用正文，编译为冻结运行定义。

加载要求：

- 文件路径使用包内相对路径，沿用现有真实路径边界校验；允许在包内分类目录和人物子目录中引用。
- JSON 保持严格字段、重复键与类型校验；Markdown 为合法 UTF-8，读取为文本数据。
- 材料 ID 唯一；purpose、visibility、delivery 有限枚举；owner、地点、人物、物品关联引用已定义对象。region 关联同时覆盖其下属 place，按已有地图层级展开。
- `npc_profile`、`npc_knowledge`、`npc_plan` 为 owner 材料；计划所有者与材料 owner 一致。作者真相和发展材料使用 author 权限。
- 一份材料的 `file` 与 `text` 互斥。结构化模块文件与启用能力一致，沿用既有能力校验。
- 初始工程上限为 128 份材料、单份正文 64 KiB、正文合计 1 MiB；summary 最多 256 个 Unicode 字符，基础正文最多 800 个字符。相同文件可被不同主题引用，但总量按逻辑材料计入。

v4 digest 覆盖入口、所有引用 JSON、材料正文及已有资源，按确定路径顺序计算；v1/v2/v3 digest 合同保持。相同 revision 的正文变更须拒绝发布，使用新 revision。

新世界保存材料元数据与全文，正常 Turn 只读世界冻结定义。另存、重启、原始包移走后仍可完整游玩。导入、导出和发布保留全部引用内容。现有结构化草稿若不能表达 v4 文件材料，明确拒绝该格式的编辑保存，不将材料静默丢弃；本轮不增加可视化材料编辑器。

### 3.2 用途与知情范围

材料用途描述内容类型；模型调用用途描述执行职责。二者由系统映射，不接受作者任意指定模型调用权限。

| 调用 | 可选入内容 |
| --- | --- |
| 玩家意图 | 精简公开背景、玩家自己的资料、当前情境和可操作对象；理解表达所需的相关信息 |
| NPC 决策 | 公开背景、本人资料、本人知识和计划、本人获准经历及可知的当前事实 |
| 行动协调 | 涉及对象的规则、作者真相、本人已提交决定和最新能力工作态 |
| 世界推进 | 相关冲突、作者真相、外部安排、最新事实；本人计划仍由对应 NPC 决定 |
| 玩家正文 | 玩家获准事件、当前可感知事实和相关公开背景 |
| 摘要与建议 | 对应接收者已有获准来源；保持现有边界 |

所有索引、摘要和正文执行同一权限判断。public 表示可公开，不表示每个 NPC 已经知道整份档案；精简社会常识可直接使用，详细资料须有初始知识、当前观察或实际传达的来源。材料补充请求也执行这项知情检查，读取本身不补造获取经历。作者层能够使用真实规则裁定后果，不把规则全文交给尚未知晓的角色。人物材料只填写本人有概念的线索和疑问；“尚不知道某个隐藏身份”同样会提示该身份存在，应留在作者层的信息分布中。

### 3.3 渐进读取合同

在调用材料构造中形成 `MaterialSelection`：用途、接收者、当前版本、选入 ID、正文、来源以及省略/受限情况。精简基础材料常驻对应用途；按当前地点、对象 ID、本人计划和已确认变化选入相关材料。可选索引同样受数量与预算限制。

材料来源使用运行系统生成的 `material:<definition_revision>:<material_id>`，只接受当前世界冻结且本次实际提供的材料。人物初始知识标注开场基准，当前经历与观察保持时间来源；初始计划只用于初始化，正常决策读取存档中的当前计划，避免取消或调整后的计划被旧文件恢复。

首次装配优先使用精确关联和短文本匹配。模型可以在尚未形成最终候选前返回类型化的 `needs_material` 请求，字段为获准目录中的材料 ID。运行系统读取冻结正文后，继续同一用途。模型不能提供文件路径、网络地址或查询命令。

初始上限：每个用途最多一次补充请求、最多 4 份材料；整轮最多 2 次补充请求。基础装配、补充材料、来源说明、系统提示、历史、推理和输出预留共享现有预算，不提高当前 12000 输入 token 上限。日志和构建报告记录选入/省略 ID、受限原因与容量。

同 Stage 的并行人物请求汇合后按稳定 entity ID 分配读取额度，额度用尽返回明确受限信息；不由模型返回的先后顺序决定谁获得材料。

材料请求是读取动作，不产生人物决定，不写事件、记忆或计划。每个 NPC 在同一 Stage 只形成一个最终决定；本轮已确定的决定不因补充材料再生成。JSON 修复保持现有有界合同，不因材料请求重新获得无限修复次数。

补充完成后读取仍不足时，模型可以形成有依据的暂缓或不执行结果；必需事实缺失、未知材料、越权请求和必需输入超限产生明确错误。失败整轮不提交，玩家输入保留。静态阅读不自动成为人物经历；只有观察、交流和实际认识形成个人记录。

可选材料按相关性选取并整份省略。涉及移动、物品转移、关系或状态判断时，相关当前值、定义和因果来源为必需材料。最新物品归属与状态不得被作者初始描述覆盖。已知来源的查询与材料读取有相同世界、阶段及版本约束。

### 3.4 持续发展和人物计划

作者配置三种内容：

| 内容 | 含义 | 推进方式 |
| --- | --- | --- |
| development | 尚未解决的矛盾、压力与可能发展 | 相关情境出现时由世界推进评估 |
| NPC plan | 本人依据知识形成的行动意向 | 到期或收到本人新刺激时由本人重估 |
| external schedule | 作者确定的外部事实，例如天气或公开营业安排 | 到期提供外部变化，人物应对仍由本人决定 |

计划运行记录包含稳定 ID、owner、当前自然语言计划、依据来源、下次检查分钟、最近检查依据及 active/paused/completed/cancelled 状态。NPC 决策输出自己的计划调整；世界主持不能替其接受、执行或完成计划。程序检查身份、来源、时间和状态合同，模型理解具体行动语义。

到期选择只依据游戏时间、本人计划及本人获准刺激，不依据其尚不知道的作者秘密。待检查时间不等于预定成功时间。银镜不在原地时，人物可依据到场观察重估调查，不因某个 `item_at` 判断失败便永久消失。

推进在已有回合内执行，使用最新工作态。每轮保持一个有界世界推进轮次，最多唤醒 2 名到期/受刺激人物；其余按到期时间与稳定 ID 留待后续轮次。人物在不同 Stage 再决定时，必须先获得前阶段获准结果。重复检查同一依据不重复提交变化，下一次检查安排不能形成同轮循环。

明确等待推进游戏内时间；无玩家回合时不启动后台持续模拟。移动按实际路线与消耗时间结算，计划检查不将人物瞬间传送到目的地。新开放定义和旧节点定义在同一个推进入口按冻结格式执行，共用人物决定、结果协调与提交路径；本轮不转换旧计划或旧事件记录。

### 3.5 现有路径收口

以下问题与世界推进直接相关，纳入同一模块：

- 世界事件评估读取相关对象的最新能力工作态，包含当前物品归属，记录因果来源。
- 只有关系或计划提案、没有非言语行动的 NPC 决定也正常应用；能力变化不依赖 `len(allowed) > 0` 才执行。
- 场外结果的写入使用完整冻结背景人物目录，实际见证资格仍逐结果校验。
- 非空间世界收到结构化 movements 时明确拒绝，不静默忽略。
- 私密玩家结果的所有输出通道执行相同接收范围检查，包括 bystanders。模块 2 的完整投影接入前，私密结果只写入获准接收者。
- 计划依据受 epoch 与来源有效性约束；无效来源不继续推动计划，沿用已有纠正和重建机制恢复。

### 3.6 《雾都余烬》新修订

内容草案见[分类材料目录](../templates/mist-embers-materials/README.md)。正式包新修订目标为 `mist-embers.pack.v5`、格式 v4，交付时保持既有 game、地点、人物和物品实例 ID。当前正式包 `mist-embers.pack.v4` 使用格式 v3，实施前保持原样。

新修订将公开世界背景、作者真相、异常规则、人物知识与计划分别编写；正文和公开地图不暴露隐藏地点内部线索、人物任务或银镜作用。委托窗口变为现实压力材料，银镜回收变为亚瑟本人计划。新修订不使用前置节点顺序或物品条件表达这两项人物计划。

原作参考用于世界氛围与规则依据，现有四名人物、失踪案、具体街道设施和裂纹银镜为剧本内容。`3-917` 为同人档案编号，未经核实不声称是原作正式物品或确定原作评级。当前示例地图、状态、物品、关系和潜入固定判定保持有限范围。

时代采用第一部结束之后、愚者教会已经存在的同人分支。具体开场日期留在内容合同中确认；《宿命之环》后期的教会格局、人物能力和技术变化按原作时间整理，不回填为较早开场的事实。教会存在与当地普通人的知情程度分别表达。

## 4. 个人感知模块

### 4.1 混合输入与人物回复

完整输入始终保留。意图产出少量有序片段，每片段带原文范围、行动者、交谈对象、交谈范围与顺序。只在交谈范围、对象或影响观察资格的位置发生变化时拆分，不将每个修饰词拆成独立行动。

“告诉记者一个秘密，然后离开”分别形成私密交流和可观察移动。重要人物根据实际获得的片段决定，未经获准的秘密不进入他人的决策材料。NPC 回复声明公开或指定私密对象，由本人选择；程序检查接收者和实际可接触条件。对白范围在 speech 合同中表达，`action_intent` 保持非言语行动用途。

### 4.2 作者结果与个人投影

每个行动保留一份作者层结果，结构化状态、物品、关系和位置变化引用该结果。接收者各有独立 projection 内容与来源；玩家正文仅使用 player projection。

投影根据行动发生时的位置、交流范围和有效来源决定。公开离开可以被同场者观察，此前耳语只归私密双方；抵达者不能获知抵达前的交谈。同一结果允许人物看到不同部分，作者完整内容不自动复制给 recipients 或背景人物。

场内行动、场外行动、世界事件和背景人物互动使用同一投影合同。背景人物保留稳定身份与获准经历，重要人物的新决定仍来自本人。关系和状态变化引用获准经历，不能用根结果替代未经传达的知识。

### 4.3 纠正保护

保护按受影响的来源依赖执行，覆盖 event、perception 及相关派生记录。被当前位置、状态、物品、已消费关系提案、判定或当前计划使用的来源，必须保持当前事实一致。

支持事实重建前，对会使既有结构化事实失去依据的追溯纠正明确拒绝。人物现在改变态度或发现旧认识有误，可以作为新的获准经历正常推进；这与追溯改写已消费的历史来源分别处理。普通文字纠正沿用现有记忆恢复流程。

## 5. 工程与真实环境验收

### CR-世界推进

- v4 引用文件、UTF-8、路径边界、重复材料、能力引用与 digest 校验；同 revision 改正文拒绝。
- 未关联的长背景和物品不进入请求；owner/author 索引与正文均不进入越权接收者；材料请求上限和总输入预算可测。
- 物品已移走、持有人在原场景、状态已变化时，世界推进读取最新事实；不规定模型必须作出哪种选择。
- 计划到期、私人线索、暂缓、重新安排及重复检查；关系提案无行动时仍保存；场外实际背景见证人可写入。
- 私密玩家结果不能经 bystanders 泄漏；未启用空间能力时拒绝 movements。
- 无材料读取时的普通回合、v1/v2/v3 冻结世界继续读取；另存、重启、原始包移走后材料和计划仍可用。

### CR-个人感知

- 一次输入中的私密交流与公开离开分别保存，完整原话和合法顺序保持。
- NPC 公开/私密回应、背景人物、离开前和抵达后的观察范围；投影允许省略秘密，不复制作者层全文。
- 场内和场外统一投影，玩家正文只使用 player 来源；物品、状态、关系及有序来源仍原子保存。
- event/perception 纠正不会使已消费事实失去依据；普通纠正与后来的认知改变保持可用。

每个模块运行 `go test ./... -count=1`、受影响包 race、`go vet ./...`、`go build ./...` 与 `git diff --check`。前端有改动时运行类型检查、机制测试和正式构建。确定性测试验证合同，不断言固定故事路线。

真实模型使用独立存档贯穿同一场景：玩家私聊后离开，人物依据自己的知识和计划调查已经变化的诊所，然后另存、重启继续。模块 1 验证到期计划、最新事实、独立人物决定和既有私密边界；模块 2 完成混合输入与 NPC 私密回复的整体验证。检查秘密、唯一物品归属、关系保存、原档和分支隔离；不要求人物走指定路线或到达指定结局。

模型超时、非法字段、越权材料和候选校验失败时，保留输入且整轮不提交。真实模型的延迟、失败和语义偏差单独报告，测试替身不记为真实体验通过。
