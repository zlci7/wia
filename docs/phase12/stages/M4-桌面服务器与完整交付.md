# Phase12 M4 桌面、服务器与完整交付技术方案

状态：规划阶段，尚未进入开发。本方案整理总体技术合同中的 M4 边界；实现前仍需单独工程评审。

依据：[产品说明](../../产品说明.md)、[总体技术方案](../../summary/总体技术方案.md)、[开发指南](../开发指南.md)。M4 以 M1–M3 工程收口为前提，不负责补做故事内核、长期记忆或内容编辑器。

## 1. 阶段目标

M4 把本机浏览器内测形态交付为普通用户可以安装或部署的产品：

1. Windows 桌面应用能够启动、复用和关闭自己拥有的 Runtime。
2. 本机浏览器仍可直接使用同一后端和数据。
3. Linux 自托管服务支持真实账户、各自的世界和模型档案。
4. 电脑与手机浏览器能够在同一后端接续同一账户的故事。
5. 提供备份、恢复、升级和正式发布构建。

不包含 macOS/Linux 桌面包、原生手机应用、匿名公开注册、离线双向同步、多人同时控制一个故事、内容市场或大规模托管承诺。

## 2. 交付形态

```text
Windows 桌面
  Electron shell
      │ 本地启动交换、健康检查、窗口和进程所有权
      ▼
  WIA Runtime ── 本地数据根

本机浏览器
  Browser ── loopback WIA Runtime ── 本地数据根

自托管服务器
  Reverse proxy / TLS
      │
      ▼
  WIA Runtime ── 多用户应用库、世界目录、附件与密钥存储
      │
      └─ 受控出站模型 Provider
```

三种形态共用 `storyapp`、`storyapi` 和正式网页，不复制第二套故事逻辑。桌面壳只负责进程和窗口，不读取或修改世界数据库。

## 3. Windows 桌面应用

### 3.1 进程生命周期

桌面壳启动时：

1. 选择应用数据目录并检查可写性。
2. 尝试连接已经存在且身份匹配的本地 Runtime。
3. 没有可复用实例时启动随包分发的 Runtime，并取得进程所有权。
4. 完成本地启动交换后打开应用窗口。
5. 退出时只关闭自己启动且仍归自己所有的 Runtime。

Runtime 异常退出时显示明确恢复入口，不无限重启。桌面应用升级不能删除或覆盖用户数据目录。

### 3.2 安全边界

- Electron 开启 context isolation 与 sandbox，页面禁用 Node 能力。
- preload 只暴露最小启动状态和窗口控制接口。
- 禁止任意路径读取、命令执行、外部导航和未经允许的新窗口。
- 启动会话秘密不进入 URL、普通命令行参数或日志。
- 页面内容、角色卡和 Markdown 不能调用桌面 IPC。

### 3.3 打包

正式构建包含网页静态资源、Runtime 可执行文件、Electron 壳、版本元数据和许可证。Windows 首版目标为 x64 安装包；是否增加 portable 包在工程评审时决定。构建产物必须在干净机器或隔离虚拟机验证安装、首次启动、升级、卸载和保留数据。

## 4. 真实账户与会话

### 4.1 用户模型

M4 将当前本地 `App.userID` 接入真实会话：

- `user_id` 是授权边界，不使用主角名称、世界名称或浏览器标签作为身份。
- 每个用户拥有自己的活动世界、世界列表、内容项目、人物模板、模型档案和用量记录。
- 管理员创建或邀请账户；首版不开放匿名注册和社交登录。

### 4.2 认证

- 密码使用成熟的慢哈希方案和独立随机盐。
- 会话使用 Secure、HttpOnly、SameSite cookie。
- 所有写接口验证 CSRF/Origin；反向代理来源必须显式配置。
- 登录、注销、改密、会话撤销和管理员禁用具有确定状态。
- 限制登录尝试并记录不含密码和故事内容的安全日志。

本地 loopback 模式继续使用启动交换，不要求本机单用户每次输入账户密码。服务器模式不能复用“固定 local 用户”作为授权捷径。

## 5. 模型档案与凭据

模型档案按 owner 保存 provider、模型、受控 base URL、能力与修订。个人凭据和管理员开放的共享档案分开授权；普通用户不能读取共享密钥或其他用户档案。

凭据静态保存使用受控加密，主密钥与数据库分开配置和备份。API 不回显密钥；日志、导出、诊断和崩溃报告均不包含密钥。

服务端出站连接执行允许列表和 SSRF 防护：验证协议、DNS、实际连接地址、重定向和私网目标。管理员明确批准的本地模型使用单独规则，不能由普通用户提交任意内网 URL。

模型档案更新发布新 revision。运行中的回合使用冻结版本；新回合采用新版本。禁用账户或撤销凭据时阻止新调用，并取消仍可取消的相关任务。

## 6. 多设备接续

同一账户在一个后端上共享 `active_world_id + active_revision`。读取目录、正文和状态不切换世界；显式激活才改变写入目标。

电脑在 A 中生成、手机激活 B 时：

1. 用户级切换协调器验证 B 的 owner 和 ready 状态。
2. A 停止接受该用户的新生成，正在运行的任务完成或取消。
3. 旧任务发布前因 active revision 变化而失去写入权。
4. B 发布为活动世界，两端收到可理解的切换状态。

不同用户互不影响。同一账户不支持两台设备同时向两个世界写入；旧页面必须显示“存档已在其他设备切换”并停止提交。

M4 不提供本地数据与服务器数据的自动合并。迁移使用显式备份或导入，冲突时不按时间戳猜测覆盖。

## 7. 数据目录、备份与恢复

备份包含：

- 应用库；
- ready 世界目录及其 SQLite、definition 与资源快照；
- M3 内容项目、发布修订和附件；
- 模型档案元数据；
- 单独处理的加密凭据材料和密钥说明。

备份不直接复制正在写入的 SQLite 主文件而忽略 WAL，使用一致性备份机制或在受控维护窗口完成。恢复先进入隔离数据根，校验 schema、世界登记、附件 digest 和 owner 引用，再切换为正式数据。

恢复演练必须覆盖：完整恢复、缺失附件、损坏世界、不同应用版本、无凭据恢复和回滚。损坏世界与空世界分别报告，不能静默创建替代存档。

## 8. 升级与迁移

- 应用库和世界库迁移都带 schema version，重复执行幂等。
- 升级前生成可恢复备份或明确要求操作者备份。
- 迁移失败保持旧数据，不启动半升级 Runtime。
- 新版本不得从当前剧本模板覆盖既有世界 definition。
- 桌面应用、Runtime 和网页资源版本必须兼容；不兼容时阻止启动并给出升级说明。

正式版本号、数据 schema 与内容 schema 分开。应用升级不等于故事内容 revision 更新。

## 9. 部署合同

Linux 自托管提供明确的单进程部署基线、数据卷、环境变量、反向代理和健康检查说明。首版仍由一个 Runtime 进程独占一个数据根，不支持多个进程同时写同一组 SQLite 文件。

部署必须配置：

- 外部 URL、可信代理和 HTTPS；
- 数据与备份目录；
- 会话和凭据主密钥；
- 管理员账户初始化方式；
- 允许的模型 Provider 与出站策略；
- 上传和模型调用限额；
- 日志保留与轮换。

健康检查只报告服务、存储和迁移就绪，不泄露账户、世界、模型名称或密钥状态。日志使用不透明 ID 和错误码，不记录正文、人物秘密、Prompt 或推理内容。

## 10. 发布流水线

发布流程至少包含：

1. Go 全仓测试、相关 race/vet 和正式 Runtime 构建。
2. 前端机制测试、类型检查和 production build。
3. Electron 安全配置测试与 Windows 安装包构建。
4. Linux 部署镜像或发布包构建与启动测试。
5. 迁移、备份恢复、多用户隔离和跨设备切换集成测试。
6. 产物签名、校验和、版本说明与升级说明。

不执行自动生产部署。发布远端、上传安装包或修改线上服务需要用户明确授权。

## 11. 验证矩阵

| 范围 | 必测内容 |
| --- | --- |
| Windows | 安装、首次启动、已有 Runtime 复用、异常退出、升级、卸载保留数据 |
| Electron | sandbox、preload 允许列表、导航、外部链接、IPC 和恶意内容 |
| 账户 | 注册边界、登录、会话撤销、禁用、owner 正反向隔离 |
| 凭据 | 加密保存、不回显、日志/导出排除、密钥缺失恢复 |
| 出站 | DNS、重定向、私网地址、管理员本地模型例外 |
| 多设备 | A 生成时切 B、重复激活、旧请求迟到、不同用户并行 |
| 备份 | 应用库、世界、附件、内容项目、恢复校验和损坏处理 |
| 部署 | 新数据根、升级数据根、反向代理、手机浏览器和容量边界 |

手机至少使用可用实机验证登录、阅读、输入、设置、回顾、存档切换和软键盘；桌面视口模拟不能替代该项。

## 12. 完成定义

M4 工程完成要求 Windows 正式包、本机浏览器方式和 Linux 自托管方式都有可复现构建与验证记录；账户、owner、凭据、备份、迁移和跨设备切换通过程序测试及实际运行验证。

用户体验验收独立进行：普通用户能够安装或打开产品、连接模型、继续存档，并理解数据和模型由谁托管。打包成功、容器启动或单机管理员访问成功都不能单独视为完整 Phase12 发布验收。
