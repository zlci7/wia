## P3/P4 候选：世界推进与持久化兼容

[世界节点编译](../../../backend/internal/turn/scene_world.go)按实际工作时间、位置和发展依据选择事项，沿用到期安排、发展轮转、个人计划、旧节点和开放事件的既有规则。实际选中的事项必须有评估；无变化评估更新依据，发生的事项有对应世界节点。结构条件由程序在发生前检查，证据进入来源依赖。未获个人投影的人物不获得作者根内容；无人观察的变化可以只保存世界记录。

未来计划的窗口只提供目录，实际到期时再装配本人资料。每轮最多两名到期 owner 可以在一次资料扩展中装配，继续共用整场预算。稳定人物档案使用共享字段表，保留完整字段及 owner；完整地点连接是必需信息，地点详细环境按预算装配。当前《雾都余烬》v9 的隔离候选用例两次核心请求的输入估计分别为 11,730 和 11,432，均不超过 12,000；一次用于补充发展材料，没有结构或业务纠正。另有一次固定规则意图解析。该用例证明当前材料可以装配，不是任意场景容量或真实 Provider token 数保证。

## 个人来源优先召回

现有 `memory.SearchMemoryGroups` 在同一次有界候选扫描中优先匹配明确的个人记录 ID 或事件 ID，再按关键词排序。请求仍限定本人 archive；摘要保留状态及本人当前计划提供引用，没有模型检索规划调用。扫描保持最近 512 条候选、32 MiB 来源预算、500 ms 时限和最多五个完整组；引用列表至多检查 32 项。窗口之外的来源报告受限，不绕过预算扫描全部历史。

该规则同时用于现行个人上下文和集中场景候选。完整组不与近期必需组重复；从未摘要 backlog 取回的完整组只装配一次，并参加共享容量裁剪。检索不推进摘要水位、不改写历史和计划，也不把被预算排除的原文标为已经提供。

[检索规则测试](../../../backend/internal/memory/referenced_recall_test.go)验证关键词不匹配时的记录/事件精确定位、尝试与结果共同返回、来源缺失、完整组去重和扫描/字节/引用上限。[场景记忆测试](../../../backend/internal/turn/scene_memory_recall_test.go)验证两个 owner 的同名记录分别归一、摘要与计划引用各自生效、禁止交叉引用，以及 backlog 文本只提供一次。模型能否正确利用承诺和失败结果仍由 E08 验证。

## 来源、输入顺序与恢复边界

人物对白、行动和观察引用前序节点时，仅取得本人实际收到的投影。人物个人记录与原文保持 owner 权限；主持裁定可以引用实际提供的冻结事实，世界节点可以引用主持来源。角色行动不能以作者根记录取得另一人的私聊或个人经历。

混合输入按原文顺序引入；未执行片段先于独立后段保存。没有关联节点的片段须为 `not_executed` 并有原因，原因通过现有尝试、结果和个人投影保存。未发生的交谈没有 NPC 听众，玩家记忆保留未执行结果；该记录不改变钱物、位置或经过时间。
