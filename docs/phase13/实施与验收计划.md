# Phase13 实施与验收计划

当前优先执行[共创游玩执行规划](CoCreative-Gameplay-Execution-Plan.md)。其单剧本创作原型不以本页的完整兼容矩阵为验收范围；本页正式切换、存档与完整世界机制验收后置，已交付能力和历史记录保持原状态。

状态：工程实施，实际范围与验证结果见[开发状态](../phase12/开发状态.md)及[工程验收记录](../summary/phase13/工程验收记录.md)。范围为[开放叙事与单 Agent 技术方案](开放叙事与单Agent-技术方案.md)中的集中场景生成、上下文、结果校验及兼容迁移。2026-10-07 获得真实预检、正式切换及切换后连续验收的执行授权。使用已有模型与隔离存档，沿用输入、输出、超时及重试限制；密钥、用户存档和本机默认配置保持。第 8 节为工程工时预估与建议安排。

## 本轮执行顺序

整轮生成时间预算为 300 秒；正式入口、候选入口及内层模型阶段共用该值，并继承取消与更短的调用方截止时间。输入、输出与调用次数上限保持，见[生成预算与等待进度](生成预算与等待进度.md)。

1. **真实质量预检**：在隔离世界验证连续追问、多个意图、多人互动与私聊。保存完整输入、正文、个人投影、实际状态、请求数、用量、纠正和失败。先完成四至六个有价值的回合；同条件旧链路对照使用切换前修订与独立数据根。每条失败输入最多一次技术重试，确定的容量问题先本地修复。
2. **正式链路切换**：预检没有未解决的重大控制权、秘密或连续性问题后，将 `Service.Execute` 接入唯一集中创作流程。保留现有运行准入、取消重试、阶段诊断和原子提交；清理旧逐人物生成、协调及独立正文调用和过时次数断言。共享纯规则继续复用，兼容世界能力完整保留。
3. **正式验收**：运行全仓、相关包 race、vet、构建和 43 项机制回归；通过正式入口完成连续追问、私聊后公开交谈、世界推进、钱物变化、个人记忆、另存重启与分支续玩。记录正文等待、建议独立就绪、模型实际用量与缓存诊断；真实失败保留，不用替身成功覆盖。
4. **收口**：完成内部 CR、本地提交、事实源与验收证据；独立区分机制通过、真实小样本结论和未验证项。服务不可用时停止付费重试，完成仍可执行的本地工作；未通过预检不进入正式切换。

## 1. 工作单元

| 单元 | 具体工作 | 交付与验收 | 依赖 |
| --- | --- | --- | --- |
| P0 基线与合同 | 冻结 HEAD、fixture、现有调用、事件与资料投影；补齐 SceneDraft 字段表 | 当前行为基线、错误路径、迁移清单和可复现输入 | 无 |
| P1 规则解耦 | 提取旧阶段内身份、来源、听众、移动、状态、关系、物品纯规则 | 正式调用仍保持原行为；全仓、race、vet 和差异通过 | P0 |
| P2 上下文与候选 | 实现 scene 用途、多人物个人视图、重点摘要与完整旧经历、唯一整场预算、有界响应循环、对白派生投影、判定检查点及候选校验 | 仅测试链路可生成完整候选，未启动第二正式引擎 | P1 |
| P3 链路切换 | 集中人物互动、行动裁定、正文；节点生成正式事件并组装 Output | 普通场景、失败和提交回归通过；直接替换旧调用 | P2 |
| P4 世界与兼容 | 到期安排、计划复查、发展事项、开放事件、旧节点、旧存档与纠正 | 全能力矩阵通过，切换后既有能力持续可用 | P2/P3 |
| P5 真实质量评估 | 相同模型、材料、设置和自由度对照，连续游玩及状态核对 | 区分机制交付、体验结论和未验证项 | P3/P4；已有真实模型授权 |

P3/P4 是同一发布边界。若无法在中间提交保持现有世界能力，则合并为一个完整切换工作单元，测试先行、代码一次替换。每个独立可交付单元完成相关回归、自查及 diff 检查后本地提交。

P2 后设置质量预检。先用 E01—E04 对照完整候选；普通输入须在现有生成、纠正和超时边界内可靠提交，人物互动和玩家控制没有未解决的重大问题，再进入正式切换。P5 验证正式链路的连续体验；失败预检不由离线机制通过替代。

### 1.1 开工与切换条件

| 边界 | 必需条件 | 当前结论 |
| --- | --- | --- |
| P0/P1 开工 | 单创作职责、现有 Turn/Memory/Storage 复用、兼容范围和行为基线明确 | 设计条件具备；开工先取得实际基线，不等待新框架或检索服务 |
| P2 候选开发 | 多人物 owner、整场预算、对白/行动投影、三类响应和来源转换合同明确 | 设计条件具备；只在候选测试链路验证 |
| P3/P4 正式切换 | 全机制矩阵、规定回归、旧档承接与创作质量预检通过 | 以机制证据与当前真实预检结果分别核对；未通过时保持现行默认链路 |
| P5 体验结论 | 正式新链路的同条件连续游玩、长历史与多题材证据 | 在正式切换后验证 |

开工前仍需将最终 Go 类型、节点编译和实际来源映射落实到 P0 清单。它们属于实现工作，不要求先建设 Agent Harness、全局记忆库或泛化工具系统。新增 Provider/插件运行时、语义检索与结构状态历史重建均不属于首次迁移。

## 2. P0 行为基线

保存以下可比资料，使用隔离的测试数据目录：

- 当前请求用途、顺序、必需来源、整轮调用数与失败位置。
- 原文、事件、逐人投影、时间、位置、现金、物品、关系和计划。
- 拒绝、私聊、争夺物品、行动失败、到达新地点和旧约定召回。
- 取消、重试、未知提交、另存重启与纠正后的来源失效。
- 既有篇幅、人称、主角补写、人物主动性和三项行为策略。

P1 结构解耦以行为不变为准；P3 的集中创作有意改变生成组织，按新合同与体验指标验收，不要求与旧版逐字或逐调用相同。

模型输出的语义基线仅在已有授权有效时记录。暂停期间只捕获测试替身请求，不给它标记“真实模型基线”。

## 3. 机制验收矩阵

| 编号 | 情境 | 必须成立的结果 |
| --- | --- | --- |
| T01 | 普通问答，无状态变化 | 一次合格核心创作，正文与实际对白对应 |
| T02 | 问清情况后查房间及账册 | 原文完整关联，普通步骤连续执行，未执行部分有原因 |
| T03 | NPC 甲拒绝乙，乙继续回应 | 拒绝保持；乙的后续 basis 来自本人收到的前一投影 |
| T04 | 私聊，第三人在旁 | 第三人记录没有完整私聊内容，玩家旁白没有他人私密结果 |
| T05 | 第三人稍后到场 | 位置按节点更新，不回填此前对白 |
| T06 | 两人争夺同一物品 | 冲突可以发生，最终唯一归属，失败方得到失败投影 |
| T07 | 付款、获得物品，余额不足变体 | 成功时钱物对应；不足时不产生半笔交易 |
| T08 | 未声明物品或新实体 ID | 拒绝候选，纠正失败后没有提交 |
| T09 | 固定判定成功/失败与普通行动 partial | 固定规则沿用既有 succeeded/failed 结果；使用一次已准备结果，纠正或重试不重新选规则 |
| T10 | 跨地点行动 | 连接与路线合格，当前名单由最终位置推导 |
| T11 | 主动 NPC 与沉默 NPC | 知情投影分别保存，无全员发言要求 |
| T12 | 外部安排在时间窗口内到期 | 发生时间与进度来源一致，不静默跨过关键边界 |
| T13 | 个人计划到期、暂停或完成 | 保持当前计划，不从作者初始文件重置 |
| T14 | 发展评估没有变化 | 更新有效评估依据，不凭空制造正文事件 |
| T15 | 开放事件生成与活跃上限 | 候选 0/1、冷却、起点来源和后续恢复保持 |
| T16 | 旧剧情节点与旧结局 | 读取冻结语义，进度不丢失 |
| T17 | v1/v2/v3/v4 存档 | 各自时钟和能力缺项按既有合同处理 |
| T18 | 旧约定退出近期窗口及关键词未命中 | 明确个人来源在现有预算内定位完整组；查询无命中与受限分别报告，不补写原话 |
| T19 | 纠正未被结构状态消费的普通文本事实 | 有关后续依据失效，旧原文可追溯 |
| T20 | 必需上下文超限 | 清晰容量错误，输入和世界状态保持 |
| T21 | 合法补充读取与非法读取 | 一次申请、至多四文件；未授权或再次申请被拒绝 |
| T22 | JSON 重复键、缺字段、截断、陌生枚举 | 有界纠正，仍失败没有半轮后果 |
| T23 | later-beat 来源、循环或无权投影 | 来源被拒绝，不把作者根正文作为私人经历 |
| T24 | 玩家取消、切换世界、陈旧版本 | 调用取消或提交拒绝，候选不能套到新状态 |
| T25 | 未知提交后查询与重复请求 | 查到已提交结果后复用，不重复时间、钱物与事件 |
| T26 | 另存、后端重启、续玩 | 状态、来源、个人记忆和计划保持 |
| T27 | 非诡秘最小 fixture | 同一合同可用，通用提示没有题材常量 |
| T28 | 正文与三项建议分开就绪 | 正文先可靠提交，建议迟到按 basis 丢弃 |
| T29 | 移动或状态改变后执行固定规则 | 判定使用已验证前段工作态；续请求保持前段；重试前提冲突不重掷 |
| T30 | 本轮节点、摘要与个人记录来源提交 | 临时来源归一为有效正式事件；父事件可插入，纠正可追踪失效 |
| T31 | 多节点累计改变同一状态或关系 | 整轮变化不超过预算；检查点与纠正不重置预算、不重复应用 |
| T32 | 新建计划、到期复查但没有计划调整 | 新计划归属正确；仍到期的 active 计划延后 30 分钟；显式调整不重复递增版本 |
| T33 | 节点类型与互斥响应，嵌套续请求 | 跨类型字段和混合响应拒绝；读取/检查点/纠正共享上限，核心最多四次 |
| T34 | 预备时间窗与实际行动结果不同 | 按实际时间和变化后位置选世界评估对象，不提前唤醒未来计划 |
| T35 | 合法 NPC 未选入本请求，或在新地点出现 | ID 存在不授予创作资格；有依据扩展并装配资料后才能回应 |
| T36 | 同时装配多人的近期、摘要与召回 | 前一人物资料不被覆盖；整场共享预算与去重，owner 始终保留 |
| T37 | 公开/私下对白、未装配档案的听众与晚到者 | 程序派生合法原话投影；私人第三人没有正文；听见不授予创作资格 |
| T38 | 同账户不同存档、多人个人记录/digest 归一与相似来源 ID | 先限定 world/owner 和有效来源，再排序与归一；同轮后续引用只取得本人投影 |
| T39 | 目录条目、冻结补材与目的地运行时资料扩展 | 目录不冒充正文；个人视图不冒充剧本文件；补充机会只消费一次 |
| T40 | 纠正文本与受保护结构来源 | 普通文本按现行合同纠正；会破坏钱物、位置或已结算来源的纠正被拒绝 |
| T41 | 连续摘要跨多轮，包含谎言、推测、已兑现承诺、失败尝试及历史相对时间 | 状态种类与来源合法；主观说法保留主体，已完成事项不成为待办；尝试失败不关闭仍有效承诺；世界日期有依据，不使用 CreatedAt 推算 |
| T42 | 可选摘要失败、额度耗尽与旧任务迟到 | 保留有效旧摘要和完整未摘要组；不重置调用额度；epoch/revision/head 冲突不发布，必需缺项仍失败 |
| T43 | 摘要发布后继续游玩或另存重启 | 稳定档案可复用，下一请求读取最新摘要、时钟与钱物；来源范围和 world 绑定保持 |

测试应集中验证真实约束和失败行为，不为每个纯文本风格句子写镜像断言。旧阶段次数测试改为新职责、调用预算和状态正确性测试；历史基线记录保持。

T41 的类型、来源和时间依据由机制检查覆盖；承诺含义、主观判断与摘要表达同时进入 E08 的真实评估。测试替身只验证材料与保存合同，不证明模型能够正确理解这些含义。

## 4. 运行检查

叙事代码单元必须运行：

```powershell
go test ./... -count=1
go test -race ./backend/internal/turn ./backend/internal/app ./backend/internal/storyapi ./backend/internal/content
go vet ./...
go build ./...
git diff --check
```

若改动 memory、plot、storage 或 llm，增加直接受影响包的 race 和针对性回归。当前模块边界测试和旧存档兼容测试必须保留。

若修改前端或玩家 API 的展示合同，运行既有类型检查、机制测试和正式构建，再验证正文、资料、建议、草稿、阅读位置与错误恢复。只有后端内部生成合同改变时，不为本阶段重做 UI。

文档维护检查全部本地链接、引用路径、示例 JSON、围栏平衡和事实状态；历史截图及指标文件保持内容校验。实际证据写入 `docs/summary/phase13/`，只在取得结果时创建验收记录。

## 5. 真实体验场景

| 编号 | 场景 | 重点 |
| --- | --- | --- |
| E01 | 委托人隐瞒一段争执，玩家连续追问 | 信息递进、态度一致、重复描写 |
| E02 | 请求检查房间和账册，再问发现意味着什么 | 完整意图处理、固定线索与新推测区别 |
| E03 | 两名 NPC 有不同利益，当着玩家互相回应 | 对话连贯、个性和拒绝 |
| E04 | 玩家私下提供消息，第三人观察后试探 | 直接泄漏与未知内容影响行为 |
| E05 | 同一件物品的交付被另一人打断 | 动作、对白、结果和钱物一致 |
| E06 | 原有压力发展为通知、机会或暂时平静 | 有依据的创作空间和事件密度 |
| E07 | 到达新地点，接触新人并继续交谈 | 到场顺序和当前参与者 |
| E08 | 隔多轮提起旧约定，再另存重启 | 旧证词条件与结果、兑现/取消后的承接、主观判断和世界日期；记录召回受限与实际漏召回 |
| E09 | 固定规则失败后人物重新安排计划 | 不篡改判定，失败有后续意义 |
| E10 | 非诡秘交易/调查 fixture | 通用性和题材适配 |

第一批优先 E01—E04，每个场景双方使用相同冻结输入起点，再各自连续两至三轮，观察后续是否承接。若没有重大机制问题，再按实际授权和剩余预算扩展。相同首轮输入便于对照；分歧后的后续输入遵循同一玩家意图，不强行把不适用的动作复制到另一分支。

两版使用分别启动的修订和隔离存档，不在正式实现中保留双引擎。模型、参数、内容、设置和创作空间等价；无法保持等价的地方列为混杂因素。文本去除版本标识后盲评，事件与状态核对另行进行。

## 6. 评分与结论

连贯、意图处理、人物区别、自由发挥、节奏分别以 0—4 评分：0 为严重不成立，1 为明显问题，2 为部分成立，3 为稳定成立，4 为表现突出。分数必须附具体片段与原因，不只给平均值。

玩家控制、关键秘密、钱物/位置、保存与恢复单独记录严重事件。把失败回合和重试计入结果，不能只挑成功正文评分。程序缺陷不能被更好的文笔抵消。

| 结论层级 | 所需证据 |
| --- | --- |
| 技术方案完成 | 文档合同、迁移和验收完整且一致 |
| 工程实现完成 | 机制矩阵与规定回归通过，正式链路单一 |
| 小样本体验更合适 | 同条件对照中连贯和意图处理改善，人物区别没有明显下降，无未解决重大缺陷 |
| 持续游玩质量通过 | 长历史、世界推进、另存重启和多题材连续体验成立 |

不能运行真实模型时，交付已通过的规则解耦与候选机制结论，正式切换与 P5 保留待验证。小样本结论只适用于该模型、材料和设置，不写成所有模型下的普遍结论。

整轮指标保留正文完成时间、建议就绪时间、各用途请求、纠正/失败数、估计与实测输入输出、缓存诊断。费用不是本阶段主选型指标，仍遵守已有授权上限。

## 7. 收口与交付

完整单元交付包含：实际行为、提交、测试命令和结果、真实体验证据与已知限制。内部自查与独立审查分别陈述，没有独立审查时不声称已经完成。

正式切换时同步架构、产品与跨阶段合同中关于人物调用和共享上下文的现行描述，阶段设计不反向改写 Phase12 验收结论。实际进度只更新开发状态，阶段总结与截图归入对应总结目录。

真实模型验证的恢复需已有暂停被明确解除；失败时保持测试世界安全，不覆盖用户存档、配置或密钥。本地提交依次保存完整单元，推送由用户执行。

## 8. 工时预估与执行安排

估算基于当前 Turn、ContextComposer、来源与存档机制，以及本方案的 43 项机制情境；不是实测吞吐或完成承诺。以单个执行者连续工作、开发环境可用、复用现有 UI 和剧本包为前提。现代运行机制参考只深化现有迁移合同，不包含框架接入或新增记忆服务。Hermes 相关检查复用记忆、来源和存档 fixture，不包含长历史索引建设或维护调度迁移。

| 工作 | 预计工时 | 收口点 |
| --- | --- | --- |
| P0 基线与合同冻结 | 0.5—1 小时 | 行为、事件 ID、规则准备与旧版本矩阵明确 |
| P1 纯规则解耦 | 1.5—2.5 小时 | 旧正式链路不变，直接回归通过 |
| P2 场景上下文与候选原型 | 2—3 小时 | 来源转换、互斥响应、检查点与共享预算成立 |
| P3/P4 正式切换与世界兼容 | 4—6 小时 | 单一链路、能力矩阵及旧档恢复通过 |
| 综合回归、内部 CR 与文档收口 | 1.5—2.5 小时 | 全仓、race、vet、构建及最终事实源一致 |
| 真实质量预检与最终连续体验 | 2—4 小时 | P2 小样本和 P5 正式链路对照，保留失败证据 |
| 源依赖、旧阶段耦合与响应修正缓冲 | 2—3 小时 | 修复发现的问题并复验受影响行为 |

工程实现与回归约 9.5—15 小时；包含真实质量验证与缓冲，建议总预算约 14—22 小时，按 16—18 小时安排主要工作。真实模型暂停解除的等待、服务不可用时间和额外费用不计入上述工时。服务或体验结果可能要求重新估算；不能因预算结束而把未验证项记为完成。

### 8.1 第一轮五小时

| 时段 | 工作 | 预期结果 |
| --- | --- | --- |
| 0:00—0:30 | 冻结当前行为与事件/判定合同 | 可复现基线及重点兼容清单 |
| 0:30—2:00 | 解耦直接受集中链路影响的纯规则 | 身份、来源和能力规则复用；旧链路回归保持 |
| 2:00—4:00 | 最小 SceneFrame/SceneDraft、普通对白与观察、来源编译和拒绝路径 | 可测试候选原型；P2 未完成部分明确列出 |
| 4:00—5:00 | 回归、内部 CR、文档与完整单元本地提交 | 首轮工程证据与清晰续接点 |

第一轮目标是合同、规则和候选原型，不承诺五小时内正式切换或证明剧情变好。固定判定检查点和完整世界兼容在 P2/P3/P4 继续完成。任一单元超时则压缩原型情境，保留最后一小时回归和收口；尚未通过的修改不进入正式调用链路。

### 8.2 后续顺序

1. 完成 P2 的检查点、材料与调用上限，覆盖 T29—T43；获准时先做创作质量预检。
2. 完成 P3/P4 待切换实现的节点编译、世界资格、计划、开放事件和旧档承接，在隔离测试环境验证。
3. 全机制矩阵、全仓与受影响包回归、旧档和创作质量预检通过后，一次替换正式创作调用；核对切换结果并按完整工作单元保存本地提交。
4. 真实模型获准后完成 P5，优先 E01—E04，再验长期承接和非诡秘情境。工程与体验分别结论。
