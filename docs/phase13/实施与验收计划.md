# Phase13 实施与验收计划

状态：待实施。范围为[开放叙事与单 Agent 技术方案](开放叙事与单Agent-技术方案.md)中的集中场景生成、上下文、结果校验及兼容迁移。运行代码尚未切换，真实模型继续暂停。本计划不沿用已经执行的 Phase12 五小时预算，不预设新的工作时长或费用额度。

## 1. 工作单元

| 单元 | 具体工作 | 交付与验收 | 依赖 |
| --- | --- | --- | --- |
| P0 基线与合同 | 冻结 HEAD、fixture、现有调用、事件与资料投影；补齐 SceneDraft 字段表 | 当前行为基线、错误路径、迁移清单和可复现输入 | 无 |
| P1 规则解耦 | 提取旧阶段内身份、来源、听众、移动、状态、关系、物品纯规则 | 正式调用仍保持原行为；全仓、race、vet 和差异通过 | P0 |
| P2 上下文与候选 | 实现 scene 用途、SceneFrame、人物资料包、预算、互斥材料请求和 SceneDraft 校验 | 仅测试链路可生成完整候选，未启动第二正式引擎 | P1 |
| P3 链路切换 | 集中人物互动、行动裁定、正文；节点生成正式事件并组装 Output | 普通场景、失败和提交回归通过；直接替换旧调用 | P2 |
| P4 世界与兼容 | 到期安排、计划复查、发展事项、开放事件、旧节点、旧存档与纠正 | 全能力矩阵通过，切换后既有能力持续可用 | P2/P3 |
| P5 真实质量评估 | 相同模型、材料、设置和自由度对照，连续游玩及状态核对 | 区分机制交付、体验结论和未验证项 | P3/P4；真实模型恢复授权 |

P3/P4 是同一发布边界。若无法在中间提交保持现有世界能力，则合并为一个完整切换工作单元，测试先行、代码一次替换。每个独立可交付单元完成相关回归、自查及 diff 检查后本地提交。

## 2. P0 行为基线

保存以下可比资料，使用隔离的测试数据目录：

- 当前请求用途、顺序、必需来源、整轮调用数与失败位置。
- 原文、事件、逐人投影、时间、位置、现金、物品、关系和计划。
- 拒绝、私聊、争夺物品、行动失败、到达新地点和旧约定召回。
- 取消、重试、未知提交、另存重启与纠正后的来源失效。
- 既有篇幅、人称、主角补写、人物主动性和三项行为策略。

P1 结构解耦以行为不变为准；P3 的集中创作有意改变生成组织，按新合同与体验指标验收，不要求与旧版逐字或逐调用相同。

模型输出的语义基线仅在已有授权有效时记录。暂停期间只捕获测试替身请求，不给它标记“真实模型基线”。

## 3. 机制验收矩阵

| 编号 | 情境 | 必须成立的结果 |
| --- | --- | --- |
| T01 | 普通问答，无状态变化 | 一次合格核心创作，正文与实际对白对应 |
| T02 | 问清情况后查房间及账册 | 原文完整关联，普通步骤连续执行，未执行部分有原因 |
| T03 | NPC 甲拒绝乙，乙继续回应 | 拒绝保持；乙的后续 basis 来自本人收到的前一投影 |
| T04 | 私聊，第三人在旁 | 第三人记录没有完整私聊内容，玩家旁白没有他人私密结果 |
| T05 | 第三人稍后到场 | 位置按节点更新，不回填此前对白 |
| T06 | 两人争夺同一物品 | 冲突可以发生，最终唯一归属，失败方得到失败投影 |
| T07 | 付款、获得物品，余额不足变体 | 成功时钱物对应；不足时不产生半笔交易 |
| T08 | 未声明物品或新实体 ID | 拒绝候选，纠正失败后没有提交 |
| T09 | 成功、失败和 partial 的固定判定 | 使用一次已准备结果，纠正或重试不重新选规则 |
| T10 | 跨地点行动 | 连接与路线合格，当前名单由最终位置推导 |
| T11 | 主动 NPC 与沉默 NPC | 知情投影分别保存，无全员发言要求 |
| T12 | 外部安排在时间窗口内到期 | 发生时间与进度来源一致，不静默跨过关键边界 |
| T13 | 个人计划到期、暂停或完成 | 保持当前计划，不从作者初始文件重置 |
| T14 | 发展评估没有变化 | 更新有效评估依据，不凭空制造正文事件 |
| T15 | 开放事件生成与活跃上限 | 候选 0/1、冷却、起点来源和后续恢复保持 |
| T16 | 旧剧情节点与旧结局 | 读取冻结语义，进度不丢失 |
| T17 | v1/v2/v3/v4 存档 | 各自时钟和能力缺项按既有合同处理 |
| T18 | 旧约定退出近期窗口 | 相关召回有来源，未命中不证明未发生 |
| T19 | 纠正一项旧事实 | 有关后续依据失效，旧原文可追溯 |
| T20 | 必需上下文超限 | 清晰容量错误，输入和世界状态保持 |
| T21 | 合法补充读取与非法读取 | 一次申请、至多四文件；未授权或再次申请被拒绝 |
| T22 | JSON 重复键、缺字段、截断、陌生枚举 | 有界纠正，仍失败没有半轮后果 |
| T23 | later-beat 来源、循环或无权投影 | 来源被拒绝，不把作者根正文作为私人经历 |
| T24 | 玩家取消、切换世界、陈旧版本 | 调用取消或提交拒绝，候选不能套到新状态 |
| T25 | 未知提交后查询与重复请求 | 查到已提交结果后复用，不重复时间、钱物与事件 |
| T26 | 另存、后端重启、续玩 | 状态、来源、个人记忆和计划保持 |
| T27 | 非诡秘最小 fixture | 同一合同可用，通用提示没有题材常量 |
| T28 | 正文与三项建议分开就绪 | 正文先可靠提交，建议迟到按 basis 丢弃 |

测试应集中验证真实约束和失败行为，不为每个纯文本风格句子写镜像断言。旧阶段次数测试改为新职责、调用预算和状态正确性测试；历史基线记录保持。

## 4. 运行检查

叙事代码单元必须运行：

```powershell
go test ./... -count=1
go test -race ./backend/internal/turn ./backend/internal/app ./backend/internal/storyapi ./backend/internal/content
go vet ./...
go build ./...
git diff --check
```

若改动 memory、plot、storage 或 llm，增加直接受影响包的 race 和针对性回归。当前模块边界测试和旧存档兼容测试必须保留。

若修改前端或玩家 API 的展示合同，运行既有类型检查、机制测试和正式构建，再验证正文、资料、建议、草稿、阅读位置与错误恢复。只有后端内部生成合同改变时，不为本阶段重做 UI。

文档维护检查全部本地链接、引用路径、示例 JSON、围栏平衡和事实状态；历史截图及指标文件保持内容校验。实际证据写入 `docs/summary/phase13/`，只在取得结果时创建验收记录。

## 5. 真实体验场景

| 编号 | 场景 | 重点 |
| --- | --- | --- |
| E01 | 委托人隐瞒一段争执，玩家连续追问 | 信息递进、态度一致、重复描写 |
| E02 | 请求检查房间和账册，再问发现意味着什么 | 完整意图处理、固定线索与新推测区别 |
| E03 | 两名 NPC 有不同利益，当着玩家互相回应 | 对话连贯、个性和拒绝 |
| E04 | 玩家私下提供消息，第三人观察后试探 | 直接泄漏与未知内容影响行为 |
| E05 | 同一件物品的交付被另一人打断 | 动作、对白、结果和钱物一致 |
| E06 | 原有压力发展为通知、机会或暂时平静 | 有依据的创作空间和事件密度 |
| E07 | 到达新地点，接触新人并继续交谈 | 到场顺序和当前参与者 |
| E08 | 隔多轮提起旧约定，再另存重启 | 长期连贯和存档承接 |
| E09 | 固定规则失败后人物重新安排计划 | 不篡改判定，失败有后续意义 |
| E10 | 非诡秘交易/调查 fixture | 通用性和题材适配 |

第一批优先 E01—E04，每个场景双方使用相同冻结输入起点，再各自连续两至三轮，观察后续是否承接。若没有重大机制问题，再按实际授权和剩余预算扩展。相同首轮输入便于对照；分歧后的后续输入遵循同一玩家意图，不强行把不适用的动作复制到另一分支。

两版使用分别启动的修订和隔离存档，不在正式实现中保留双引擎。模型、参数、内容、设置和创作空间等价；无法保持等价的地方列为混杂因素。文本去除版本标识后盲评，事件与状态核对另行进行。

## 6. 评分与结论

连贯、意图处理、人物区别、自由发挥、节奏分别以 0—4 评分：0 为严重不成立，1 为明显问题，2 为部分成立，3 为稳定成立，4 为表现突出。分数必须附具体片段与原因，不只给平均值。

玩家控制、关键秘密、钱物/位置、保存与恢复单独记录严重事件。把失败回合和重试计入结果，不能只挑成功正文评分。程序缺陷不能被更好的文笔抵消。

| 结论层级 | 所需证据 |
| --- | --- |
| 技术方案完成 | 文档合同、迁移和验收完整且一致 |
| 工程实现完成 | 机制矩阵与规定回归通过，正式链路单一 |
| 小样本体验更合适 | 同条件对照中连贯和意图处理改善，人物区别没有明显下降，无未解决重大缺陷 |
| 持续游玩质量通过 | 长历史、世界推进、另存重启和多题材连续体验成立 |

不能运行真实模型时，停在工程结论，保留 P5 未验证。小样本结论只适用于该模型、材料和设置，不写成所有模型下的普遍结论。

整轮指标保留正文完成时间、建议就绪时间、各用途请求、纠正/失败数、估计与实测输入输出、缓存诊断。费用不是本阶段主选型指标，仍遵守已有授权上限。

## 7. 收口与交付

完整单元交付包含：实际行为、提交、测试命令和结果、真实体验证据与已知限制。内部自查与独立审查分别陈述，没有独立审查时不声称已经完成。

正式切换时同步架构、产品与跨阶段合同中关于人物调用和共享上下文的现行描述，阶段设计不反向改写 Phase12 验收结论。实际进度只更新开发状态，阶段总结与截图归入对应总结目录。

真实模型验证的恢复需已有暂停被明确解除；失败时保持测试世界安全，不覆盖用户存档、配置或密钥。本地提交依次保存完整单元，推送由用户执行。
