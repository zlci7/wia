# WIA 共创游玩执行规划

日期：2026-10-07。状态：内部原型与连续测试已交付，实际范围见[开发状态](开发状态.md)。代码核对基线：`a7f4f90`。后续网页交付范围见[网页共创试玩执行规划](网页共创试玩-执行规划.md)。

本轮交付为《雾都余烬》的轻量连续共创原型。验收以真实模型生成的完整场景、人物互动、合理的新发展和玩家选择权为依据。正式回合接线属于独立交付范围。

模块职责见[整体架构](../summary/ARCHITECTURE.md)，产品范围见[产品说明](../产品说明.md)，通用合同见[总体技术方案](../summary/总体技术方案.md)。实际进度记录在[Phase13 开发状态](开发状态.md)，已有模型结果见[连续预检与容量验收](records/连续预检与容量-验收.md)。

## 1. 本轮范围

| 工作 | 交付 |
| --- | --- |
| 显式控制模型思考 | 在诊断和创作请求中选择思考模式，以实测确定参数 |
| 集中场景创作 | 一次组织相关人物、互动、行动结果和正文 |
| 精简返回合同 | 正文，以及承接下一轮所需的少量情境变化和记录 |
| 相关上下文装配 | 剧本事实、人物动机、近期对话及相关旧经历 |
| 逐回合推进授权 | 内部请求参数 `allow_plot_advance` |
| 剧本材料完善 | 在现有文件中分别表达固定事实、人物驱动力和创作空间 |
| 连续互动验证 | 本地内部会话入口、真实文本和测量结果 |

UI、存档迁移、存读档验收、正式入口切换、经济机制扩展、固定判定接入、长历史基础设施和其他可玩剧本后置。用户数据与本机配置保持原状态，既有能力及历史验收结论保留。

完整 Phase13 兼容矩阵属于后续正式迁移。本原型仍运行与代码改动相匹配的仓库检查；原型通过不代表正式应用、持久化兼容或完整世界机制已经通过验收。

## 2. 创作闭环

```text
玩家原文＋是否允许主动推进
  → 装配相关剧本材料与当前会话情境
  → 一次集中场景创作
  → 校验完整结果
  → 接受正文、必要情境变化与连续性记录
  → 以接受后的情境承接下一轮
```

实施位置为现有 `backend/internal/turn` 候选创作职责。复用 Provider、材料选择、`ContextComposer`、记忆结构和位置规则。内部会话入口属于开发验证，不建立第二个正式运行时或记忆服务。本轮正式应用入口继续使用现有 `Service.Execute`。

纯正文生成只作为测试入口中的创作参照。最终创作实现采用一份返回合同；被替换的候选生成逻辑和过时消费者在对应单元中修订或删除，历史代码保留在 Git 中。

验证会话可以在内存中承接已接受的上下文。原型不构造虚假的 `Output`、事务成功结果或存档记录。

## 3. 请求与返回边界

### 请求

- 保留玩家原文。
- 每轮显式接收 `allow_plot_advance`。
- 诊断和创作请求显式选择思考模式。
- 思考模式与流式传输分别控制。
- 沿用适用的输入、合并输出、截止时间和取消限制。

固定对照样本使用 `allow_plot_advance=false`，第二段连续会话验证开启后的表现。正式界面的默认选项后置。

### 最小返回

| 字段 | 含义 |
| --- | --- |
| `narrative` | 必填，完整的玩家可读场景 |
| `scene_changes` | 必填，实际耗时与相关人物的结束位置，使用既有人物与地点 |
| `continuity_notes` | 可选，重要发现、证词、约定或未完成事项，以及对应知情人物 |

具体 Go 类型与运行合同见[轻量共创游玩](轻量共创游玩.md)。每轮提供相关人物的结束位置，连续性事项按需提供。普通返回不要求逐句事件图、重复抄写玩家输入、每轮世界评估报告或重复的完整对白。

情境变化沿用位置单一权威，同场由接受后的位置推导。日常背景细节可以直接进入正文，不因此创建重要人物实例或地图实体。本原型不宣称支持数值资源结算或固定规则结果。

连续性记录区分亲见结果、人物证词、推测和未兑现约定。人物说法不自动成为客观真相。重要私聊保留必要原话和真实接收者；顺序号和来源标识由程序生成。

近期上下文保留完整对话；连续性记录保存关键事项，不代替整段近期经历。

### 校验与失败

检查完整格式、字段、引用、剧本创作范围和支持的情境变化。Provider 支持的 JSON 模式可辅助格式正确性，但不能替代本地检查，也不能防止输出截断。

程序应用被接受的变化。失败或取消时保持上一轮已接受情境；流式片段属于候选内容。

符合条件的格式或引用错误最多进行一次技术纠正，仍受既有总限制约束。额度耗尽、确定的容量错误和重复服务故障先定位，再决定是否继续付费调用。重复描写或节奏不足作为质量问题评审，不固定增加裁判 Agent 或自动重新生成。

集中创作会看到多个人物的材料。结构化知情检查不能证明正文完全保守秘密，私聊和动机一致性须通过真实互动验证。

## 4. 创作行为与剧本解耦

### 未开启主动推进

充分展开当前互动，让人物彼此回应，完成玩家已经选择的普通步骤。实际后果与经过的情境继续成立，场景围绕当前意图展开。

### 开启主动推进

人物可以延续相关互动、提出自己的事情、透露适当信息，并在剧本创作范围内形成新情境。停在有意义的节点或新的重要玩家选择前。符合当前处境的平静或悬而未决场景同样有效。

两种模式均保留玩家对重要承诺、危险选择和新目的地的决定权。NPC 之间可以有自然的多轮交谈，主角的新决定由玩家给出。开关控制主动增加剧情发展的幅度，不冻结行动及已有后果。

### 剧本材料

当前剧本位于 `backend/internal/content/packs/mist-embers`，沿用现有格式，分别提供：

1. 已成立的事实和重要真相。
2. 人物身份、动机、知识和当前关切。
3. 合理的互动、调查过程、波折与可选发展的创作空间。

`narrative/developments.md` 表达创作空间，人物档案与知识文件保持人物差异。材料描述压力与可能性，不规定必须经过的路线或预定成功。

在许可范围内接受的新事实成为后续连续性依据，每个新细节不必对应预写剧情节点。创作保持既有真相，区分背景补充与实际发现。

通用代码和提示词不包含剧本专属的人名、地点、组织及日期。用离线材料注入测试验证解耦，不增加第二个可玩剧本。

## 5. 上下文装配

通过现有入口，按下列顺序装配：

1. 简短的通用创作职责、返回合同和玩家选择边界。
2. 相关固定事实和必要世界规则。
3. 相关人物的身份、动机和分别标明归属的知识。
4. 完整近期对话和已接受的当前情境。
5. 相关旧经历、未完成约定与线索。
6. 玩家原文和本轮推进选项。

普通创作调用前完成相关材料选择。必要的材料扩展受现有许可与请求限制约束；无关城市背景、所有人物的完整历史和全部机制不作为每轮必需材料。

人物记忆按各自范围组织，在同一个请求中提供；召回不增加逐 NPC 模型调用。当前情境与已发生经历优先于开场描述，主观记录不能覆盖固定真相。

## 6. 工作单元与完成条件

| 单元 | 工作 | 完成条件 | 预估 |
| --- | --- | --- | --- |
| U1 参数控制与创作参照 | 记录 HEAD 和实际限制；显式控制思考；关闭思考对照纯正文与当前合同 | 保存确切参数、完整结果、推理与结果用量、耗时；参数接线测试通过 | 约 1 小时 |
| U2 轻量创作链路 | 固定最小类型；修订候选生成与校验；简化事件记账和重复创作调用 | 场景完整接受；拒绝结果保持情境；普通回合一次核心调用 | 2～3 小时 |
| U3 材料与推进授权 | 装配相关上下文；完善当前剧本材料；接入逐回合开关 | 两种模式有效；事实和人物差异保持；剧本解耦通过检查 | 1～2 小时 |
| U4 连续游玩与收口 | 两段真实会话、缺陷评审、针对性修正、适用检查与证据整理 | 实际文本和测量支持游玩结论，未验证范围明确 | 2～3 小时 |

首版预计 6～9 小时，包括常规验证与收口，不包括服务不可用等待和进一步风格调优。最后 1～1.5 小时保留给评审、验证和交付；工作预算结束时，未完成项保持未完成状态。

U1 首先显式关闭思考，使用相同模型、剧本材料、冻结输入、传输方式和适用 token 上限，对照纯正文与当前结构化返回，两者只改变返回合同。既有高强度思考失败证据保留；需要判断质量或完整性时再增加低强度变体。合并输出、可见结果和推理用量分别记录。

U2、U3 有意改变创作组织与表现，以连续性、玩家控制和真实文本质量验收，不要求与旧链路逐字一致。后续恢复正式迁移时，再执行对应的完整迁移门槛。

## 7. 连续游玩与验收

在剩余真实模型授权预算内，目标为两段各 10～15 轮的会话：

- **主动调查**：连续追问、普通多步骤行动、人物拒绝、当面分歧、私聊和后续回忆。
- **自主推进**：多轮开启推进、玩家拒绝机会、人物主动性、新情境及后续影响。

裁缝店追问使用既有输入作为可复现样本。不同分支保持等价玩家意图，不强行复制已经不适用的行动。

| 项目 | 验收依据 |
| --- | --- |
| 行动承接 | 完整处理已选意图，障碍和未完成部分清楚 |
| 人物互动 | 人物彼此回应，动机不同，不要求全员发言 |
| 自主创作 | 开启后形成合理的新处境，并在后续继续承接，不强制每轮制造意外 |
| 连续记忆 | 已完成动作不重演，重要事实、证词和约定保持一致 |
| 私聊 | 旁观者不在后续复述未听到的秘密 |
| 玩家控制 | 不替玩家接受新任务、承诺、支出或危险选择 |
| 节奏 | 不重复铺景，不机械等待或强塞行动菜单，普通步骤得到有意义的完成 |
| 等待价值 | 记录完整响应、失败数、实际耗时及推理与结果用量 |

技术通过要求完整结果与稳定失败行为。游玩通过要求两段实际文本、上述场景评审，以及没有未解决的严重真相、私聊或玩家控制问题。失败与技术重试纳入全部请求统计。

小样本不推导普遍速度或稳定失败率；预算不足而缩短的样本只支持实际验证的情境。测试替身只证明机制，不能证明叙事质量。

## 8. 验证与交付

确定性测试覆盖思考参数、推进选项传递、相关材料与人物归属、必要情境变化、返回校验和拒绝后的情境保持。提示效果通过生成文本评估，不为措辞编写镜像断言。

叙事链路改动运行 `go test ./... -count=1`、受影响包的 `go test -race`、`go vet ./...` 和相关构建。文档检查运行 `git diff --check` 并验证本地链接。本轮不改 UI，不增加前端专项验收。

按完整单元进行本地提交，代码、测试和材料只包含直接相关内容。最终交付：

- 内部连续互动入口及确切本地使用方式。
- 创作链路、上下文和当前剧本材料。
- 带输入、推进选项、模型参数和结果的真实对话文本。
- 用量、请求数、首个结果片段与完整响应耗时，以及纠正和失败。
- 测试结果、本地提交列表和未完成范围。

证据不包含密钥、本机配置、真实玩家存档或原始模型思考。实施者自查与实际独立审查分别标明。原型质量与正式应用接入分别交付结论。

## 9. 默认选择与决策边界

沿用已有模型、当前剧本、一个创作职责、逐回合推进授权及现有上下文和记忆组件。思考参数根据实测选择。范围内的提示和字段调整自主执行，不逐项确认。

已有真实调用授权、暂停、费用上限、截止时间和重试次数继续有效。计划轮数不提高费用上限；达到限制时停止付费工作，完成仍可执行的本地任务并记录缺失证据。此前失败与已消耗重试额度保留。

更换模型、提高费用上限、正式运行时与存档迁移、UI 扩展、动态创建重要人物或改变固定真相，需要另行决定。本轮没有依赖这些决定的工作。
