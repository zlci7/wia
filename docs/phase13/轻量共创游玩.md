# 轻量共创游玩

## 网页入口

启动本地 WIA，打开《雾都余烬》剧本页面，选择开场身份，点击“以此身份开始试玩”。继续当前会话使用“继续当前试玩”；以另一身份重新开始使用“以此身份开始新试玩”。旧存档从原有存档入口继续。

试玩使用当前 DeepSeek 模型连接。网页默认勾选“深度思考”、关闭主动推进、采用非流式。新会话启用思考，传输方式沿用当前页面选择。每个会话使用应用内存保存接受后的情境和人物记录；同一应用运行期间刷新页面可恢复已接受的故事，应用退出后会话结束。浏览器只保存会话标识，不保存完整故事或人物秘密。

| 操作 | 行为 |
| --- | --- |
| 自然语言输入、Ctrl + Enter | 提交完整行动；公开、私下和交谈对象直接写在输入里 |
| 深度思考 | 勾选以 `reasoning=low` 启用 Provider 思考；取消以 `off` 关闭，与传输和剧情推进分别选择 |
| 允许主动推进剧情 | 本轮允许合理增加剧情发展；默认按玩家当前行动承接 |
| 传输方式 | 非流式完整返回；流式逐步显示候选正文，校验后生效 |
| 取消生成 | 保留上一轮情境和输入；已经接受的结果保持有效 |
| 三个行动建议 | 正文之后异步生成，纵向展示；点击填入草稿，可修改后发送 |
| 关闭建议 | 停止建议任务，自由输入保持可用 |
| 角色、背包、地图、人物 | 共用资料窗口查看身份、状态、技能、实际现金与物品、已知地点和同场人物；查看不消耗世界时间或调用模型 |

生成期间冻结本轮输入和选项。提交结果不明确时用同一请求标识确认；成功接受后释放输入。失败与取消保留草稿，技术纠正会重置候选正文。打开模型设置或回到当前试玩保持输入和阅读位置。

四种开场都位于贝克兰德，世界时间为 1358 年 3 月 29 日 09:00：本地调查员、保留现代生活记忆的异乡转生者、序列 9 观众、黑夜教会序列 9 不眠者。各自使用所选身份的经历、开场、起点、现金、训练与物品。选择只作用于新试玩，正在进行的会话保留原身份。

流式正文直接位于阅读流，与接受后的正文共用消息节点、排版和位置。等待提示与取消按钮位于输入栏的辅助区域。资料窗口读取已接受数据，候选生成期间保持上一轮状态。

建议只读取玩家可见材料、近期正文和玩家重要记录，不读取人物私密记忆或作者真相。已有草稿时建议按钮保持禁用。建议失败不影响已接受正文，不自动代替玩家行动。

## 开发者命令行

在仓库的 `backend` 目录运行 `go run ./cmd/wia-play`。默认加载《雾都余烬》；模型配置顺序为 `-model-config`、`WIA_MODEL_CONFIG`、`%LOCALAPPDATA%/WorldIsAgent/story-app/config/model.json`。

| 命令 | 含义 |
| --- | --- |
| `/advance on`、`/advance off` | 从下一轮选择是否允许主动增加剧情发展 |
| `/stream on`、`/stream off` | 从下一轮选择流式或非流式 |
| `/reasoning off`、`/reasoning low`、`/reasoning high` | 从下一轮选择思考模式 |
| `/quit` | 结束会话 |

命令行默认关闭思考、关闭主动推进、采用非流式。命令行流式片段是候选 JSON；完整校验成功后显示接受的正文。网页只投影候选正文。原始模型思考不写入测试记录。

## 连续测试

```powershell
go run ./cmd/wia-play `
  -inputs ../docs/phase13/records/evidence/co-creative-play-2026-10-07/investigation-inputs.json `
  -record investigation.json `
  -reasoning off -stream -max-calls 16
```

`-record` 要求新文件。输入文件为 1～15 项 JSON 数组，每项包含 `input` 和 `allow_plot_advance`。`-max-calls` 为本会话所有请求的硬上限，范围 1～32，包含材料补充、纠正和失败请求；它不提高已有费用授权。

## 创作合同

### 剧本开场数据

v4 `story.json` 的可选 `starting_options` 最多 8 项，每项有唯一 `id`、`title`、`description`，以及可选的 `player`、`opening`、`initial_location`、`items`。人物、非凡能力与城市规则均来自剧本材料。

省略玩家、开场或起点时继承剧本初值；提供 `player` 时替换完整玩家配置，其状态、已知地点使用既有校验。省略 `items` 时继承原玩家物品；显式空数组代表空背包，提供数组时替换玩家物品，其他持有人的物品保留。导入数据只声明已有物品定义与合法引用。

`POST /api/v1/play-sessions` 接收可选 `starting_option_id`。省略时采用第一项，没有开场列表时采用原始配置；未知 ID 拒绝创建。会话冻结所选初值，同一创建键不能换成另一身份。选择不修改剧本包、其他会话或旧存档。

### 回合结果

`turn.CreationSession.Interact` 接收玩家原文、推进选项、思考模式和传输选项。完整结果包含：

| 字段 | 要求 |
| --- | --- |
| `narrative` | 必填，完整场景正文，最多 6,000 字符 |
| `scene_changes` | 必填，世界耗时与结束位置；可选声明已有状态和物品变化 |
| `continuity_notes` | 可选，最多 12 项重要事项 |

`scene_changes.elapsed_minutes` 为 0～120 分钟，`positions` 列出每个已选人物的结束地点。程序检查人物与地点引用、当前地点到目的地的有向可达性，以及世界日期范围。

`state_changes` 每项含 `entity_id`、`state_id`、`reason`，以及整数 `delta` 或带 `type` 的 `value`，两者只选一个。每轮每个状态最多一项变化，复用既有类型、范围、只读策略和整轮预算。货币只使用声明的最小整数单位增量；报价与约定不构成付款。`item_moves` 每项含 `instance_id`、`reason` 和单一目标 `holder_id` 或 `location_id`。物品使用已有实例，转移前归属由程序读取，取放须满足开始或结束位置的接触条件。两类变化各最多 16 项，没有变化时省略。

初值来自冻结剧本的状态与物品声明。已接受的状态与当前归属用于下一轮上下文和玩家公开投影。时间、位置、钱物、状态、正文与个人记录共同接受；任一校验失败则整轮保持原状。未配置的余额不自动显示为零，异地或隐藏物品不进入玩家资料。

连续性事项包含 `kind`、`content`、`recipients`，以及适用的 `speaker_id`：

- `observed`：实际观察。
- `statement`：有说话者的证词。
- `hypothesis`：尚未证实的推测。
- `commitment`：尚未兑现的约定。

事项保存给实际接收者，说话者也保留自己的记录。人物说法与约定保持各自性质。

## 上下文与记录

创作复用现有 `ContextGenerator`、`ContextComposer`、材料授权、个人 `MemorySource` 和有界整组检索。固定事实、创作空间和人物资料来自 v4 剧本包；通用提示词使用剧本数据中的人物与地点。

相关人物包括当前位置的人物、原文提及的人物、目的地人物，以及上一轮实际说话或获知重要事项的相关人物。上一轮完整输入与正文为必需材料；更早的近期互动按容量装配，旧经历按本人范围检索。当前时间和位置在历史之后、玩家原文之前提供。

本轮相关人物的重要个人事项另有受限保留：总计最多 8 项、每人最多 2 项、估算最多 1,200 token，按约定、观察与证词、假设的优先级选取，类别内取最近记录。保留完整事项，不截断或自动改写；历史约定是否兑现须结合后续经历判断。模型中的个人记录用顺序号、说话者、类别、日期和内容表达，实际来源 ID 保留在上下文报告和记录中。

人物记录在当前会话的 `map[entity_id][]memory.MemorySource` 中维护，含个人顺序号、来源 ID、回合 ID、说话者、类型、内容和世界时间。`PersonalSources` 返回该人物记录的副本。记录与情境在完整结果校验后一起接受。

## 运行边界

普通回合一次核心调用。材料确有需要时沿用一次补充读取；格式或引用错误最多纠正一次，整轮最多三次核心调用，共享 300 秒截止时间与取消信号。截断、Provider 故障和取消直接保留上一轮情境。

共创网页和命令行使用同一个 `CreationSession`。旧存档的持久化回合仍使用 `Service.Execute`。试玩维护已声明状态、货币和物品；固定规则判定、关系数值、库存新实例和完整世界发展调度仍属于正式机制范围。途中停靠和完整交易账簿没有单独建模。用量沿用应用账本。

本地字段校验不能证明正文的每个语义判断正确。人物知情、玩家承诺、固定真相和细节连续性通过真实文本评审。
