# 试玩资料与流式阅读修复规划

日期：2026-10-07。基线：`9b6780a`。阶段：Phase13。

## 目标与边界

共创试玩保留 A 方案阅读界面。角色、背包、地图和在场人物通过共用资料窗口按需打开；角色栏目展示身体状态与技能，背包展示实际现金与持有物品。打开与关闭资料不改变草稿、阅读位置或世界时间。

流式正文和已接受正文处于同一阅读位置，使用相同字号、宽度和段落样式。玩家输入也使用相同的提交消息位置。生成耗时与取消操作使用输入栏的小字号辅助区域；校验成功后原位确认正文，取消或失败保留上一轮情境和草稿。技术纠正仍可替换候选内容。

共创结果增加可选的钱物与状态变化，复用既有状态类型、范围、策略、整轮预算、物品唯一归属与公开投影。已有配置决定现金单位与展示，通用代码不写死剧本、货币或物品。报价、承诺和提及不构成收付或物品转移。未定义的新资源、固定规则结算、关系系统与持久化迁移不在本轮范围。

会话继续保存在应用进程内，旧存档与模型配置保持原有机制。查看资料不调用模型，普通行动仍使用一次集中创作。默认关闭模型思考，候选正文按正文呈现，不将正文标为思考。

## 工作单元

| 单元 | 交付 | 验收 |
| --- | --- | --- |
| F1 真实资料 | 从冻结剧本初始化状态与物品；可选变化复用既有校验；发布玩家公开资料 | 类型、策略、余额、整轮预算、当前归属、同场、隐私与失败原子性通过；非诡秘配置可用 |
| F2 阅读呈现 | 共用资料工具与窗口；流式和接受消息使用稳定节点；弱化生成信息 | 无正文边框、无重复消息、完成前后阅读宽度与字号相同；资料开关、草稿、焦点与滚动正常 |
| F3 验证与交付 | 完整工程回归、桌面和窄屏浏览器证据、本地提交 | 受控现金收付、取放物品、状态更新与取消恢复可验证；明确区别工程、视觉和真实剧情验收 |

## 数据合同

`scene_changes` 保留耗时与结束位置，新增可选 `state_changes` 和 `item_moves`。每项变化有简短的实际发生原因；状态只引用已存在实体与状态，整数可用增量，布尔或枚举用类型值。货币以声明的最小整数单位收付，不允许直接改写余额。物品只引用已存在实例，目标为单一持有人或地点。

程序从本轮快照确定变化前值与归属，为通过校验的变化附加本轮来源；复用既有状态与物品应用逻辑。资源、位置、日期、正文和个人记录共同接受，任何字段失败则整轮保持原状。

网页发布玩家身份、公开状态、可见物品、已知地点与实际同场者，不发布作者真相、异地物品与人物私人资料。查看资料直接读取接受后的投影。

## 检查与交付

叙事调整运行完整 Go 测试、相关 race 和 vet；前端运行类型检查、机制测试和正式构建。用 gstack `/browse` 验证正式构建，记录桌面与 390 像素窄屏、流式前后节点和几何、浮层焦点、草稿、滚动、失败与取消。

本轮交互验证采用明确标识的受控模型，不追加付费模型调用。此前真实模型结果保留原结论，新的资源合同真实生成质量需另行实机评审。交付范围与结果更新到[开发状态](开发状态.md)，每个完整工作单元仅本地提交。
