# 开放世界闭环执行方案

工作窗口：2026-10-01 23:56 至 2026-10-02 09:56，Asia/Shanghai。时间为投入安排；交付状态以实际验证结果为准。

## 1. 目标与范围

交付可真实游玩的《雾都余烬》初始剧本，完成世界推进、个人感知和玩家工作台，验证从新建存档到持续行动、另存、重启续玩的完整路径。

剧本采用第一部结束后、愚者教会已经存在的贝克兰德有限街区。沿用四名重要人物、现有地点与裂纹银镜；背景、组织、人物知识与可能发展按材料分类配置。具体原作年份保持未指定。人物的路线、委托选择与故事结局由实际行动形成。

数据结构与执行合同见[渐进材料与持续世界技术方案](../../../phase12/stages/渐进材料与持续世界-技术方案.md)，文件合同见[开发者剧本编写规范](../../../phase12/stages/开发者剧本编写规范与模板.md)，模块依赖见[架构方案](../../../ARCHITECTURE.md)。

## 3. 初始剧本

以新建世界默认进入《雾都余烬》为目标。旧存档沿用各自冻结内容，新内容不重写旧世界。稳定 game、地点、人物及物品实例 ID 保持。

背景资料采用[诡秘世界作者资料库](../../../phase12/reference/诡秘世界/README.md)的来源与时代标签。运行包保存与当前街区有关的精简公开背景、按需详细背景、作者事实、个人知识与计划。材料的索引、摘要和正文执行相同知情边界。

内容覆盖日常生活、初始人际处境、公开地点、局部调查线索、银镜现象与代价、人物各自的动机和可调整计划。真实判断由模型结合当前事实完成；程序维护位置、来源、唯一归属、时间和原子提交。状态、关系、物品与固定判定沿用现有能力。

## 4. 前端体验

使用 Impeccable，采用已确认的直接代码实现与实测流程。产品范围以[产品说明](../../../phase12/产品说明.md)为准，视觉规则与表面设计在前端实施时确定。

主要阅读与行动界面突出正文、当前场景和输入，人物与状态在需要时可达。首页明确进入初始故事及继续存档；生成中、失败、重试和保存状态可理解。保留现有玩家操作、模型配置与存档语义。

桌面与手机共同完成一次视觉和交互检查，集中修正后做一次确认。类型检查、前端机制测试与正式构建为交付门槛。

## 5. 验证与完成判据

每个叙事模块运行全仓 Go 测试、受影响包 race、vet、build 与 diff 检查。旧 v1/v2/v3 世界读取、冻结内容移除后续玩、版本冲突和原子提交保持有效。

真实模型使用隔离测试存档和现有模型连接，总验证规模控制在 20 个成功回合以内。单个失败场景至多一次技术重试；模型额度不足或服务不可用时停止收费验证，记录确切未验证项，继续独立工作。

核心真实场景：私聊后离开，人物依据本人知识和计划调查已经变化的诊所，玩家与物品继续行动，再另存、重启续玩。验证秘密接收范围、人物独立决定、最新事实、物品唯一归属、关系与计划保存、原档和分支隔离；不要求固定路线或结局。

闭环证据包含新建存档、首次自由行动、混合输入、私密回复、人物自主推进、地图与状态查询、另存、重启、失败输入保留及重试。自动测试、真实模型和浏览器结果分别记录。全部目标具备相应证据后才能判定完成。

## 6. 待决事项与执行边界

当前范围具备开工条件。实施中出现需要用户决定的产品事项，写入本节并说明影响，相关分支后置，其他工作继续。

更大的城市地图、新重要人物、通用骰子能力、原作精确年代和教会地方编制不属于本工作窗口的交付门槛。现有启动和本地游玩路径完成闭环；账户、跨设备服务和生产部署按既有后续阶段处理。

实际进度只更新[开发状态](../../../phase12/开发状态.md)，验证证据写入各板块的验收记录。
