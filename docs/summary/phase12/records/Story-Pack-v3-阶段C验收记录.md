## 实现结果

### 风险判定与规则效果

- v3 新增 `rules: 1` 能力和 `action_rules` 数据区。意图模型只能从当前前提成立的规则列表中选择规则 ID；骰点、目标值、修正、成败和效果均由程序决定。
- 首版只支持百分骰 roll-under：1–100 的骰点小于等于最终目标即成功。剧本声明基础目标、上下限和基于位置、状态、关系、物品或已提交规则结果的修正条件，不支持任意公式或模型自报骰点。
- 每个程序规则绑定稳定 `input_id`。`action_resolutions` 在后续模型调用前保存规则 ID、骰点、目标和已应用修正；同一输入重试强制复用已准备的规则身份和骰点。准备记录不是世界事实，世界事件和状态后果仍只在最终事务成功时提交。
- 规则结果形成独立 `rule_result` 事件并依赖本轮行动结果。协调器必须逐字采用程序决定的状态，正文只消费已确定结果。失败是可提交结果，按剧本声明产生后果。
- 首版程序效果只支持 `rule_only` 整数状态增量，沿用既有 Turn 工作态、来源依赖、变化历史和最终事务；结果在整数溢出前安全计算，并收敛到剧本声明的上下限。模型不能通过 `state_effects` 修改 `rule_only` 状态。

### 条件剧情与场外行动

- `plot` 节点可以声明结构化 `requirements`，读取当前位置、整数状态、有向关系、物品持有或所在地点，以及已提交规则结果。条件不成立时按节点声明 `defer` 或 `skip`，模型不能改写程序结论。
- 参与、拒绝和等待通过已提交规则结果与游戏内时钟区分。条件被提前破坏时节点跳过；未满足结构化条件的节点不得产生人物投影或唤醒请求，避免把作者结论泄露给人物。
- 世界计划、NPC 行动意图和行动结果继续使用三类独立事件。计划只进入作者记录；到期节点只向节点允许且实际获得刺激的人物投影，NPC 再以本人决策产生行动意图。
- 空间世界的场外 NPC 行动支持结构化 `movements`。程序校验行动者、成功结果、有向路线、起点、终点、地点感知和个人场景更新，并在最终事务提交权威位置；场外结果不会自动广播给玩家。

### 《雾都余烬》配置

- 修订升级为 `mist-embers.pack.v3`，声明四条规则：接受委托、拒绝委托、诊所潜入风险和使用裂纹银镜。
- 诊所潜入基础目标为 55；状态尚佳提供正修正，已经积累的调查负荷提供负修正。成功增加少量调查负荷，失败增加更明显负荷并留下暴露后果。
- 新增剧本自定义状态“调查负荷”和“镜像失谐”，均由规则结算。使用由玩家持有的裂纹银镜会增加镜像失谐；该语义没有进入通用代码分支。
- 委托窗口按接受、拒绝或持续等待结算；银镜回收节点读取银镜的实际位置，物品已经被取走时原计划跳过。开放事件继续受地点、参与者、活跃数和冷却限制。

## 验证证据

自动化覆盖：

- 判定准备记录的创建、复用、冻结输入检查和原子结算。
- 同一稳定输入跨运行重试复用骰点；第一次协调失败不写世界后果，重试后的失败结果、规则事件和状态变化各提交一次。
- 模型试图把程序失败改成成功时进入有限修复并最终拒绝，不以正文覆盖结果。
- 结构化条件读取当前 Turn 工作态；参与、拒绝、等待和物品前提被破坏产生对应进度。
- 已结算规则状态持久保存并建立查询索引，规则结果离开近期事件窗口后仍可满足剧情条件；旧数据库会从既有结果事件补齐状态。
- 派生事实来源不会被误当成事件外键；另存和重启可恢复含派生事实证据的剧情进度。
- 加载器拒绝类型或作用域不匹配的规则条件与效果；状态效果到达边界后按上下限结算，不使整个回合永久失败。
- 场外计划先投影给指定人物，再由本人产生行动意图；结构化移动更新权威位置，玩家没有来源时不获得场外结果。
- v3 包、开发者草稿和发布链保留规则数据；未知能力、非法规则、非法引用和规则效果目标拒绝加载。
- 另存使用 SQLite 完整复制，因此判定准备、已结算事件、规则状态、剧情进度和场外位置随分支保存；重启从冻结定义和当前事实恢复。
- 受控浏览器验证覆盖长历史分页、跨世界隔离、失败与未知结果恢复、小屏布局、场景抽屉、另存与删除、延后连接模型开局及活动世界被外部删除。

## 默认内容切换与旧数据方案

工程 CR-C 通过后仍保持三份内置包和当前默认数据根不变。用户明确授权内容切换后，按以下顺序执行：

1. 在独立数据根复核《雾都余烬》真实模型连续游玩、另存和重启，并保存当前 `app.db`、内容目录和内置包摘要清单。
2. 将旧内置剧本仍有价值的机制场景收敛为测试夹具，再从正式内置目录移除旧示例；新安装或没有活动世界的用户默认展示《雾都余烬》。《雾都余烬》不会覆盖既有世界的冻结定义。
3. 用户目录中已经安装的包、世界数据库、导出文件和活动世界保持原样；不删除用户数据，不为 v1/v2 世界补造空间、状态或规则能力。
4. 启动时只迁移内置包登记和摘要版本，事务失败时保留旧登记；先核对路径、摘要、冻结定义和世界可读性，再发布新目录状态。
5. 回滚时恢复 `app.db` 与内置内容目录备份，重新启用旧包登记；世界数据库没有被改写，因此无需逆向迁移世界事实。

## 已知边界

| 对象 | 当前行为 |
| --- | --- |
| 风险规则 | 首版固定百分骰 roll-under；每个玩家输入最多绑定一条程序规则，不支持任意公式、战斗轮或组合检定 |
| 规则效果 | 首版只提供规则拥有的整数状态增量；复杂支付、装备、合成和经济系统不在本阶段 |
| 剧情条件 | 支持位置、整数状态、关系、物品和规则结果；自然语言条件仍用于表现与无法结构化的作者约束 |
| 场外推进 | 仅在到期节点与受刺激人物响应轮内推进，不提供后台持续模拟 |
| 纠正 | 描述性纠正保持原流程；影响位置、状态、物品、判定或剧情进度的事实纠正在重建能力完成前拒绝 |
| 真实模型 | 尚未完成建议的 30 回合连续游玩及叙事质量验收 |
| 默认切换 | 只有方案，没有执行；等待单独授权 |
