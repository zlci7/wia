## 实现结果

### 作者合同

- v3 能力清单支持 `state: 1`、`relations: 1` 和 `items: 1`，并继续要求 `spatial: 1`。未知能力、错误版本、能力与数据不匹配、非法引用和非法初始值拒绝加载。
- 状态 ID、名称、描述、单位和业务含义由剧本提供。运行代码不识别“疲劳”“污染”等固定名称。
- 状态类型支持整数、布尔和枚举。布尔与枚举首版只读；整数只有声明 `bounded_proposal` 和单回合累计上限后才能接受模型提案。
- 开发者内容草稿、发布和包往返保留状态、关系和物品字段；普通玩家侧没有新增剧本编辑器。

### Turn 与权限

- 协调结果使用 `state_effects`、`relationship_effects` 和 `item_transfers` 提交候选变化。每项必须引用本轮成功或部分成功的行动结果。
- 状态目标只能是来源行动者或明确目标；程序根据当前工作值计算新值，执行类型、范围、整轮预算和重复来源校验，不静默截断。
- 关系由主体持有。人物只能依据自己获准感知的已提交结果提出变化，并绑定该个人经历来源；协调器只能采用主体本人的原提案，变化不会自动对称复制。接受变化时创建独立的关系结果事件，分别依赖提案经历与上一关系来源，避免把旧经历重新解释成当前事实。
- 物品同一时刻只有一个持有人或一个地点。当前持有人只能通过本人的成功行动向同地且明确参与结果的接收者转移；现场物品只能由位于该地点的取得者本人行动后获得。
- 三类候选在隔离副本中整组校验。一项非法时全部丢弃；同一回合的主协调与剧情响应共享连续工作态、累计预算、关系提案结算记录和物品转移记录。叙述失败、取消和最终版本冲突不写入候选事实。
- 人物决策只接收本人获准状态、以本人为主体的关系和本人持有或现场可见的物品。玩家接口只返回自己的可见状态、当前同场且有来源的公开 NPC 状态以及持有或现场可见的物品；离场后不继续显示他人的精确实时值。

### 持久化与界面

- 当前状态、关系和物品分别保存权威值、来源、更新回合和版本；变化历史保存前后值、来源事件、回合和顺序，结构化结果以多父依赖边保留此前事实来源。
- 状态、关系、物品、事件、感知、消息、位置与运行完成标记由同一个最终事务提交。
- 另存复制完整世界数据库；重启从冻结定义和当前事实恢复，不重新套用作者初始值。
- 会使当前位置、状态、关系或物品事实失去依据的事件纠正在重建能力完成前拒绝。
- 玩家工作台在桌面侧栏和手机“场景与人物”抽屉中根据服务器投影动态显示权威地点、相邻地点、状态和物品，并区分玩家持有、NPC 持有和现场物品。没有提供秘密关系面板、复杂背包或装备界面。

《雾都余烬》修订为 `mist-embers.pack.v2`，定义玩家疲劳、信任与好感关系类型，以及位于废弃诊所的裂纹银镜实例。疲劳、关系名称和初始值属于该剧本数据，不是 WIA 内置状态。银镜在阶段 B 只是普通物品实例。

### 实际界面与真实模型

前端类型检查、机制测试和正式构建已通过。受控浏览器 fixture 在 390×844 视口验证“调查事务所”、相邻地点、“疲劳 18”和“裂纹银镜由裁缝店老板持有”均可见，页面与抽屉没有横向溢出，控制台无错误或警告。阶段 B 尚未执行真实模型连续游玩，也未将测试替身结论记为叙事质量通过；仍需按上方路径体验信息隔离、关系变化幅度、物品转移表达及重启后的连续性。
